## R-DOC-01：意见主体一律用集体称谓，不出现领导个人姓名

**症状**：文件里写"董事长意见""董事长已明确此类命名缺新意""郭涛（董事长/总经理）、刘维（副总经理）"。

**为什么必须改**：正式行文出现个人姓名，一是把集体决策归于个人，二是对外流转时形成不必要的指向性。国企公文对集体意见的标准表述是按层级称谓。

**规则**：

| 层级 | 统一表述 | 禁止 |
|------|---------|------|
| 集团层面意见 | **集团领导** | 董事长意见、某某董事长认为 |
| 茶业公司层面意见 | **茶业公司领导** | 郭涛、刘维（个人姓名） |
| 旅投集团层面 | **旅投集团** | 旅投某领导 |
| 外部合作方 | 单位 + 职务 | 对方个人姓名 |
| 上级单位 | 上级单位名称 | 具体个人 |

**关键区分**：**职务 ≠ 姓名**。
- 属职务表述，保留：如"郭涛（董事长/总经理）"→ 改为"茶业公司领导"；"四川旅投产业发展部部长 陈天科"→ 改为"旅投集团产业发展部"（职务 + 单位，不带名）。
- 属事实引用（ASR 校名对照、来源引注），可保留职务但**不列具体姓名**，写"原文音近称谓 + 正确职务/单位"。
- 例外：文件名与人名一一对应的请示件（如"关于任命×××的请示"）可保留本人姓名。

**兜底替换表**：
```
董事长意见        → 集团领导意见
董事长已明确…    → 集团领导已明确…
主送负责人：X（…）、Y（…）  → 茶业公司领导
抄送：集团领导层（A/B）…    → 抄送：集团领导层…
选品分工：X（某公司副总经理）→ 选品分工：茶业公司领导
主持人：某部 X 某            → 主持人：某单位某部
```

## R-DOC-02：批量替换必须先圈定"禁改清单"

**症状**：为统一"董事长意见"，对多个目录做递归批量替换，**误改了原始录音转写件**（都江堰国宴 9-24 会议记录中 1 处"董事长认为"被改成"集团领导认为"）。

**为什么会误伤**：原始记录里也有"董事长"字样，且是**当事人原话**，不是我的行文。改了就污染一手资料。

**规则**：
1. 批量替换前，先列出**禁改清单**：文件名含"来自【得到大脑】""会议记录""_parsed""录音"的原始件，一律不动。
2. 替换范围只覆盖**我产出的文件**（方案/名册/纪要/笔记/memory）。
3. 替换后**必须做一次反向核查**：在禁改清单内 grep 被替换的词，确认残留为 0；若 >0，**立即按规则还原**。
4. 原始件与我的派生件并存时，改派生件不碰原始件；派生件若需引用原始表述，写"原文音近称谓"。

## R-DOC-03：同一份记录内部数据矛盾时，以"原文陈述"为准，不取"智能总结"

**症状**：10-22 会议记录中，糖酒公司直供网点：智能总结写"600 个"，章节概要与原文均写"6000 个"。

**为什么**：语音转写类文件的"智能总结"是模型二次生成的摘要，**会出现数字丢位**（6000→600）；章节概要也可能失真；而"原文"是转写文本，量级错误概率最低。

**规则**：引用任何数字前，**三层比对**——智能总结 / 章节概要 / 原文。冲突时：
- 以原文为准；
- 在文件内标注"（口径待核）"或"（智能总结与原文不一致，以原文为准）"；
- 仍无法确定者列入"待明确事项"，不写进正文。

## R-DOC-04：调研范围不得自设窄边界，尤其禁止"某子目录为空 = 全库无记录"

**症状**：2026-10-17 判定"安逸臻选全新立项"时，只搜了 `anyi-ops-kb` 一个子目录就下"完全空白"结论，还基于此画了战略白皮书、提了 7 个"必须先答"的问题。实际项目文件在桌面 `产业发展部\` 下有 20+ 份核心文档，且**已签框架协议、已过党委会、已过总经理办公会**。

**根因**：把"知识库"等同于"知识库的一个子目录"。项目文件常在：桌面工作目录、KB 多个编号目录、Obsidian vault、Git 历史。

**规则**：
1. 判定"某主题是否已有记录"前，**搜索范围必须横跨**：① 全部 KB 编号目录 ② workspace 根目录 ③ 桌面相关工作目录 ④ Obsidian/归档区 ⑤ Git 历史（log --all -S 关键词）。
2. 搜索命中 0 时，**先扩大范围再下结论**，且结论措辞用"在已检索范围内未见"，**不得**用"完全空白/全新立项"。
3. 已经动手写战略方案前，先查是否已有同主题方案/纪要/协议——**已有则先读再写**。
4. 反面自检：若"结论"能被一句"你再搜搜桌面"推翻，就是没搜完。
