## 第5页: 技术实现方案（核心疑虑1）

**问题: 技术怎么实现？是直接安装还是怎么样？**

**答案: 三种接入方式，视酒店现有系统情况定**

### 方案A: API直连（最佳）

```
适用条件: 酒店PMS系统支持API接口

对接方式:
1. 我们提供API文档
2. 酒店IT/ PMS厂商配合对接
3. 数据实时同步
4. 周期: 2-4周

支持的PMS系统:
├─ Opera (西门/凯宾斯基等)
├─ 番茄来了
├─ 蓝凤凰
├─ 千里马
└─ 其他主流PMS（可评估）
```

### 方案B: 中间件对接（备选）

```
适用条件: PMS不支持API，但支持数据导出

对接方式:
1. 酒店定期导出Excel数据（日报/周报）
2. 我们开发中间件解析数据
3. 半自动化同步
4. 周期: 1-2周

缺点:
→ 数据时效性略低
→ 部分功能受限
```

### 方案C: 最小化方案（保底）

```
适用条件: PMS老旧，完全不支持对接

对接方式:
1. 仅对接OTA数据（携程/美团EBK后台）
2. 通过人工+系统混合模式
3. 快速启动
4. 周期: 3-5天

备注:
→ 这是保底方案，确保任何酒店都能用
→ 后续可随PMS升级切换到方案A/B
```

**谁来做实施**:
```
□ 我们的技术团队负责对接开发
□ 酒店只需安排1位对接人（通常是你的IT或前厅经理）
□ PMS厂商配合（如果需要）
□ 全程不需要酒店IT深度介入
```

### 权限设定体系

```
三级权限体系:

【管理员权限】(酒店业主/总经理)
├─ 查看全部数据
├─ 系统配置
├─ 权限分配
└─ 数据导出

【运营权限】(前厅/收益经理)
├─ 查看经营数据
├─ 使用AI运营功能
├─ 查看报表
└─ 无法删除核心数据

【员工权限】(普通员工)
├─ 使用日常功能
├─ 查看自己操作的数据
└─ 无数据导出权限

权限控制原则:
□ 最小权限原则 → 只给必要的权限
□ 职责分离原则 → 审批和执行分开
□ 操作可追溯 → 所有操作有日志
□ 离职即停权 → 员工离职自动回收权限
```

## 第11页: 常见问题Q&A

```
Q1: 如果试点效果不好怎么办？
A: 试点本身就是验证，效果不好也是价值。
   我们会分析原因，酒店可以选择退出或调整方向。
   试点期不收任何费用，没有损失。

Q2: 我们的数据会被用来训练AI吗？
A: 不会。试点期数据仅用于服务本酒店，
   不用于任何AI模型训练或算法优化。

Q3: 试点结束后如果不继续，数据怎么办？
A: 酒店可以选择：1) 全部删除 2) 导出备份
   无论哪种，数据控制权100%在酒店。

Q4: 员工会不会用不来？
A: 我们的设计理念是"零门槛"。
   1小时培训即可上手，全程微信式操作。
   7x24小时技术支持，随时解决使用问题。

Q5: 需要买什么设备/软件吗？
A: 不需要。试点期全部使用我们的系统。
   酒店只需提供网络和员工电脑/手机。

Q6: 和我们现有的PMS/系统冲突怎么办？
A: 我们的系统是增量补充，不是替换。
   对接后，原有系统照常运行，数据互补。

Q7: 竞争对手也在用怎么办？
A: 这是好事。说明我们验证了行业趋势。
   试点结束后，酒店有优先合作权和优惠价格。

Q8: 试点期间可以随时退出吗？
A: 可以。提前7天通知即可，无违约金。
   退出后数据全部删除或转移给酒店。
```
