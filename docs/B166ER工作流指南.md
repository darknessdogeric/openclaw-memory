## 一、核心工作流（必用）

### 流程1: 创意工作流
```
用户需求 → brainstorming → 方案设计 → writing-plans → 执行
```
**使用场景**: 新功能、新项目、重大决策

**调用技能**:
1. `brainstorming` - 理解需求，探索方案
2. `writing-plans` - 制定实施计划

---

### 流程2: 执行工作流
```
实施计划 → subagent-driven-development → 代码审查
```
**使用场景**: 有实施计划，需要执行

**调用技能**:
1. `subagent-driven-development` - 当前会话执行
2. `executing-plans` - 独立会话执行
3. `requesting-code-review` - 代码审查

---

### 流程3: 内容工作流
```
内容需求 → copywriting → 内容生成
```
**使用场景**: 写文案、landing page、销售页

**调用技能**:
1. `copywriting` - 撰写说服性文案

---

### 流程4: 社交媒体工作流
```
社交内容 → social-content → 内容发布
```
**使用场景**: LinkedIn、Twitter、Instagram内容

**调用技能**:
1. `social-content` - 社交内容策略和创作

## 三、TOKEN节省原则

### 1. 技能使用原则
- ✅ 先判断是否需要技能，1%可能就调用
- ✅ 短任务直接执行，不调用技能
- ✅ 复用已有方案，不重复brainstorming
- ❌ 不读取技能完整文档（只按需调用）

### 2. 对话原则
- ✅ 确认问题一次问完
- ✅ 简单问题直接回答
- ✅ 用要点列表，不用长解释
- ❌ 不用"当然""我来帮您"等开场白
- ❌ 不用"如果有任何问题"等结尾

### 3. 记忆原则
- ✅ 先查记忆库，再问用户
- ✅ 重要信息写入MEMORY.md
- ✅ 用文件路径引用代替复制内容

### 4. 工具原则
- ✅ exec > 浏览器 > web_fetch > web_search
- ✅ 优先用轻量工具
- ❌ 避免不必要的截图

## 四、工作流程决策树

```
收到用户消息
    │
    ▼
是否有具体技能需求？ ──是──> 调用对应技能
    │
    否
    │
    ▼
是否创意/设计类任务？ ──是──> brainstorming → writing-plans
    │
    否
    │
    ▼
是否有实施计划？ ──是──> subagent-driven-development
    │
    否
    │
    ▼
是否需要写文案？ ──是──> copywriting
    │
    否
    │
    ▼
是否需要社交内容？ ──是──> social-content
    │
    否
    │
    ▼
直接执行或询问
```

## 五、禁止事项（节省TOKEN）

1. ❌ 不重复读取已读过的文件
2. ❌ 不用`ls -la`查看目录（用`dir`或直接读）
3. ❌ 不做heartbeat以外的多余检查
4. ❌ 不主动搜索互联网（除非用户要求）
5. ❌ 不安装不需要的技能
6. ❌ 不用复杂markdown表格（用简单列表）
