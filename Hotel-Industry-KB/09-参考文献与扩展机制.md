## 二、扩展机制 (Update Mechanism)

### 2.1 触发更新点

```
定期触发 (按时间):
- 季度: 主要酒管集团财报 + 行业新闻
- 半年: 全 KB 内容巡检 + 政策环境评估
- 年度: KB 整体 review + 结构升级

事件触发:
- 新酒店集团 IPO
- 重大并购 / 资产重组
- 重大政策 (中央或地方)
- 行业重大事件 (如疫情危机)
- AnYi 工作进展里程碑
- AI 行业重大进展 (新模型 / 新技术)
```

### 2.2 责任分工

```
维护责任:
- B166ER (日常): 资料归档 / 监测 / 增量更新
- B166ER + Eric 共同 (重大): 战略判断 / 内容审查
- Eric (决定): 内容方向调整

版本管理:
- 主版本 (Major): 1.0 → 2.0 (结构性升级)
- 次版本 (Minor): 1.1 → 1.2 (新增章节 / 重大修订)
- 补丁 (Patch): 增量更新

每次更新:
1. 简要说明变更内容
2. 影响范围
3. 来源 / 链接
4. 验证状态
```

## 四、KB 的局限与边界

### 4.1 局限

```
1. 时效性局限
   ── 行业变化快, 信息可能很快过时
   ── 半年内必须 review

2. 数据深度局限
   ── 公开数据有限, 内部决策难
   ── 需结合公开 + 工作经验 + 行业洞察

3. 角色局限
   ── 本 KB 是 Eric 个人认知基础设施
   ── 不是行业权威定论
   ── 仅供内部参考

4. 范围局限
   ── 仅覆盖酒店集团 + 酒管公司
   ── 不含: OTA / 旅游业上下游 / 餐饮 / 文旅
   ── (这些可作为未来扩展方向)
```

### 4.2 边界

```
不使用:
- 任何未公开的内部数据
- 任何个人隐私信息
- 任何 AHL 个人项目内部代号
- 任何 Eric 入职后才知道的 AnYi 内部数据

不输出:
- 任何对外发布的文章
- 任何带个人品牌的内容
- 任何混入 AnYi 的 AHL 内容
- 任何版权不清晰的素材
```
