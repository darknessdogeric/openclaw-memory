## 三、写作标准（KB 基础认知迭代标准）

### 3.1 必含维度

| 维度 | 标准 |
|------|------|
| **地理覆盖** | 全球 + 中国双轨（不局限于中国市场） |
| **业态覆盖** | 奢华/高端/中端/经济/Lifestyle/长住/度假/会议/医养... 全业态 |
| **模式覆盖** | 全权委托/特许经营/租赁/自有/联营/平台分成 全模式 |
| **玩家覆盖** | 华住/锦江/首旅/亚朵/万豪/希尔顿/雅高/凯德... 全球头部 + 区域代表 |
| **价值链覆盖** | 投/融/管/退（开发 → 定位 → 筹建 → 运营 → 营销 → 收益 → 分销 → 退出） |
| **周期覆盖** | 全生命周期（含历史 / 当前 / 未来 5-10 年趋势） |

### 3.2 必含结构（每篇）

- **定义 + 业务边界**（与邻近概念区分）
- **5 维认知**（历史沿革/当下/原因分析/未来预判/底层逻辑）
- **全球 + 中国双轨数据**（带数据时点）
- **头部玩家对照**（国际 + 国内双轨）
- **关键指标/能力清单**（带行业基准）
- **R66 核对状态**（来源 / 时点 / 一致性）

### 3.3 Agent 训练语料标注（v2.0 新增）

每篇文件末尾应标注：
```
## RAG 召回标注
- 召回关键词：[关键词1] [关键词2] ...
- 适用问题类型：[事实型] [分析型] [决策型]
- 数据时点：[YYYY-MM]
- 置信度：[高/中/低]
```

### 3.4 禁用模式

- ❌ 不写"对XX集团的价值"段落
- ❌ 不假设任何集团作为内置读者
- ❌ 不纠结"集团视角 vs 行业视角"——按 KB 标准即可
- ❌ 不出现任何内部集团名称（如无必要）

## 四、增补 vs 重写

### 4.1 三种更新方式

| 方式 | 触发场景 | 操作 |
|------|---------|------|
| **增补** | 加新板块 / 新文件 / 新维度 | 新建文件，路径符合 KB 结构 |
| **迭代** | 在现有内容上做版本号升级 | 文件名加 v1.x 或 v2.0 |
| **不重写** | 已交付内容仍有效 | 仅在顶部加 note，不改正文 |

### 4.2 版本号规范

```
v1.0  → 首次交付
v1.x  → 小幅更新（修正/补充）
v2.0  → 重大升级（结构/视角/范围变更）
v3.0+ → 跨代升级（KB 体系本身升级）
```
