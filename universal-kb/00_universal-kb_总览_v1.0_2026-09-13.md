## 一、为什么需要 universal-kb

### 1.1 Eric 的核心洞见(2026-09-13 12:24)

> "我希望你的状态是在另一个会话的时候聊安逸的时候,有安逸的专属垂系内容,而你应该是全能啊,比如你的酒店知识库就是独立于安逸集团的,因为酒店行业知识库是大于安逸集团的。除了酒店我们还要干很多别的事儿 啊。"

**核心原则**:
```
✅ 正确架构:
├── anyi-ops-kb/   ← 安逸集团专属(央国企/集团项目/干部身份)
└── universal-kb/  ← 通用知识(独立于任何集团)

❌ 错误架构(本次修正前):
└── anyi-ops-kb/
    ├── 00_全域商业市场认知/  ← 把通用知识塞进集团 KB
    │   ├── 01_酒店行业/      ← 通用行业知识被错误归类
    │   ├── 02_文旅景区综合/  ← 通用行业知识被错误归类
    │   └── 03_中国历史/      ← 通用知识被错误归类
```

### 1.2 通用 vs 集团的关键区别

| 维度 | 通用 KB | 集团 KB |
|------|---------|---------|
| 服务对象 | 任何人/项目/场景 | 仅限集团内部 |
| 复用性 | 跨集团可复用 | 集团专属 |
| 更新频率 | 慢(通用知识相对稳定) | 快(集团动态) |
| 红绿灯 | 默认全绿灯 | 按干部身份相关红绿灯 |
| 文件量级 | 大(覆盖广) | 中(聚焦集团) |
| 保密性 | 公开/半公开 | 内部 |

## 四、universal-kb 与 anyi-ops-kb 的边界规则

### 4.1 判别规则(三问法)

```
对每个新 KB 文件,问 3 个问题:

1. 这个 KB 是否服务于"非安逸"项目?
   ✅ 是 → universal-kb/
   ❌ 否 → 继续下一个问题

2. 这个 KB 是否包含集团内部数据/干部身份相关内容?
   ✅ 是 → anyi-ops-kb/
   ❌ 否 → 继续下一个问题

3. 这个 KB 是否独立可复用(任何集团/项目都用得上)?
   ✅ 是 → universal-kb/
   ❌ 否 → anyi-ops-kb/
```
