## 今日工具链教训（写文件/渲染，高频踩坑）

1. **JS 数组元素里 `"` 直接写，不要写 `\"`** —— JS 会把 `\"` unescape 成裸 `"`，破坏 Python 源码（`HERO = """` → `HERO = ""`，导致后面整段 HTML 被当代码解析，报"invalid character U+3001"）。
2. **最可靠的写文件方式：JS 模板字符串（反引号）+ `write` 工具** —— 无任何转义地狱，产出 UTF-8 无 BOM。
3. **PowerShell here-string 写 Python 会丢字符**（实测丢引号）；且 `>` 重定向产出 **UTF-16**，读日志要 `[System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes($log))`。
4. **exec code mode 的 `tools.exec` / `tools.sessions_spawn` 不存在** —— `exec` 是顶层工具；`sessions_spawn` 必须原生调用。
5. PowerShell 里 `$(...)`/反引号/`$变量` 会与 JS 模板串互相干扰 → 长中文文档优先 `write` 工具。
6. **检查器自误报**：小字号大字形（line-height < 1.3，如 31px/58px 数字）会误判"纵向溢出"→ 判定改为 line-height 感知（`lh > fs*1.3` 才报）。
7. 深色主题的"像素覆盖率"指标失效（把深底当墨）→ 改用"最大亮度 + 最空带峰值亮度"。
