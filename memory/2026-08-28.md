## 📌 会话日志 (13:17-13:20)

**Milvus 评估 + POC 落地**（Eric 授权"你决定你行动"）
- 评估结论：Milvus = 开源向量库"规模天花板"，但对 AHL/安逸/个人工具链是"重炮"，1000万向量以下用 Standalone/Lite 即可
- 行动：验证 pymilvus 3.0.1 + milvus-lite 3.2.1 **兼容 Python 3.14**（纯 py wheel，底层 faiss-cpu）
- POC：`toolbox/ahl_milvus_poc.py` — 用 model2vec(potion-256维) + Milvus Lite 跑通 AHL「最优匹配」语义检索 + 元数据过滤闭环（12 家样例酒店，3 个场景，总耗时 <1s）
- 关键发现：**基础设施层 OK，但 potion-base-8M 微型模型语义精度弱**（"温泉"没召回古尔沟温泉）→ 生产需换强 embedding（bge-m3/text-embedding-3）或补 BM25 混合检索
- 产物：`toolbox/ahl_milvus_poc.py` / `toolbox/ahl_milvus_poc_result.txt` / `ahl_hotels.db`

**下一步（13:35 Eric 再次授权）- Embedding A/B 对比（部分受阻）**
- 目标：验证"embedding 是瓶颈"，用生产级中文 embedding 对比 potion
- **关键发现**：potion-base-8M 是**纯英文模型**，喂中文→语义弱。"温泉召回失败"根因是语言不匹配，不是模型小
- API 现状排查：Jina=占位符 / OpenAI=429 / Minimax=参数待确认 / Dashscope=无key
- 本地中文模型 bge-small-zh(54MB) 下载被中国网络卡（HF镜像 ~75KiB/s，43% 后中断）
- 结论：A/B 受阻于网络，非能力。待网络允许→bge-small-zh 到位即可完成 A/B
- 已装好 fastembed 0.8.0 + onnxruntime 1.24.4（兼容 Py3.14）
