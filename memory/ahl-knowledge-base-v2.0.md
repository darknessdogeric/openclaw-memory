## 一、项目本质

### 1.1 一句话定义

**AHL = 住宿业从"货架经济"到"客户经济"的范式革命者**

不是 OTA 替代品，而是用 AI 向量匹配重构住宿业交易底层逻辑的新协议。
在 V2.0 阶段：**AHL = Eric 个人设计 + 安逸集团内孵化的产业协议层**。

### 1.2 范式革命的核心逻辑

**旧范式（货架经济）**：
```
商家生产 → 放到OTA货架 → 消费者浏览100页 → 随便选一个
问题：被动等待 / 信息过载 / 佣金20-30%
```

**新范式（客户经济）**：
```
消费者: "我想住大理古城带院子的民宿，喜欢有故事的老房子，预算500"
AI管家: 理解需求 → 精准匹配 → 推荐最合适的3家 + 解释原因
同时：商家AI运营官主动分析服务能力 → 精准推送给目标客户

结果：最合适的客人 ↔ 最合适的商家，双向价值最大化
```

### 1.3 V2.0 新增：与 1244 战略的同构

```
1244 战略 = 安逸集团的"1244"产业架构
AHL = 1244 战略中"协议层"的具象化产品

┌──────────────────────────────────────┐
│ 1244 战略：1 个核心 + 2 大引擎 + 4 大平台 + 4 大支撑 │
│   ↑                                           │
│   └── AHL = 协议层 = 4 大平台之一的"产业互联网平台" │
└──────────────────────────────────────┘
```

AHL 不再是独立项目，而是 **1244 战略的产业互联网承载**。

### 4.1 核心架构：四层金字塔

```
Layer 4: 应用层（消费者+商家）
  消费者: 自然语言交互
  商家: AGENT 运营决策

Layer 3: 双 AGENT 智能层
  C 端 AI 管家 ↔ 向量匹配引擎 ↔ B 端 AI 运营官

Layer 2: AGENT 集群层（9 大 AGENT × 87 个 SKILL）
  核心 AGENT + 营销 + 收益 + 工程 + 安防 + 宴会 + 财务 + 人力 + 供应链

Layer 1: 数据协议层
  标准向量数据 + 非标向量数据（深水数据）
  + L1 分层记忆（L0 原始 + L1 结构化 + L2 场景）
```

### 4.2 双 AGENT 架构

**C 端 AI 管家**：
- 自然语言理解需求
- 提取需求实体 → 生成需求向量
- 向量检索 Top-K 匹配商家
- 多轮对话澄清需求
- 直连预订，无中间商

**B 端 AI 运营官**：
- 产品/服务向量化封装
- 动态定价与库存管理
- 客户洞察与精准营销
- AGENT 集群协同运营

### 4.4 L1 分层记忆体系（V2.0 新增，2026-05-15 部署）

**来源**: github.com/Tencent/TencentDB-Agent-Memory（1,561 ⭐，2026-04 创建）

**文件**: `workspace/AHL-memory/ahl_l1_extractor.py`

**核心价值**: AHL 最缺的不是数据，而是"从数据到分层记忆"的架构。

**AHL 借鉴的三个核心设计**：

| 设计 | TencentDB 实现 | AHL 对应物 | 落地优先级 |
|------|-------------|-----------|----------|
| L0 原始记录 | JSONL 按日存储对话 | AHL 客栈询价原始记录 | ⭐⭐⭐⭐ |
| L1 结构化原子 | persona / episodic / instruction | 客栈属性 / 成交事件 / 运营规则 | ⭐⭐⭐⭐⭐ |
| L2 场景整合 | Workspace 沙箱 + LLM 文件工具 | 旺季涨价 / 议价拉锯 / OTA 异常 | ⭐⭐⭐ |

**实测**: 客栈"云隐居"对话 8 轮 → 提取 6 条 L1 记忆
- property × 4（位置 / 定价 / 房型 / 客群，P=80-95）
- transaction × 1（成都客人询价→议价→成交，P=95）
- rule × 1（禁止宠物，硬约束 P=-1）

**存储**: `ahl_memories/{property_id}/l1/{date}.jsonl`
**下一步**: PropertyAgent 启动时注入记忆

**License 风险**: ⚠️ repo 标 MIT 但实际 License 是"Other"——集成前需确认。

## 五、竞争优势

### 5.1 vs OTA（携程/美团）

| 维度 | AHL | OTA |
|------|-----|-----|
| 收费模式 | 技术费 2-3% | 佣金 15-25% |
| 数据归属 | 商户自有 | 平台垄断 |
| 用户交互 | 对话式 AI | 搜索比价 |
| 商户关系 | 赋能型 | 抽成型 |

### 5.2 核心壁垒

1. **深水数据**：噪音分贝、光照指数、主理人语义画像（OTA 采不到）
2. **垂类模型**：AHL-LLM 懂住宿业非标需求
3. **协议层**：向上连接大模型，向下连接 PMS
4. **网络效应**：越多商户接入，AI 推荐越准，用户越多
5. **V2.0 新增：L1 分层记忆**：商户侧"对话-记忆-运营"闭环（OTA 没有）
