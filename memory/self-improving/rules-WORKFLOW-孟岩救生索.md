# 主会话工作流规则（救生索）
**创建时间**: 2026-07-13 15:41
**触发原因**: 主会话 WS 缓冲累积导致 7+ 次工具全死

---

## 🔴 铁律：主会话只干 3 件事

**主会话的职责边界**（永久规则，不得突破）：

1. ✅ **接收指令** — Eric 说什么，听清楚
2. ✅ **分析 + 判断** — 用脑子（不是工具）判断做什么、怎么做
3. ✅ **派工** — spawn subagent 去执行，不自己动手

**主会话绝对不干的事**：
- ❌ exec 运行任何 Python / cmd（超过 3 行必定死）
- ❌ Get-ChildItem / Get-Content 中文路径文件
- ❌ read 工具对中文路径文件（WS 缓冲杀手）
- ❌ cron list / session_status / subagents 查询（WS 杀手）
- ❌ 任何超过 30 秒的连续工具调用

---

## 🟢 正确做法：subagent-first

**所有重活一律派 subagent**：
```
Eric: "做 X"
B166ER: 
  1. 分析 X（主会话，0 工具）
  2. 写 prompt 给 subagent（主会话，写字）
  3. sessions_spawn（主会话，1 次调用）
  4. 等推送汇报（不轮询）
```

**subagent 跑完之后**：
- ✅ 收到 webchat 推送
- ✅ 用极简 echo 试探主会话状态
- ✅ 如果主会话死了 → **不再尝试任何工具调用**
- ✅ 直接告知 Eric 等推送结果

## 🟡 WS 缓冲累积规律（已验证）

**触发 WS 死亡的操作**（按危险程度排序）：
| 危险级 | 操作 | 后果 |
|--------|------|------|
| 🔴 极高 | exec + 中文路径 + cmd | 立即死 |
| 🔴 极高 | exec + 任何 Python | 死（30min 内）|
| 🔴 极高 | subagents 查询 | 死 |
| 🔴 极高 | session_status | 死 |
| 🟡 高 | cron list/get | 间歇死 |
| 🟡 中 | exec echo / hostname | 偶尔死 |
| 🟢 低 | 纯文字输出 | 几乎不死 |

**主会话"死"的判断标准**：
- exec echo 没返回 → 死
- 连续 3 次 echo 只有部分返回 → 死

**恢复特征**：工具全死约 30-60min 后，有 1-2 次"短暂复活"（可以跑 1-2 个工具），但随即又死。
