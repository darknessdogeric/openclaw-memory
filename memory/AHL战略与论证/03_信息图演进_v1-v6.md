## 二、每版详细演进

### v1（原版）· 4 KPI
- **核心叙事**：4 个数字（95% / 7×24 / 50% / 87%）
- **问题**：抽象数字看不到结构，缺范式 / 缺架构
- **Eric 反馈**："这个我需要更简单易懂一些。一图讲透在商业体应用上的架构模式"

### v2 · 范式 + 架构 + 泛用
- **核心叙事**：3 段式（范式对比 / 架构模式 / 泛用性）
- **新增**：左货架 vs 右匹配 + 三层架构（触达层 / 匹配引擎 / 供给层）+ 5 行业泛用
- **问题**：中央"匹配引擎"Hub = 中心化嫌疑
- **Eric 反馈**："你这个有中心化嫌疑啊。我要的是客人到商家的直接点对点"

### v3 · 双矩阵 P2P
- **核心叙事**：双 AGENT 矩阵（C 矩阵 / AHL 协议层 / B 矩阵），6×6 P2P mesh，中间打"X NO HUB"
- **新增**：范式三阶（货架 → 匹配 → 直接），双矩阵 + P2P 直接握手
- **问题**：只有协议握手，缺价值流 / 缺经济循环
- **Eric 反馈**："逻辑对了。但是用什么支撑整个经济循环，应该是 TOKEN 费用"

### v4 · + TOKEN 经济循环
- **核心叙事**：范式四阶（货架 → 匹配 → 直接 → TOKEN）+ 4 步 TOKEN 循环 + 工业电费 vs AI TOKEN 对照
- **新增**：TOKEN 流转图、电费对照表、握手计费数字标注
- **问题**：信息密度过高，复杂
- **Eric 反馈**："再简化一下，就是酒店，酒店集团，文旅产业这三个层级"

### v5 · 三层级 + 图示
- **核心叙事**：三个大圆形 icon（酒店 / 集团 / 文旅）+ TOKEN 光带贯穿
- **新增**：TOKEN 贯穿光带（金色光柱贯穿三层）
- **问题**：三层被当成"三种应用"展示，但 Eric 想要的是"同一种范式嵌套"
- **Eric 反馈**："你没理解我的意思，而是我的双 AGENT 矩阵范式可以从单店，到集团，到文旅这三层。每层都是完备的。"

### v6 · 同构分形架构（终版）
- **核心叙事**：三层并列，每层画完整双矩阵 + 同构 + 自完备 + 可嵌套
- **新增**：每层显式呈现"C 矩阵 / AHL 协议层 / B 矩阵"完整结构，三个关键洞察（🪞 同构 / 🧩 自完备 / ♾️ 可嵌套）
- **核心标签**：**分形架构 / Fractal Architecture**
- **状态**：✅ 终版，作为对外传播主视觉

## 五、关键技术决策

### HTML+Edge 截图路线（v2-v6 全部采用）
- **优势**：中文完美、信息密度可控、深色风格支持好
- **路径**：`toolbox/ahl_infographic_v{N}.html` + `shoot_ahl_v{N}.ps1`
- **Edge 调用**：`--headless --disable-gpu --hide-scrollbars --no-sandbox --force-device-scale-factor=2 --window-size=1080,1920`

### AI 图像生成失败总结
- **MiniMax image-01**：中文乱码（不支持中文渲染）→ ❌
- **OpenAI gpt-image-1.5**：连接超时（199.59.148.89:443 ETIMEDOUT）→ ❌
- **最终结论**：复杂中文海报**不用 AI 生成**，用 HTML+Edge 截图是 100% 可靠的路线
