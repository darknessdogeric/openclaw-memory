## 一、项目本质

### 1.1 一句话定义

**AHL = 住宿业从"货架经济"到"客户经济"的范式革命者**

不是OTA替代品，而是用AI向量匹配重构住宿业交易底层逻辑的新协议。

### 1.2 范式革命的核心逻辑

**旧范式（货架经济）**：
```
商家生产 → 放到OTA货架 → 消费者浏览100页 → 随便选一个
问题：被动等待 / 信息过载 / 佣金20-30%
```

**新范式（客户经济）**：
```
消费者: "我想住大理古城带院子的民宿，喜欢有故事的老房子，预算500"
AI管家: 理解需求 → 精准匹配 → 推荐最合适的3家 + 解释原因
同时：商家AI运营官主动分析服务能力 → 精准推送给目标客户

结果：最合适的客人 ↔ 最合适的商家，双向价值最大化
```

## 四、产品架构

### 4.1 核心架构：四层金字塔

```
Layer 4: 应用层（消费者+商家）
  消费者: 自然语言交互
  商家: AGENT运营决策

Layer 3: 双AGENT智能层
  C端AI管家 ↔ 向量匹配引擎 ↔ B端AI运营官

Layer 2: AGENT集群层（9大AGENT × 87个SKILL）
  核心AGENT + 营销 + 收益 + 工程 + 安防 + 宴会 + 财务 + 人力 + 供应链

Layer 1: 数据协议层
  标准向量数据 + 非标向量数据（深水数据）
```

### 4.2 双AGENT架构

**C端AI管家**：
- 自然语言理解需求
- 提取需求实体 → 生成需求向量
- 向量检索Top-K匹配商家
- 多轮对话澄清需求
- 直连预订，无中间商

**B端AI运营官**：
- 产品/服务向量化封装
- 动态定价与库存管理
- 客户洞察与精准营销
- AGENT集群协同运营

| 指标 | 数值 |
|------|------|

|------|-----|-----|
| 收费模式 | 技术费2-3% | 佣金15-25% |

| 商户关系 | 赋能型 | 抽成型 |
| 技术路线 | AI原生 | 传统互联网 |

### 5.2 核心壁垒

1. **深水数据**：噪音分贝、光照指数、主理人语义画像（OTA采不到）
2. **垂类模型**：AHL-LLM懂住宿业非标需求
3. **协议层**：向上连接大模型，向下连接PMS
4. **网络效应**：越多商户接入，AI推荐越准，用户越多
