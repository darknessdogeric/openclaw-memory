## 2. cron_to_obsidian 双通道（--content-file + --append-daily）

**场景**：R60-11 主报告内容较长（>10KB），不适合直接传 --content 参数

**用法**：
```bash
# Step 1: 主报告写入临时文件
write /tmp/self-check-am-2026-08-08.md

# Step 2: 推送（双通道）
python toolbox/cron_to_obsidian.py \
    --task "深度自检上午" \
    --content-file "/tmp/self-check-am-2026-08-08.md" \
    --importance high \
    --summary "{3 条要点}" \
    --append-daily
```

**优势**：
- 主报告推送 + 日记摘要同步 = R60-11 沉淀动作的标准实现
- --content-file 避免命令行长度限制
- --append-daily 让日记与 cron 报告同步

## 3. HEARTBEAT.md edit-tool 原子写（R271 持续执行）

**场景**：避免 R-NEW-V3 数据丢失事件（HEARTBEAT.md 第三次数据丢失 8/7）

**用法**：
```python
# ❌ 错误（会覆盖）
write('memory/HEARTBEAT.md', '...')

# ✅ 正确（原子追加）
edit('memory/HEARTBEAT.md', oldText='...', newText='\n### HB #...\n- ...')
```

**优势**：
- 不会因 write 工具覆盖而丢失历史数据
- 自第三次数据丢失事件后未再发生
- 已成为 HB 写入的强制规范
