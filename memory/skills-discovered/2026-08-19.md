## 协议级发现 (R283 草案)

### R283: 跨会议主题联动识别协议
**触发条件**:
- 24h 时间窗口内 Eric 推送 ≥2 份会议纪要 / 文件
- 文档字数总和 ≥3000 字
- 文档之间存在时间或主题相关性(由 Eric 推送时间差 <30 分钟作为初始信号)

**核心规则**(四条铁律):
1. **批处理识别** - 单次推送的多文档 = 一次战略动作,不是多次独立
2. **主题矩阵提取** - 每份文档抽象出 3-5 个核心标签
3. **共同战略轴提取** - 找出多文档的"交集命题"(主战略方向)和"并集缺口"(应提到而未提的)
4. **联动分析报告** - 在每份单独 absorption 报告后,附加"批处理联动分析"段

**8/18 实证**:
- 国宴 + 平安 → "安逸 IP+渠道双驱动" = 共同战略轴
- 共同轴 = "从酒店持有方升级为生态整合方"
- 并集缺口 = "数字化中台连接 IP 和客户"(钟华运管部 RFP/TMC 是基础设施层)

**关联规则**:
- R264 v3.0 (AnYi 留痕协议) - 单文档吸收的协议
- R66 (文件接收质量门控) - 单文档纠错
- R282 (AI 渠道情报协议, 候选) - 跨主题识别的方法论原型
- R280 (战略任务即时结构化协议) - 同为批处理场景

**理由**:
- 单文档吸收(R264 v3.0)的盲区 = 跨文档的结构性盲区
- Eric 在高密度会议周使用"批处理推送"是必然模式(节省操作时间)
- B166ER 必须从"单文档吸收"升级到"批处理吸收 + 联动分析"
- 否则 = 信息孤岛,无法识别"跨会议战略动作"
