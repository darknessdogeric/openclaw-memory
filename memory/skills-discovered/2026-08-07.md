## 1. cron_to_obsidian.py --content-file 模式

**场景**：R60-11 主报告内容较长（>10KB），不适合直接传 --content 参数。

**用法**：
```bash
# 1. 先把报告写入 /tmp/self-check-{today}.md
# 2. 然后用 --content-file 推送
python D:/B166ER-OpenClaw/workspace/toolbox/cron_to_obsidian.py \
    --task "深度自检晚间" \
    --content-file "/tmp/self-check-2026-08-07.md" \
    --importance high \
    --summary "{3 条要点}" \
    --append-daily
```

**优势**：
- 大文件不超命令行长度限制
- 内容可复用（同一文件可多次推送）
- 与 R60-11 协议对齐（Eric 唯一推送通道）

## 3. 最佳实践：早间 cron 异常触发的透明化处置

**事件**：cron 标题"晚上 21 点"任务在 08:10 早晨触发

**最佳实践**：
1. **不静默忽略** — 在报告中明确标注异常
2. **不中断执行** — 按 R60-11 协议完成 9 章节报告
3. **透明化披露** — 在 §0 中说明 cron 异常 + 处置方式
4. **影响最小化** — 早间执行比晚间更静默（R69 合规更安全）

**模板**：
```markdown
## § 深度自迭代晚间

### 0. cron 异常触发说明（透明化）
| 字段 | 值 |
|------|-----|
| 触发时间 | 2026-08-07 08:10 GMT+8 |
| 任务标题 | "B166ER-深度自迭代-晚上 21 点" |
| 判定 | 定时器调度异常 |
| 处置 | 视为晚间 21 点 cron 提前触发，按 R60-11 协议执行 |
```
