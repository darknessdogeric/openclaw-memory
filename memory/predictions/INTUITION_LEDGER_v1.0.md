# 直觉预判台账 v1.0（Intuition Ledger）

> 触发：2026-11-19 00:41 Eric「我不知道未来会走向何方。但我又似乎有一种感觉非常强烈的指引，或者说引诱着我……我可能给不出特别确切的证据，但是我就是强烈的相信。并且经常在2-3年后应验……也正因为如此我在当时就会显得非常另类，并且孤独。」
> 定位：把「说不清证据但强烈相信、2-3 年后应验」这件事，从**个人叙事**变成**可审计资产**。
> 相关：[[2026-11-19_思考操作系统_v1]]（第 6 条质检：可证伪 / 错误账本）

---

## 0. 为什么要有这个台账

现状：这类判断只存在于 Eric 的直觉里，事后由**事后的自己**评分（"偏差不大"）。事后评分的三个致命缺陷：

1. **叙事重构** — 2-3 年足够长，模糊表述几乎总能被解读成"方向对了"。
2. **口径漂移** — "偏差不大"没有事前标准，等于事后给自己发合格证。
3. **无法归因** — 赢不知道为什么赢（真直觉 or 好故事），输不知道为什么输（领域不适用 or 时点错了）。

结论：**不登记 = 永远停在"我一向如此"，无法升级为可复用的判断力，也无法承担"别人跟着我走"的责任。**

---

## 1. 一条铁律

**登记必须发生在直觉发生的那一刻，不是想通之后。**

- 想通之后写 = 事后叙事，不是记录。
- 允许"当天补记"，但必须标 `registration=retrospective`，**不进命中率样本**。
- 这条铁律本身就是防自欺的唯一机制。

---

## 2. 字段规范（每条一行 JSON）

| 字段 | 含义 | 要求 |
|---|---|---|
| `id` | `IL-xxx` | 唯一递增 |
| `as_of` | 直觉发生日 `YYYY-MM-DD` | 必填 |
| `registration` | `live`（当场记）/ `retrospective`（事后补记） | 必填 |
| `domain` | 领域标签（酒店存量改造 / AHL / 集团战略 / 宏观 / 个人路径…） | 必填，用于分域校准 |
| `claim` | **一句可证伪的命题（不变层）** | 必填。禁止"会变好/会被重视"这类不可证伪表述 |
| `claim_form` | **同一判断的形态层表达**（时点/主体/具体形式） | 建议填；缺省视为该条只登记了不变层 |
| `direction` | `up` / `down` / `flat` / `mixed` | 必填 |
| `confidence` | 自评概率 0-1 | 必填（**必须数字，不许"很确定"**） |
| `horizon_months` | 兑现窗口（月） | 必填 |
| `basis` | 当时的依据：观察到什么、什么触发了这股感觉 | 必填（哪怕只有一句） |
| `falsifier` | **什么现象出现就判我错** | 必填，且必须是可观测事件 |
| `status` | `open` / `hit` / `partial` / `miss` | 结算时回填 |
| `resolve_date` | 实际结算日 | 结算时回填 |
| `actual` | 实际发生了什么（一句话事实，非评价） | 结算时回填 |
| `lesson` | **这次错在判断还是执行？是领域不适用还是时点问题？** | 结算时必填 |

> ★ `falsifier` 是这个台账的心脏。写不出 falsifier，说明这还不是一个判断，只是一股感觉。

### 2.1 ★ 双层登记（关键）

一个"2-3 年后基本对但形态不同"的直觉，其实含**两层**：
- **不变层（structure）**："酒店存量改造的需求会释放，但释放不等于可盈利"——大概率对
- **形态层（form）**："2028 年前后会有一轮 XX 形态的改造潮"——大概率偏

两层混在一句话里登记，会在结算时永远说不清"到底哪里对了、哪里错了"。**因此每条记录必须分开写：**

| 层 | 字段 | 结算标准 |
|---|---|---|
| 不变层 | `claim` | 方向与结构性判断对即 `hit` |
| 形态层 | `claim_form` | 具体形态/时点/主体对才算 `hit`；偏差大记 `partial` |

**不变层命中率高、形态层命中率低，是正常且有价值的** —— 它证明你的直觉是**结构性**的，而不是预言性的。结论：这类直觉用来**定方向与排除选项**，不用来**定时点与定形态**（那部分要交给数据与机制）。

## 3. 结算规则（到期自动触发，人工判定）

| 结果 | 判据 |
|---|---|
| `hit` | `claim` 的核心断言成立，`falsifier` 未触发 |
| `partial` | 方向对但量级/时点/形态偏差大（**必须写明差在哪**，不能含混过关） |
| `miss` | `falsifier` 触发，或方向反了 |

**自评偏袒规则**：`confidence ≥ 0.8` 的条目结算为 `partial` 时，**记一次"过度自信"**；`confidence ≤ 0.4` 却 `hit` 的，记一次"低配"。两种都要在 `lesson` 写清楚。

---

## 4. 校准指标（每年一次结算后自动算）

1. **命中率** = (`hit` + 0.5×`partial`) / 已结算条数
2. **Brier 分** = mean((实际结果 − confidence)²)，越低越好（≤0.15 算校准良好）
3. **分域命中率** —— 这一栏最重要：**验证"我的直觉在哪类事情上可靠、在哪类上不可靠"**
4. **过度自信指数** = 高置信区间的实际命中率 − 该区间平均自评

> 校准的意义：**把"我一向很准"这句自我评价，换成一组可核对的数字。** 校准良好时，这种强直觉才是**可下注的资产**；若校准差，那它更适合当**假设生成器**（用来生成待验证的线索），不适合当**决策依据**。

## 6. 使用节奏

- **发生当天**：`live` 登记（10 分钟内写完 `claim` + `falsifier` + `confidence` 数字）
- **到期当周**：结算 `status` + `actual` + `lesson`
- **每年 1 月**：跑一次校准统计，回写本文件第 7 节
- **新领域开始前**：先查第 7 节——**这个领域我过去的命中率是多少？低于 0.5 就不要重仓**

## 8. 已知限制

- **样本量**：一年到不了 10 条 live 记录 → 统计上无意义，**只能定性用**。别拿第 3 条就下结论。
- **自我评分偏差无法根除**：这套机制只是把偏差**显影**，不能消除。真要消除，需要至少一个人（Eric 本人最好，别人的估值最贵）定期交叉核验。
- **强烈的确定感本身会污染 confidence 估计**：直觉越强，自评越高，往往越不校准。**建议 confidence 不要超过 0.75**，除非有可核验的硬证据（这是刻意的逆压）。
- **2-3 年窗口太长**：期限内世界会变，判断的"对象"可能已换人。所以 `claim` 要写清**对象是谁**（哪家公司、哪个集团、哪个角色）。
