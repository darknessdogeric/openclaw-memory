## 七、★ 工具与方法论教训（可复用）
1. **OTA 深爬可行性**：携程**详情页**（`https://hotels.ctrip.com/hotels/<id>.html`）用 web_fetch 的 readability 抽取**能抓通**（含真实住客点评原文、酒店政策、开业/装修/房量、酒店简介全文）；**列表页会 302 到无关酒店页，抓不到**。要竞对 hotelId，先 web_search（domain_filter=hotels.ctrip.com）从 snippet 取 URL 与 hotelId，再逐个抓详情页。
2. **子代理在重爬取任务上会烧光预算**：本次 4 路并行调研中 3 路超时无产出（累计 122 次工具调用无可见输出）。**重爬取类任务应自己小批量定点抓，或给子代理明确"抓不到即停"的收敛条件。**
3. **模型 bug 两处（均已修）**：① 收入模型 `build_rev` 把非房算成客房×2，导致总收入虚高 50%（正确：非房＝客房＝50% 倒挤，`total = room/0.5`）② 反算投入漏计整体设计费 150／样板房 30／隐蔽工程 230。
4. **写 Python 脚本时手写 tuple 极易把结尾 `)` 写成 `]`**：本轮反复触发 SyntaxError。**用通用修复器批量处理**（行首 `(` 且行尾 `]`/`],` 且 `(` 计数多于 `)` → 末位 `]` 换 `)`），比逐处手改快。
5. **Excel 列宽按内容量分配的正确做法**：权重＝该列单元格**平均**内容量（中文 1 单位、ASCII 0.5），下限按**渲染宽度**而非字符数（`units × 字号 × 0.0353 + 内边距`），否则中文列会比数字列窄很多。
