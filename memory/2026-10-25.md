### 扫描器第 3 次加固：覆盖度静默降级 + git 熔断漏计（2026-10-25 20:22-20:45）

**cron 报告自己标出的真缺陷（我认同并已修）**：
「clawhub 查询 hotel 返回 rc=-1（15.6s 超时/失败）→ 本轮 hotel 关键词可能未取全，
酒店侧候选覆盖度打折」→ **我的向量通道超时即放弃、不重试、不告警**，
于是「某个方向没取全」这件事**只体现在 stdout 的一行 rc=-1**，不写进报告也不写进 JSON
→ 下游（无论是人读还是 agent 读）**无法察觉覆盖度已降**。

**两处修复**
1. **向量通道**：rc=-1 时**用 2 倍超时重试一次**；仍失败则记入 `vec_failed`，
   并在**报告正文 + 结构化 JSON** 双处输出「覆盖度缺口：<关键词>（该方向候选打折）」告警。
2. **git 网络熔断**：`rc == -1`（超时）原先**不计入** `consec_net_fail`，
   只有 neterr 才计 → timeout 型失败不触发熔断，会把 6 个仓逐个等一遍。
   现超时同样计入熔断计数。

**修复效果（实测对比）**
| 指标 | 20:22 轮（修前） | 修后实测 |
|---|---|---|
| 总用时 | 126.7s | **44.7s**（网络预检直接跳过，省 82s 无谓等待）|
| 市场去重 | **5 条**（hotel 超时未取全 → 打折）| **10 条**（完整）|
| git 分类 | 失败 3｜跳过 3 | **失败 0｜跳过 6**（预检熔断，不逐个等）|

**教训**：**任何通道的「没取全」都必须显式落盘成可被下游读到的告警**，
而不是只留在 stdout 的一行 return code —— 否则「静默降级」会让整轮结论看起来正常却实际残缺。
（与 R-HEAL-25 同族：不能靠人眼扫 stdout 判断完整性，要让机器可读。）

### 正则子串假阳性：差点把「该能力仍需自建」的真实空白掩盖成 THIN（2026-10-25 20:30-20:50）

**经过**：我把「能力空白判定」并进技能市场扫描器（复用 `registry_gap_probe.py` 的 GAPS 定义，零额外网络请求），
**首次实跑**就发现判定结果不对：
「酒店竞品房价 / 动态定价监控」被判 **THIN**，域内核心命中 = **`pricing-calc`** ——
而 `pricing-calc` 是**通用 SaaS 产品定价计算器**（value metric / tier packaging / 涨价测试），
**跟酒店竞品房价监控毫无关系**。

**根因（我自己的正则写得太松）**：
| 规则里的词 | 它其实是 | 后果 |
|---|---|---|
| `otel`（`hotel` 的备用拼写） | **`hotel` 的子串** | 任何含 "hotel" 的描述都命中 → 几乎全中 |
| `ota` | **`total` 的子串** | 几乎任何描述都命中 |
| `peer` | 命中 "peers" | 竞品语义被误判 |
| `map` | 命中 "roadmap" | 选址语义被误判 |
| `geo` | 命中 "geology" | 同上 |

**修法**：拉丁短词全部加**词边界** `\b`（`\bhotel\b`、`\botel\b`、`\bota\b`、`\bpeers?\b`…），中文不受影响。
**回归验证**（已跑）：
```
pricing-calc       core=0  ← 修前 core=1（假阳性消除）✅
\bota\b  vs "total revenue"  → False ✅
\botel\b vs "hotel pricing"  → False ✅
```

**修正后的空白状态（本轮真值）**
| 能力缺口 | 状态 | 域内核心 | 判定 |
|---|---|---|---|
| 酒店竞品房价/动态定价监控 | **ADJACENT** | **无** | 只有相邻的电商竞品监控 → **市场买不到，必须自建** |
| 酒店存量翻新选址分析 | THIN | amap-lbs/jsapi/cli、gaode-map-pro、amap… | 真实供给（高德全家桶） |
| 酒店私域/会员/复购 | THIN | majia-huiyuan、retail-member-points-check-free… | **通用会员工具，非酒店专用** |
| 酒店房价聚合（对照组） | THIN | china-hotel-price-compare、hotel-smart-book… | 对照组有供给 → **判定不过严，方法已校准** |

**差分机制已验证有效**：本轮自动报出「酒店竞品房价/动态定价监控：**THIN → ADJACENT**」——
即**它自动发现我上一轮的结论被自己的假阳性污染，并纠正回来**。
这正是把空白判定做进扫描器的价值：以后每轮都会盯住「我们的核心能力空白是否被填补」。

**教训（与 R-HEAL-25 同族，但更隐蔽）**：
- **短拉丁词必须加 `\b`**：`hotel`/`otel`、`total`/`ota` 这类「一词是另一词的子串」，
  在做**语义域判定**时会造成系统性假阳性（不是偶发，是必然）。
- **判定器的输出必须自校验**：用一个**已知该命中的样本** + 一个**已知不该命中的样本**跑一遍
  （本次用 `pricing-calc` 当反例、`amap-lbs-skill` 当正例），**回归验证通过才敢用它的结论**。
- **差分机制比绝对值更可靠**：状态从 THIN 变 ADJACENT 的**变化**本身就是信号 ——
  它暴露了上一轮判定的污染，孤立地看当前值是看不出来的。
