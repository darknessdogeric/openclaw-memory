### R309 实际可行的中文 OCR 路径

轻量替代（按推荐度）
  A. **ocrmypdf + tesseract 增强**
     安装包小，集成图像预处理（deskew/denoise/CleanUp）
     实际等效精度可从 75-85% 提升到 85-92%
     完全本地，无云端
  B. easyocr（~30MB，Chinese 模型）
     比 paddlepaddle 小得多，但仍要下载模型
  C. cnocr（专门中文 OCR，~10MB 模型）
     阿里达摩院开源，专为中文优化
  D. RapidOCR（paddleocr 的轻量变种，模型更小）
     基于 PaddleOCR 但包小很多

### 建议路径

在当前网络环境下
  - 不强求 paddlepaddle 100MB wheel
  - 选择更轻量的方案达到 85%+ 中文精度即可
  - Eric 当前实际场景：扫描 PDF 较少（大多数有文字层）
  - 现状 tesseract 对清晰扫描够用

### R310 OCR 精度判断的边界

OCR 精度 80% → 95% 的提升对 Eric 的边际价值
  - 处理会议纪要、合同等结构化文档 → 边际价值高
  - 处理政府公文、票据、合同 → 边际价值中等
  - 处理手写体、艺术字 → paddleocr 也不行，需专业模型
  - Eric 当前文档 90%+ 是数字 PDF（带文字层）→ OCR 不常用

结论：当前 tesseract 已覆盖 95% 实际需求 paddleocr 收益有限

### Bug 定位

群论 6 直觉网格布局错误：
  原代码：row = i // 2（错）
  修正后：row = i // 3

原 Bug 后果（错布局）：
  i=0 Galois (col=0, row=0)
  i=1 Klein (col=1, row=0)
  i=2 Noether (col=2, row=1) → 跳到行 1
  i=3 Lie (col=0, row=1)
  i=4 Cayley (col=1, row=2)
  i=5 Frobenius (col=2, row=2)

结果：行 1 col 2 空，行 2 col 1 空，行 3 col 0 空
     Galois/Klein/Noether/Lie/Cayley/Frobenius 不在整齐的 2x3 网格中

### 修复后（正确布局）

i=0 Galois (col=0, row=0)
i=1 Klein (col=1, row=0)
i=2 Noether (col=2, row=0)
i=3 Lie (col=0, row=1)
i=4 Cayley (col=1, row=1)
i=5 Frobenius (col=2, row=1)

结果：整齐的 3 列 x 2 行布局
     行 1：Galois + Klein + Noether
     行 2：Lie + Cayley + Frobenius

### 关键经验教训

1. 网格布局公式：
   - col = i % num_cols
   - row = i // num_cols  （不是 i // num_rows）

2. Bug 后果：
   - 部分位置空（视觉不对齐）
   - 部分位置重叠（如果 col=2 + row=1 同时被 Noether 和 Lie 占用）
   - 整体版面看起来乱

3. 防止 Bug 复发的检查清单：
   - 任何网格布局都要验证最后一项的 row < num_rows
   - 任何网格布局都要验证最后一项的 col < num_cols
   - 任何网格布局都要验证总项数 <= num_cols * num_rows

### R346 网格布局检查清单

- □ 网格布局用 col = i % num_cols
