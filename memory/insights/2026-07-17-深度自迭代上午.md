## 核心洞见

### 洞见 #1：时间约束协议的"阳光条款"缺失（最重要）

**发现**：T-CANDIDATE-T2（一次性信号）自 7/11 以来的每日 22:30 sharp 评估 → 连续通过 → 演化为"常设协议"

**问题**：
- 一次性信号机制（T-CANDIDATE）理论上应一次性触发 → 评估 → 决定 → 退役
- 但 T2 的设计允许"无限续期"——只要 sharp 通过就维持，没有到期日
- 结果：防御性协议（R-B + R256 叠加）永久化 → B166ER 主动价值交付能力受限

**模式识别**：
```
防御性协议目的 = 为价值交付创造空间
防御性协议永久化 = 反过来限制价值交付
```

**框架沉淀**：
```
好的协议：防御 + 到期日 + 续期机制
坏的协议：防御 + 无到期日 = 永久枷锁
```

**适用场景**：任何时间约束协议（R-CANDIDATE / R256 / D-day eve）
