## 一、OKR方法论

### 1.1 OKR定义与起源

```
OKR = Objectives and Key Results（目标与关键结果）

起源：
- Intel CEO Andy Grove (1970s) 发明
- John Doerr 传入Google并推广 (1999)
- 现任CEO Sundar Pichai: "Google的每一次成功都源于OKR"

核心思想：
- 目标(Objective): 定性的方向，激励人心
- 关键结果(Key Results): 定量的指标，可衡量
- 聚焦重点，避免忙碌但不有效
```

### 1.2 OKR vs KPI

| 维度 | OKR | KPI |
|------|-----|-----|
| 目的 | 挑战性目标，推动创新 | 达成性目标，保底基准 |
| 评分 | 0-1.0，通常0.6-0.7为佳 | 100%为满分 |
| 公开 | 全员透明对齐 | 通常管理层可见 |
| 周期 | 通常季度 | 通常月度/季度 |
| 结果 | 不直接关联薪酬 | 直接关联绩效 |

### 1.3 OKR结构

```
┌─────────────────────────────────────────────────────────────────┐
│                         OKR结构                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Objective (目标) - 定性的方向                                   │
│  ├── 鼓舞人心，激励团队                                        │
│  ├── 清晰可理解                                                │
│  ├── 有挑战性但可达成                                          │
│  └── 时间-bound (季度/年)                                        │
│                                                                 │
│  Key Results (关键结果) - 定量的衡量                            │
│  ├── 符合SMART原则                                             │
│  ├── 数量化/可衡量                                              │
│  ├── 有挑战性 (完成70%=成功)                                    │
│  └── 通常3-5个/Objective                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.4 OKR评分标准

| 评分 | 完成度 | 说明 |
|------|--------|------|
| 1.0 | 100% | 极端困难，通常不可持续 |
| 0.7-0.9 | 70-90% | 良好，符合预期 |
| 0.6-0.69 | 60-69% | 可接受，需要改进 |
| 0.3-0.59 | 30-59% | 不达标 |
| 0-0.29 | 0-29% | 严重不达标 |

**评分不是绩效考核**，而是学习反馈

### 1.5 OKR周期

```
┌─────────────────────────────────────────────────────────────────┐
│                         OKR季度周期                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Q第1周: 制定OKR (制定+对齐)                                   │
│    ├── 制定: 基于战略制定Objectives                             │
│    ├── 对齐: 团队/个人OKR上下对齐                              │
│    └── 公示: 全员可见                                          │
│                                                                 │
│  Q第2-10周: 执行+周检视                                        │
│    ├── 周一: 本周KR进展更新                                     │
│    ├── 周五: 团队周会对齐                                      │
│    └── 持续调整: 环境变化时适度调整                              │
│                                                                 │
│  Q第11周: 中期复盘                                             │
│    ├── 进展评估: 预测完成度                                     │
│    ├── 问题识别: 识别障碍                                       │
│    └── 调整决策: 是否需要调整KR                                 │
│                                                                 │
│  Q第12周: 评分+总结                                            │
│    ├── 自评: 每项KR自评                                        │
│    ├── 校准: 团队校准                                          │
│    ├── 总结: 季度总结+下季规划                                  │
│    └── 庆祝: 达成庆祝，未达成学习                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.6 OKR制定流程

```
Step 1: 明确使命/愿景
    └── 我们的长期目标是什么？

Step 2: 确定战略主题
    └── 本季度最重要的事是什么？(最多3个)

Step 3: 制定Objectives
    └── 每个战略主题对应的目标

Step 4: 制定KRs
    └── 每个O对应的KR (3-5个)

Step 5: 上下对齐
    └── 团队O对齐公司，个人O对齐团队

Step 6: 公示确认
    └── 全员可见，接受监督
```

### 3.2 GTD方法论

```
GTD = Getting Things Done

核心原则: 清空大脑，信赖系统

五步流程:

┌─────────────────────────────────────────────────────────────────┐
│                        GTD五步                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Step 1: 收集 (Collect)                                        │
│  └── 将所有"在脑中"的事务倒入收集箱                             │
│      - 纸笔/笔记/邮件/消息                                      │
│                                                                 │
│  Step 2: 处理 (Process)                                         │
│  └── 逐一处理收集箱:                                           │
│      - 是否可执行?                                              │
│        - 是 → 2分钟? → 立刻做                                  │
│                  → 2分钟+是否委托? → 委托                       │
│                  → 2分钟+是否推迟? → 排日程                      │
│        - 否 → 参考资料? → 归档                                  │
│               → 日后可能? → 等待清单                            │
│               → 垃圾? → 删除                                    │
│                                                                 │
│  Step 3: 组织 (Organize)                                       │
│  └── 建立项目清单、等待清单、下一步行动                          │
│                                                                 │
│  Step 4: 回顾 (Review)                                          │
│  └── 每日回顾: 今日任务                                        │
│      每周回顾: 回顾所有清单，调整计划                           │
│                                                                 │
│  Step 5: 执行 (Do)                                             │
│  └── 依情境/时间/精力选择任务执行                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.3 番茄工作法

```
番茄工作法: 25分钟专注 + 5分钟休息

┌─────────────────────────────────────────────────────────────────┐
│                       番茄钟流程                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  计划: 列出今日任务                                            │
│    ↓                                                            │
│  计时: 设定25分钟，专注工作                                   │
│    ↓                                                            │
│  计时结束: 休息5分钟                                         │
│    ↓                                                            │
│  循环4次后: 长休息15-30分钟                                   │
│    ↓                                                            │
│  每日回顾: 统计完成数，分析改进                                │
│                                                                 │
│  核心原则:                                                    │
│  - 一个番茄钟 = 25分钟 = 不可分割                            │
│  - 专注 > 时长                                                 │
│  - 保护番茄钟，不被打断                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.4 时间块方法

```
时间块 (Time Blocking): 将一天分成若干时间块，每块专注一件事

┌─────────────────────────────────────────────────────────────────┐
│                       一天时间块示例                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  06:00-07:00  晨间仪式 (冥想/运动/阅读)                         │
│  07:00-08:00  早餐 + 通勤                                      │
│  08:00-10:00  深度工作块1 (最重要的事)  ★★★                   │
│  10:00-11:00  会议块 (集中处理)                                │
│  11:00-12:00  深度工作块2 (次重要的事)  ★★                    │
│  12:00-13:00  午餐 + 休息                                      │
│  13:00-15:00  行政/邮件/消息处理                               │
│  15:00-17:00  协作块 (会议/讨论)                              │
│  17:00-18:00  收尾块 (回顾+计划明日)                         │
│  18:00-20:00  家庭/生活                                       │
│  20:00-22:00  学习/副业 (如果做AHL)                          │
│  22:00        休息                                             │
│                                                                 │
│  关键:                                                         │
│  - 保护深度工作块不被干扰                                      │
│  - 精力最高时做最重要的事                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 四、复盘方法论

### 4.1 KISS复盘法

```
KISS = Keep, Improve, Start, Stop

┌─────────────────────────────────────────────────────────────────┐
│                        KISS复盘                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Keep (保持) - 做得好的，继续保持                               │
│  └── 列出做得好的3-5件事                                       │
│                                                                 │
│  Improve (改进) - 需要改进的                                    │
│  └── 列出需要改进的2-3件事                                     │
│                                                                 │
│  Start (开始) - 以前没做，应该开始的                           │
│  └── 列出新发现的1-2件事                                      │
│                                                                 │
│  Stop (停止) - 不应该再做的                                    │
│  └── 列出应该停止的1-2件事                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 PDCA循环

```
PDCA = Plan, Do, Check, Act

┌─────────────────────────────────────────────────────────────────┐
│                        PDCA循环                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Plan (计划)                                                   │
│  └── 制定目标和方法                                           │
│                                                                 │
│  Do (执行)                                                     │
│  └── 按计划执行                                               │
│                                                                 │
│  Check (检查)                                                  │
│  └── 评估结果，发现问题                                       │
│                                                                 │
│  Act (行动)                                                    │
│  └── 标准化成功，改进失败                                       │
│      ↓                                                         │
│      循环进入下一个Plan                                         │
│                                                                 │
│  核心原则:                                                    │
│  - 小步快跑，快速迭代                                          │
│  - 每次循环都是升级                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
