# 小红书行业科普 9 图范式 v1.0

> **触发背景**：Eric 要求做「酒店分级分类」9 图笔记。v1 我用了自研深空蓝卡片范式，被三条批评打回：
> ① 维度不全（只写了政府星级 + 港澳台，漏了集团/品牌/数据机构/渠道商/消费者端）
> ② 信息全集中在页面上部、字体太小
> ③ 范式用错 —— 「这种属于行业科普或者行业研究类话题应该用什么范式」，且设计能力没用上

## 一、正确范式：Clean & Minimal（不是自创深空蓝）

**出处**：`skills/article-to-infographic/references/style-presets.md`

> "Clean & Minimal —— Refined, trustworthy, editorial · **Best for: Timelines, process flows, magazine layouts** · Off-white or warm gray, **avoid pure white** · Subtle box-shadow, thin borders, generous padding"

| token | 值 | 依据 |
|---|---|---|
| `--bg-primary` | **#f7f4ec**（暖白纸，避开纯白）| style-presets: avoid pure white |
| `--bg-card` | #ffffff + 1px 细边框 + 6px 圆角 | "thin borders, generous padding" |
| `--text-primary` | #1c1917（墨）| |
| `--text-secondary` | #78716c | |
| `--accent-1` | **#a05f26（单一强调）| craft/color.md: 强调色每屏 ≤2 处 |
| 字体 | Noto Serif SC（标题）+ Noto Sans SC（正文）| 不用 JetBrains Mono 当通用字体 |

**其他 3 个预设各归其位**（下次按内容选）：
- Bold & Vibrant → 活力营销类
- Dark & Techy → 技术/极客类
- **Warm & Editorial → 故事叙事类**（本库另有浅底纸感版可参考 2026-10-26）
- **Clean & Minimal → 行业科普/研究类 ← 本范式采用**

## 二、三段式结构：根治「信息集中在上部」

```html
<div class="wrap">        <!-- height:100%; display:flex; flex-direction:column -->
  <div class="head">     <!-- flex:0 0 auto  固定 -->
    kick / h1 / sub
  </div>
  <div class="body">     <!-- flex:1 1 auto; justify-content:space-evenly -->
    ...内容卡片...
  </div>
  <div class="foot">     <!-- flex:0 0 auto  固定 -->
    引文 / 信源
  </div>
</div>
```

**关键**：`.body` 撑满剩余高度并用 `space-evenly` 均匀分布 → **物理上不可能出现大片空白**。

**字号下限（1080×1440）**：
| 层级 | 字号 |
|---|---|
| h1 | 50px（长标题 41px）|
| 副标题 sub | 19px |
| 卡片标题 | 20px |
| 正文 | **17px**（v1 用了 13-15px，被批"太小"）|
| 标签 / 注释 | 13px |

## 三、维度覆盖：先定「谁在说话」再排内容

**行业类主题必须盘清所有「分级/评价体系」**，本次清单（酒店业）：

```
1 政府/国标（唯一法定）
2 国别体系（法国/英国/美国/日本/印度…）
3 集团分级（华住/锦江/首旅/亚朵/万豪/希尔顿…）
4 集团内品牌层级（希尔顿 6 档 / IHG 4 档 / 万豪 Classic+Distinctive…）
5 数据机构分级（STR Brand Scale/Class/STAR Report、米其林、Forbes）
6 渠道商评级（携程特牌金牌/飞猪钻级/途家优选严选臻选/同程月评/美团）
7 消费者评分（TripAdvisor 气泡、Booking）
⚠ 伪相关：信用评级（S&P/Fitch 评公司还债能力，非酒店）
```

**通用检查法**：写内容前先问「**这个主题上，一共有几套并行的评价体系？每套由谁定、给谁看？**」

## 五、生产管线（可复用）

```
_g9_lib.py   CSS（Clean & Minimal tokens）
_g9_page.py  page() 装配：head/body/foot 三段式
_g9_data.py  PAGES = [dict(kicker,title,sub,body,foot_q,foot_s), ...]
_g9_main.py  渲染 + DOM 排版检查
```

**DOM 排版检查（0 token，必须跑）**：

```javascript
// 1) 文字溢出容器   2) 元素超画布   3) 段落重叠   4) 段内容超段
```

**踩坑记录**：
1. JS 模板串 > ~8KB 会解析失败 → 拆多文件
2. 中文引号「""」在 JS→Python 传递中被吞 → 用「」
3. Python 三引号 CSS 字符串要自己核对收尾
4. page() 别忘输出 wrap 开标签
5. PowerShell `Set-Content -Encoding UTF8` 会加 BOM → ast.parse 报错（导入不受影响）
