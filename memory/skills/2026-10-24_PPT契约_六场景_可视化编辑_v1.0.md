## 二、① 前置契约：5 个必填参数

来源是逆向 Kimi 官方提示词得出的**输入 schema**（Kimi 的提示词不是自由发挥，而是显式参数）：

```
① 页数        total_slides
② 风格        style_preset (12 套具名之一, 不接受文字描述)
③ 目标听众    audience {who, knows, wants, action}   ← 不给默认值, 最易跳过也最致命
④ 必含章节    required_sections[] {name, conclusion, slides}  ← ≥3 项, 每项要有唯一结论
⑤ 数据源      data_sources[] {type, where, confidence}      ← ≥1 项, 示意数据必须标注
+ explicit_constraints (≥1 条, 尤其合规边界)
+ success_check (可判定的表述, 不接受"讲清楚")
```

### 使用流程

```bash
# 1) 复制场景模板改 (或从零写 brief)
cp assets/scenarios/05_提案融资.json my_plan.json

# 2) 生成前必跑校验 (硬门禁)
python scripts/validate_brief.py my_plan.json
# 7 项全过 → 才能进入生成
```

### 校验器行为

任一项不过 → 退出码 1 + 逐项说明缺什么 + 打印提问模板。
7 项：页数 / 风格 / 听众四项 / 章节≥3 且有结论 / 数据源≥1 / 显式约束≥1 / 成功判据可验证。

**已实测**: 6 个场景模板全部一次通过校验。

## 四、③ 在线可视化编辑器（我们补上的那层）

> Kimi 官方优势：「PPT 生成后可以点击预览，并在线修改」——这是我们此前唯一落后的一项。

### 零新依赖的复用

```
ppt-deck-builder-pro/scripts/
├── rerun_single_page.sh        ← 单页重跑   ★
├── package_image_deck.sh       ← 打包 pptx  ★
├── build_contact_sheet.py      ← 联系表总览  ★
└── generate_from_plan.py       ← 批量生成   ★
        + 新增这一层：浏览器网格预览 + 字段编辑 + 触发重跑
```

### 用法

```bash
python skills/ppt-visual-editor/scripts/visual_edit.py serve \
  --plan plan.json --images-dir out/ --port 8765 \
  --provider command --provider-command "python <your_provider.py>"
# 浏览器打开 http://127.0.0.1:8765
```

其他子命令：
```bash
visual_edit.py index  --plan P --images-dir D     # 状态表
visual_edit.py status --plan P --images-dir D     # 列出需重跑的页
visual_edit.py patch  --plan P --images-dir D --slide 5 \
        --set page_goal="新结论" --set approved_text_lines="标题|要点A" --rerun
```

### 网页上能改的 7 个字段

| 字段 | 作用 |
|------|------|
| `page_goal` | 本页要让观众记住的一句话 |
| `content` | 页面标题 |
| `approved_text_lines` | 页面上真正要出现的字（每行一个）|
| `text_regions` | 文字放哪（避免压图/越界）|
| `prompt_override` | 完全手写本页提示词（兜底）|
| `page_type` | cover/path/diagnostic/... 换排版类型 |
| `reading_path` | top to bottom / left to right 改阅读顺序 |

改动**即时写回 plan.json** → 网页改的 = plan 改的，两条路径永远一致。

## 五、踩坑记录（这次调试真实踩到的）

### 坑 1：`python3` 在 Windows Git Bash 是 Microsoft Store 桩

- 现象: 脚本零输出、退出码 **49**
- 根因: `python3` → `C:\Users\...\WindowsApps\python3`（Store 桩），调用即静默退出
- **错误修法（我第一次就踩了）**: `PY="$(command -v python3 || command -v python)"` —— `command -v python3` **会成功**（桩文件存在），所以 `||` 回退根本不触发
- **正确修法**: 逐个候选**实跑 `--version` 验证**：
  ```bash
  PY=""
  for _pycand in python3 python; do
    if command -v "$_pycand" >/dev/null 2>&1 && "$_pycand" --version >/dev/null 2>&1; then
      PY="$(command -v "$_pycand")"; break
    fi
  done
  ```
- 已应用到 6 个脚本：`check_env.sh` / `package_image_deck.sh` / `rerun_single_page.sh` / `run_full_deck.sh` / `run_image_batch.sh` / `run_reference_pack.sh`

### 坑 2：`shlex.split()` 吃 Windows 反斜杠

- 现象: `D:\B166ER-openclaw\...` → `D:\B166ER-openclawworkspacememory...`
- 修法: **provider 命令路径一律用正斜杠**

### 坑 3：重跑不会继承 provider

- 现象: 首次生成用 `--provider command` 成功，但 `rerun_single_page.sh` 不传 provider，回落到 plan 里的 `image_provider`（真实 API）→ 失败
- 修法: `visual_edit.py` 把 `--provider` / `--provider-command` / `--provider-option` **透传**给 `rerun_single_page.sh` 的位置 6+

### 坑 4：`Start-Process` 拆带空格的参数

- 现象: `--provider-command "python D:/..."` 被拆成两个 argv → argparse 报 unrecognized arguments
- 修法: `Start-Process -ArgumentList` 里元素要**自带引号**：`'"python D:/..."'`

## 六、纪律（逆向 Kimi 逆向来的）

1. **先看总览再动手** —— 打开网页第一件事是看网格，不要凭 plan 猜
2. **一次只改一页** —— 改完立刻看效果，避免多页同改导致风格漂移
3. **先改 brief 再改页** —— 某页反复改不好，多半是 brief 的「必含章节」或「听众」定错了
4. **改完必须重打包** —— 只重跑了图没重打包，交付的 pptx 还是旧的
5. **生成前必跑 `validate_brief.py`** —— 7 项门禁，缺一不进生成
