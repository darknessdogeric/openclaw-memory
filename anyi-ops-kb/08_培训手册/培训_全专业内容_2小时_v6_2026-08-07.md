|------|------|------|---------|

## 第 4 章 · 酒店的物理构成

### 4.1 不只是一间房——酒店的"前台+后台"解剖

### 4.2 前台的每一块都有利润逻辑

| 区域 | 核心功能 | 收入/利润贡献 | 关键运营指标 |
|------|---------|-------------|-------------|
| **客房** | 住宿——酒店的核心 | 通常占收入 50-70% | 入住率（OCC）、平均房价（ADR） |
| **餐饮 F&B** | 早餐+正餐+宴会+客房送餐 | 占收入 20-40%（高端酒店更高） | 翻台率、人均消费、食品成本率 |
| **会议/宴会** | MICE——会议、婚宴、活动 | 可占总收入 10-25% | 宴会厅利用率、每平米收入 |
| **康体/SPA** | 健身房、泳池、水疗 | 通常占总收入 <5%（但提升客户满意度） | 会员卡销售、日均客流 |
| **行政酒廊** | 高端客户专属空间 | 不直接产生收入，但提升套房溢价 | 行政楼层入住率 |

### 4.3 后台区域——不产生收入，但决定了成本

| 区域 | 功能 | 成本占比（在酒店总成本中） |
|------|------|--------------------------|
| **工程部** | 水电气、空调、电梯、维修 | 能耗占酒店总成本 10-15% |
| **客房部/布草房** | 客房清扫、布草清洗 | 人工成本 + 洗涤外包/自洗 |
| **厨房** | 食品加工、备餐 | 食品成本占餐饮收入 25-35% |
| **行政办公室** | 人事/财务/销售/预订 | 管理费占收入 5-10% |

## 第 5 章 · 酒店的核心运营指标

### 5.1 "你开酒店一个月赚多少？"——酒店业的六把尺子

| 指标 | 英文 | 公式 | 含义 |
|------|------|------|------|
| **入住率** | OCC (Occupancy) | 实际售出房间数 ÷ 可售房间总数 × 100% | "你今晚住了多少人" |
| **平均房价** | ADR (Average Daily Rate) | 客房总收入 ÷ 实际售出房间数 | "每个房间平均卖了多少钱" |
| **每间可卖房收入** | RevPAR (Revenue Per Available Room) | 客房总收入 ÷ 可售房间总数 = OCC × ADR | "每间房的赚钱能力"——最核心指标 |
| **经营毛利** | GOP (Gross Operating Profit) | 总收入 - 直接运营成本（不含折旧/摊销/利息/税） | "酒店运营赚了多少钱" |
| **息税折旧摊销前利润** | EBITDA | 净利润 + 利息 + 税 + 折旧 + 摊销 | "酒店的综合盈利能力" |
| **人房比** | Staff-to-Room Ratio | 员工总数 ÷ 客房总数 | "养了多少人来服务这些房间" |

### 38.3 收益管理的四大杠杆（详解）

| 杠杆 | 内容 | 实操举例 |
|------|------|---------|
| **定价** | 动态调价——不同日期、不同时段、不同客源不同价格 | 同一间标准大床房：周二晚 ¥450 → 周五晚 ¥780 → 糖酒会期间 ¥1280 |
| **库存** | 控制不同渠道的房间分配 | 酒店有 100 间房：40 间给携程（佣金 15%）、20 间给美团（佣金 10%）、30 间给会员直销（0% 佣金）、10 间留 Walk-in |
| **客源结构** | 不同客源类型给不同价格 | 商务协议价 600 元、旅游团队价 350 元（要 20 间起订）、OTA 散客价 500 元、会员价 450 元 |
| **时长控制** | 限制最少入住天数 | 国庆节："连住 2 晚起订"；淡季周一："住 1 晚也可以" |

### 一.1 核心公式复盘——从直觉到数学

| 公式编号 | 公式 | 中文 | 单位 |
|---------|------|------|------|
| F1 | RevPAR = ADR × OCC | 每间可卖房收入 | 元/间 |
| F2 | ADR = 客房收入 ÷ 售出房数 | 平均房价 | 元/间夜 |
| F3 | OCC = 售出房数 ÷ 可售房数 × 100% | 入住率 | % |
| F4 | 总客房收入 = 可售房数 × OCC × ADR = 可售房数 × RevPAR | 总客房收入 | 元 |

| 最差状态 | 40% | 250 元 | 100 元 | 既没量又没价 | 老旧酒店非旺季 |

### 55.2.5 市场细分专题：来龙去脉 × 现状 × 未来 × PMS × 集团统一规范

#### 55.2.5.A 什么是市场细分？

| 痛点 | 不做市场细分 | 做了市场细分 |
|------|------------|------------|
| 看不到真实客源结构 | 只能看总营收，不知道"OTA 占多少、TMC 占多少、协议占多少" | 56 家酒店客源结构一目了然 |
| 定价无差异 | 散客和 VIP 给同一价 | 商旅/会员/会议/OTA 各有不同价格策略 |
| 渠道佣金无优化 | OTA 占 50%+，佣金被抽血 | 看清楚后逐步降低 OTA 依赖 |
| 协议管理混乱 | 同一企业不同酒店不同价 | 集团统一价格体系 |
| 收益分析失真 | RevPAR 看不清真实经营状况 | 按市场细分看，才是真收益 |

#### 55.2.5.B 市场细分的来龙去脉（历史沿革）

| 阶段 | 时间 | 关键事件 |
|------|------|---------|
| **起源期** | 1950s | 美国酒店业开始用 "Source of Business" 概念追踪预订来源 |
| **成型期** | 1960s-1970s | Holiday Inn、希尔顿等建立市场细分编码体系（如 CORP=协议客户、WALK=散客）|
| **标准化期** | 1980s | 美国饭店协会（AHLA）推动 PMS 行业标准化，市场码进入 PMS 系统 |
| **自动化期** | 1990s | 全球 PMS 厂商（Micros/Opera/Protel）将市场细分作为标准字段 |
| **精细化期** | 2000s | 万豪/希尔顿开发 MARSHA/OnQ 等 CRS，市场细分与收益管理深度整合 |

| 集团 | 市场细分维度 | 典型应用 |
|------|------------|---------|
| **万豪（Marriott）** | 客户类型 + 渠道 + 价格等级 + 用途（商务/休闲）| MARSHA 系统支持 200+ 市场码 |
| **希尔顿（Hilton）** | 渠道 + 客户层级 + 协议类型 | OnQ 系统支持 150+ 市场码 |
| **洲际（IHG）** | 客户来源 + 价格码 + 渠道 | Concerto 系统支持 180+ 市场码 |
| **雅高（Accor）** | 渠道 + 会员等级 + 客户来源 | TARS 系统支持 100+ 市场码 |

| 阶段 | 时间 | 特征 |
|------|------|------|
| **1.0 手工期** | 2000s 早期 | 各酒店手工记录客源，无系统 |
| **2.0 PMS 导入期** | 2005-2015 | 西软/绿云 PMS 普及，市场细分作为标准字段 |
| **3.0 渠道分化期** | 2015-2020 | OTA 崛起，市场细分必须能区分 OTA/协议/会员 |
| **4.0 TMC+RFP 期** | 2020-2024 | 商旅集中采购，需要专门的市场码 |
| **5.0 AI+大数据期** | 2024+ | **市场细分 × AI 客户画像**成为可能 |

#### 55.2.5.C 市场细分的基本维度

| # | 维度 | 英文 | 典型取值 |
|---|------|------|---------|
| 1 | **客户类型** | Customer Type | 个体/企业/政府/团队/会议 |
| 2 | **预订渠道** | Booking Channel | 携程/美团/官网/TMC/电话/到店 |
| 3 | **市场码（市场来源）** | Market Code | OTA/协议/会员/会议/团队/政府 |
| 4 | **价格代码** | Rate Code | BAR/会员价/协议价/团队价/包价 |
| 5 | **用途** | Purpose | 商务/休闲/会议/医疗/婚宴 |

| 字段 | 英文 | 含义 | 颗粒度 | 例子 |
|------|------|------|--------|------|
| **市场码（Market Code）** | Market Code | 大的客源分类 | 粗（10-20 个）| OTA / TMC / 协议 / 会员 / 会议 / 政府 / 散客 |
| **市场明细码（Market Sub-Code）** | Market Sub-Code | 市场码下的细分 | 细（50-200 个）| 携程-OTA / 美团-OTA / 飞猪-OTA / 携程商旅-TMC / 同程商旅-TMC ... |

| 场景 | 只有市场码 | 有市场码 + 明细码 |
|------|----------|----------------|
| OTA 佣金分析 | 只能看"OTA 占 30%" | 能看"携程 20% / 美团 7% / 飞猪 3%" |
| TMC 合作效果 | 只能看"TMC 占 8%" | 能看"携程商旅 5% / 同程商旅 2% / 国旅运通 1%" |
| 协议客户管理 | 只能看"协议占 15%" | 能看"央企 8% / 省国企 5% / 政府部门 2%" |
| 收益管理决策 | 只能"一刀切" | 能针对性谈判（携程商旅 vs 国旅运通不同策略）|

#### 55.2.5.D 为什么必须在集团层面统一规范市场细分？

| # | 问题 | 具体表现 |
|---|------|---------|
| 1 | **市场码定义不统一** | 56 家酒店中，估计 40+ 家有自己的市场码体系，无法横向对比 |
| 2 | **明细码命名随意** | 同一渠道在不同酒店有不同名字（如"携程OTA" vs"携程网" vs"Ctrip-OTA"）|
| 3 | **数据无法汇总** | 集团想看"56 家酒店的 TMC 收入"，无法直接加总 |
| 4 | **集团收益分析失真** | 跨酒店分析需要手工"翻译"明细码，效率低且易错 |
| 5 | **价格体系混乱** | 同一企业客户在不同酒店不同价，无法做集团统一协议 |
| 6 | **AI 赋能无法开展** | AHL 客户雷达、TMC 对接等 AI 模块需要标准化市场码输入 |

| # | 原则 | 说明 |
|---|------|------|
| 1 | **国际兼容** | 遵循国际酒店行业通用市场码（OTA / TMC / CORP / GROUP / MEMBER 等）|
| 2 | **中文友好** | 同时有英文 + 中文名称（PMS 系统需要中英文兼容）|

## 第 13 节 · 项目全生命周期管理（自创方法论）

> 来源：B166ER 代笔（基于 PPT08 轻重分离 + PPT13 CRS 升级 + Eric 多年酒店咨询经验综合提炼）

### 一、核心定义
> **酒店项目全生命周期管理 = 从"市场调研 → 投资决策 → 设计建造 → 开业筹备 → 运营 → 改造 → 退出"的完整闭环管理**

### 二、8 大阶段

| # | 阶段 | 核心动作 | 主导部门 | 关键产出 |
|---|------|---------|---------|---------|
| 1 | 市场调研 | 选址/客群/竞品/定位 | 产发部+运营 | 可研报告 |
| 2 | 投资决策 | IRR/NPV/风险评估 | 董办+总办+财务 | 立项批复 |
| 3 | 融资落地 | 自有资金+银行授信+融资成本 | 财务+资产 | 融资方案 |
| 4 | 设计报建 | 方案设计+报建报审 | 工程+设计院 | 设计图纸+批复 |
| 5 | 工程建造 | 施工+造价+安全+廉政 | 工程+审计 | 验收报告 |
| 6 | 开业筹备 | 办证+人员+SOP+物资 | 运营+人力 | 开业方案 |
| 7 | 持续运营 | 收益管理+会员+OTA+服务 | 运营管理中心 | RevPAR/GOP 月报 |
| 8 | 改造升级 | 二次投资+品牌迭代 | 工程+运营+资产 | 改造方案+IRR |
| 9 | 退出处置 | REITs/转让/持续经营 | 资产+财务 | 处置方案 |

### 三、每个阶段的核心 KPI

| 阶段 | 关键 KPI |
|------|---------|
| 市场调研 | 客群画像准确度 / 竞品分析完整度 |
| 投资决策 | IRR ≥ 15% / NPV > 0 / 投资回收期 ≤ 8 年 |
| 融资落地 | 融资成本 ≤ 5% / 授信覆盖率 ≥ 80% |
| 设计报建 | 设计变更率 ≤ 15% / 报建一次通过 |
| 工程建造 | 单方造价可控 / 工程廉政零投诉 / 工期偏差 ≤ 10% |
| 开业筹备 | 首月 OCC ≥ 50% / 首年 GOP 率 ≥ 25% |
| 持续运营 | RevPAR 年增长 ≥ 5% / 会员复购率 ≥ 40% / OTA 佣金占比 ≤ 12% |
| 改造升级 | 改造投资回收期 ≤ 5 年 |
| 退出处置 | 资产溢价 ≥ 30% |

### 四、运营阶段的"6 把刀"⭐（Eric 多年实战总结）

| 维度 | 核心动作 | 安逸现状 | 目标 |
|------|---------|---------|------|
| **收益管理** | 动态定价+市场细分+渠道管理 | 一锅炖 | 5 维细分（地理/客源/消费/渠道/提前期）|
| **会员运营** | 入会门槛+积分体系+等级权益 | 160 万但活跃低 | 复购率 ≥ 40% |
| **OTA 控费** | 直销 + 协议 + 会员占比 ≥ 60% | 佣金占比 15-20% | 压到 ≤ 12% |
| **服务标准** | SOP + 神秘客 + 点评管理 | 各店不一 | 全集团统一 |
| **供应链** | 集采占比 ≥ 60% | 安逸购年销 4000 万 | 年销 ≥ 1 亿 |
| **成本控制** | 人房比 ≤ 0.5 + 能耗比 ≤ 8% | 人房比偏高 | 行业基准 |

## 第 14 节 · 酒店限制性功能产品本地社区化设计方法论（自创方法论）

> 来源：B166ER 代笔（基于 PPT01 §3.4 主题酒店 + PPT07 实战案例 + 行业研究综合提炼）

### 一、两个核心概念

> **限制性功能产品** = 只对特定客群开放 / + 限时 / + 限地 / + 限量 / + 限权 的差异化产品
> **本地社区化设计** = 把酒店从"过夜空间"变成"本地生活方式社区"——客人不只是来睡觉，是来"归属"

### 二、限制性功能产品的 5 个"限制"维度

| 维度 | 内涵 | 案例 | 价值 |
|------|------|------|------|
| **限客群** | 会员专属/等级专属/身份专属 | 亚朵 A 卡会员专属楼层 | 提升会员价值 |
| **限时间** | 周末/季节/节日限时供应 | 周末下午茶/圣诞主题餐 | 营造稀缺感 |
| **限地点** | 专属空间/景观位/包间 | 行政酒廊/总统套房/私汤 | 高端化 |
| **限量** | 限量供给/稀缺资源 | 主厨私宴/限量主题房 | 制造话题 |
| **限权** | 特权服务/优先权益 | 国宾礼仪/一对一管家 | 身份认同 |

### 三、本地社区化设计的 4 个核心要素

```
① 本地 IP（地域文化人格化）
   例：成都"熊猫茶馆"、上海"弄堂咖啡"、北京"四合院民宿"

② 体验（可参与的特色活动）
   例：酒店 + 茶道 / 酒店 + 川剧 / 酒店 + 健身 / 酒店 + 文化沙龙

③ 复购（会员 + 社群 + 私域）
   例：会员社群 / 主题活动 / 客户共创

④ 商业（多业态融合）
   例：酒店 + 餐饮 / 酒店 + 零售 / 酒店 + 演艺
```

### 四、5 阶段设计方法论 ⭐⭐⭐

#### 阶段 1：本地文化解构（Local Cultural Decomposition）
- 提取本地核心文化符号（三星堆/川剧/熊猫/茶文化/三国）
- 识别可融入酒店的 3-5 个文化元素
- 输出：《本地文化资源清单》

#### 阶段 2：限制性产品设计（Restricted Product Design）
- 在 5 个"限制"维度（限客群/限时间/限地点/限量/限权）中选 2-3 个
- 设计 5-10 个具体产品（套餐/活动/空间）
- 输出：《限制性产品矩阵》

#### 阶段 3：社区化场景构建（Community Scenario Building）
- 设计 3-5 个核心场景（迎宾/餐饮/住宿/活动/离店）
- 每个场景融入 1-2 个本地文化元素
- 输出：《社区化场景脚本》

#### 阶段 4：会员运营体系（Membership Operation）
- 设计会员等级（银/金/铂金）
- 设计积分体系（消费积分+推荐积分+活动积分）
- 设计专属权益（房型升级/专属空间/主题活动）
- 输出：《会员运营手册》

#### 阶段 5：传播与裂变（Spread & Viral）
- 设计 KOL/KOC 合作矩阵
- 设计新媒体内容矩阵（短视频/图文/直播）
- 设计老带新裂变机制
- 输出：《传播运营手册》

### 九、方法论的 3 个铁律

> **铁律 1：本地文化不是装饰品，是产品本身**——三星堆不只是大堂艺术品，是"考古体验课程"的 IP 支撑
>
> **铁律 2：限制性不是限制客户，是创造稀缺感**——总统套房参观限客群反而提升神秘感
>
> **铁律 3：社区化不是装修升级，是运营模式升级**——核心是从"卖房间"到"卖生活方式"的思维转变
