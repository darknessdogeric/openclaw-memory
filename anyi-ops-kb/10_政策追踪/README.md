# 政策追踪体系 v1.1 · 赋能型架构

> **核心升级**:从"申报主体"思维 → "赋能主体"思维
> **战略意义**:这是 AHL 政策 Agent 模块的**MVP 雏形**

---

## 一、关键边界(必读)

| 角色 | 职责 | 不做的事 |
|------|------|----------|
| **产业发展部(我们)** | 线索搜集 + 信息整理 + 条件匹配 + 申报 SOP 输出 | **不替代三级公司申报** |
| **三级公司(各酒店)** | 申报主体 + 属地化执行 + 材料准备 + 关系落地 | 不需要事事请示集团 |
| **集团总部(战略/财务/法务)** | 统筹协调 + 跨部门协同 + 重大事项决策 | 不替代三级公司执行 |

---

## 二、产业发展部在政策申报中的**3 个赋能动作**

### 2.1 情报赋能

**做什么**:把"集团外部"的政策红利,翻译成"集团内部"能用的话

- L1-L5 站点 7×24 自动抓取(45 站点)
- 每周输出"政策简报"(分级推送)
- 重大政策 1h 内预警

**不做什么**:不替三级公司去"打听"(那是一线关系网)

### 2.2 画像赋能

**做什么**:维护 56 家酒店的"申报画像"

- 业态 / 规模 / 地域 / 资质 / 历史申报记录
- 集团统一维护,各三级公司可订阅 / 更新

**不做什么**:不替三级公司准备具体材料

### 2.3 匹配赋能

**做什么**:政策 × 酒店画像的智能匹配

- 输入:某项新政策 + 56 家酒店画像
- 输出:可申报的酒店清单 + 匹配度评分 + 申报 SOP

**不做什么**:不强制三级公司申报(决策权在他们)

## 三、AHL 政策 Agent 模块 v0.1(战略级)

> **这就是 Eric 说的"AHL 能干的事情"**

### 3.1 模块定位

AHL 平台上的**"政策 Agent"**——为集团内外酒店提供"政策-酒店-匹配"智能服务。

### 3.2 模块架构(MVP 雏形)

```
输入层:
  ├─ 政策池(国家/省/市/区/园区 5 层)
  ├─ 酒店画像(业态/规模/地域/资质)
  └─ 申报历史(成功/失败/未申报)

匹配引擎:
  ├─ 资格匹配(业态/规模/资质)
  ├─ 时间窗口匹配(申报期/截止)
  ├─ 资金预估(金额预期/集团分配)
  └─ 申报 SOP(模板/材料/流程)

输出层:
  ├─ 政策简报(每周推送)
  ├─ 匹配清单(每政策 × 每酒店)
  ├─ 申报 SOP(模板化)
  └─ 复盘报告(申报结果跟踪)
```

### 3.3 集团内 MVP 路径

**第一阶段(2026 H2)**:集团内 56 家酒店
- 政策追踪 v1.1 = 集团内部版 AHL 政策 Agent
- 验证可行性 + 收集数据 + 迭代算法

**第二阶段(2027)**:集团外(锦江/首旅/华住等同业)
- 把"政策 Agent"作为 AHL 平台的核心服务之一
- 收费模式:订阅制 / 按申报成功率分成 / 政策落地咨询服务

### 3.4 战略价值

- 🟢 **可量化**:每个酒店集团可申报的金额 × 申报成功率 = 实际收益
- 🟢 **可复制**:标准化产品,边际成本接近 0
- 🟢 **可防御**:政策数据库 + 酒店画像库,数据壁垒
- 🟢 **可扩张**:从"政策"延伸到"补贴 + 招商 + 产业基金 + REITs"等所有"钱"的匹配

## 四、三级公司赋能 SOP(从"信号"到"申报")

```
[信号捕获]
  集团产业发展部:7×24 雷达抓取
   ↓
[一级筛选 · 集团]
  集团产业发展部:金额 + 截止 + 资格匹配
   ↓
[政策简报推送]
  集团产业发展部:每周一推送至 56 家三级公司
   ↓
[二级筛选 · 三级公司]
  三级公司:根据本酒店情况决定是否申报
   ↓
[申报 SOP 支持]
  集团产业发展部:提供模板 + 流程 + 关键节点提醒
   ↓
[属地化执行]
  三级公司:对接当地文旅局 / 财政局 / 提交材料
   ↓
[资金到账 + 复盘]
  三级公司:反馈资金到账情况
  集团产业发展部:记录到"申报画像" + 更新匹配算法
```

**关键原则**:集团赋能 ≠ 集团代办。决策权在三级公司,执行权在三级公司。
