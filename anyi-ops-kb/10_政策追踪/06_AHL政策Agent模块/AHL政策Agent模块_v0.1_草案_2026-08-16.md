# AHL 政策 Agent 模块 v0.1 草案

> **战略定位**:AHL 平台"产业 Agent"赛道的**第一个落地场景**
> **核心价值**:把"政策红利"翻译成"酒店可申报的清单"
> **MVP 路径**:集团内 56 家酒店 → 集团外(锦江/首旅等同业)

---

## 一、为什么是"政策 Agent"

### 1.1 行业痛点(集团外)

```
酒店集团(尤其是中小连锁)每年损失 ¥100-500 万 / 集团
  ├─ 不知道有哪些政策(信息差)
  ├─ 不知道是否符合资格(认知差)
  ├─ 没有精力申报(执行力差)
  └─ 没有专业人才(能力差)

痛点本质 = "信息-认知-执行"三道鸿沟
```

### 1.2 行业机会(政策红利)

```
2025 年中国文化产业总规模 ≈ 16 万亿(国家统计局)
  ├─ 中央财政文旅专项资金 ≈ 100 亿+/年
  ├─ 省级财政文旅专项资金 ≈ 50 亿+/年
  ├─ 市级财政文旅专项资金 ≈ 30 亿+/年
  └─ 区县级 + 园区 ≈ 20 亿+/年

→ 总盘子 200 亿+/年,符合资格的酒店 5-10 万家
→ 平均每家酒店每年可申报 5-15 项
→ 平均每项金额 5-500 万
→ 单店年潜在申报金额 100-1000 万
```

### 1.3 AHL 的优势(为什么能做)

| AHL 能力 | 对应痛点 | 优势 |
|----------|----------|------|
| 政策雷达(L1-L5) | 信息差 | ✅ 已就位(v1.1) |
| 酒店画像库 | 认知差 | ✅ 集团内 56 家可验证 |
| 智能匹配引擎 | 执行力差 | 🟡 待开发 |
| 申报 SOP 库 | 能力差 | 🟡 边做边建 |
| 集团内验证场景 | MVP | ✅ 现成 |

## 五、技术栈选型(初步)

### 5.1 MVP 阶段(0-6 个月)

```
- 数据采集:TrendRadar + Tavily + Web Fetch + RSS
- 数据存储:本地 JSON / SQLite(轻量)
- 匹配引擎:LLM + 规则引擎(简单规则 + LLM 兜底)
- 用户界面:命令行 + MD 输出(渐进到 Web)
- 部署:本地工作站 + 定时任务
```

### 5.2 产品化阶段(6-12 个月)

```
- 数据采集:同 MVP + 微信公众号 / 邮件订阅
- 数据存储:PostgreSQL + 向量数据库(ChromaDB)
- 匹配引擎:向量相似度 + 规则引擎 + LLM 推理
- 用户界面:Web 端(React) + 移动端(WeChat 小程序)
- 部署:云服务器 + 自动化运维
```

### 5.3 商业化阶段(12-18 个月)

```
- 数据采集:全渠道 + API 接入 + 人工订阅
- 数据存储:PostgreSQL + Redis + 向量数据库 + 图数据库
- 匹配引擎:知识图谱 + LLM Agent + 推荐算法
- 用户界面:全端覆盖 + 个性化推荐
- 部署:云原生 + SaaS 架构 + 多租户
```
