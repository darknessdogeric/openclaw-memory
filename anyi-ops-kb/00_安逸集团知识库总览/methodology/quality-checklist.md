## 7 项必查清单

### ✅ 1. 34 维度信源覆盖率 ≥70%

```bash
python scripts/audit_34_dimensions.py --report reports/<file>.pdf
```

**标准**：
- 🥇 ≥80% 优秀
- 🥈 70-80% 合格（可标注缺失后发布）
- 🥉 60-70% 待补（必须补救）
- 🔴 <60% 不达标（拒绝发布）

**实测**（弥勒 v4）：
- 覆盖率 80%（27/34）—— ✅ 达标

---

### ✅ 2. 10 章宏观全景 + 5 维可行性完整

```bash
# 自动校验
python scripts/check_schema.py --pdf reports/<file>.pdf
```

**必查项**：
- [ ] 第 1 章 行业总览（4 数据点 + 1 警示）
- [ ] 第 2 章 宏观环境（PEST）
- [ ] 第 3 章 行业供给（全国 + 区域 + 民宿）
- [ ] 第 4 章 行业需求（消费端 + 旅居 + 民宿）
- [ ] 第 5 章 运营表现（OCC/ADR/RevPAR）
- [ ] 第 6 章 竞争格局（外资 + 内资 + 标杆）
- [ ] 第 7 章 营销渠道
- [ ] 第 8 章 AI+PMS
- [ ] 第 9 章 资本市场
- [ ] 第 10 章 政策（办证 + 土地 + 担保）
- [ ] 第 11 章 5 维可行性（市场/政策/财务/运营/退出）

**实测**：弥勒 v4 11 章完整 —— ✅ 达标

---

### ✅ 3. OCC/ADR/RevPAR 推算有 Eric ADR 估算方法支撑

```bash
python scripts/validate_adr.py --data reports/<file>_raw_data.json
```

**必查项**：
- [ ] ADR 来源明确（OTA 抓取/EBK 数据/财报基线）
- [ ] 去掉无窗房、促销价、套房、特殊房型
- [ ] 保留主力标准房型
- [ ] 公式说明（×0.5 + ×0.5 加权 或 ×0.865 反推）
- [ ] OCC 来源说明（节假日售罄 + 行业基准反推）
- [ ] RevPAR = ADR × OCC

**实测**：弥勒 v4 ✅ 通过（基于 v2 Eric ADR 估算方法）

## 7 项检查的反向校验（防漏）

| 易漏点 | 自检动作 |
|--------|---------|
| ❌ 只做地区级不做单店级（v3 教训） | 每个报告必须同时是"地区级"+"项目级" |
| ❌ OCC/ADR 用宏观数据而不分档次 | 必须按 STR 档次看 |
| ❌ 政策只提不全 | 至少 3 个层级（国家/省/州） |
| ❌ 财务模型只有一种场景 | 必须保守/中性/乐观 3 档 + 3 修正路径 |
| ❌ 客群分析空泛 | 至少 5 类细分客群 + 占比 + 价值密度 |
| ❌ 退出方案不说 | 必须给"5 年退出预案" |
| ❌ 没图表或图表不行 | ≥6 张 ≥ 标准模板 |

## 失败模式与纠正

### 模式 1：覆盖率不达标
**应对**：立即补搜缺失信源，再次审计

### 模式 2：章节缺失
**应对**：按 schema.md 补足缺失章节

### 模式 3：财务模型单一
**应对**：增加 3 档场景 + 修正路径

### 模式 4：图表缺失或质量差
**应对**：用 templates/ 标准图表生成

### 模式 5：政策不全
**应对**：3 层级梳理 + 创业担保贷款等地方政策

### 模式 6：客群空泛
**应对**：5 类细分客群 + 占比 + 价值密度

### 模式 7：退出缺失
**应对**：5 年退出预案 + 3 条路径
