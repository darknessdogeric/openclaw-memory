## 0. 一句话结论

> ⭐⭐ **找到了，而且不是"一张表"，是一套已经跑了三个项目的测算体系** —— 通用模版 Excel（11 表）+ 测算引擎 `hotel_irr_calc.py`（557 行 / 5 个预置案例）+ 三轮校订记录。
> ⭐⭐⭐ **本次优化的最大收获不是"算得更细"，而是纠正了一个口径级错误**：总府这类**存量资产改造**，必须用**增量口径**（改造后现金流 − 改造前现金流），而不是全口径。用全口径会把存量资产的亏损算进分子，从而得出"回收期 20–86 年、IRR 不成立"的错误结论。**修正后：改造前经营现金流为负（年均 −1,424 万），改造后转正（方向二中性 +1,235 万），但增量 NPV 仍为负 → 决策依据必须走国资口径的"评估增值率 + 资产证券化通道"，而非 IRR。**

## 2. 针对总府的 6 处优化（引擎层）

> 实施方式：**新建 `hotel_irr_calc_zongfu.py`，import 原引擎的 RAMP_CURVES / calc_irr / calc_static_payback / calc_dynamic_payback / assess_verdict / write_excel_report，不改动原引擎** —— 保证原引擎 5 个 preset 结果一字可复现。

| # | 新增维度 | 为什么总府必须有 | 取值 |
|---|---|---|---|
| **1** | ⭐ **`mgmt_fee_rate` 管理费/抽佣可调** | ⭐⭐ 原引擎**硬编码** `incentive_mgmt = gop × 6%`。而**抽佣结构正是方向二的核心价值主张**（现行委托 8%–14% → 洲至奢选 5.3%–7.3%，十年省 1,100–3,400 万）。若不建模，**测算会把方向二最核心的优势抹平** | 方向一 11%｜方向二 6.3%｜方向三 9% |
| **2** | ⭐ **`gop_rate_gross` GOP 率拆"管理费前"** | 原引擎只有综合 GOP 率（已含管理费），三方向的 GOP 差异与抽佣差异无法分离 | 方向一 22–24%｜方向二 31–36%｜方向三 33–38% |
| **3** | ⭐ **`closure_months` + `closure_loss_monthly`** | ⭐⭐ 隐蔽工程整改必然停业（815 万/月）。**原引擎完全没有停业期损失维度** —— 这是总府最大的单一成本项，不建模等于把总府算成一个"普通改造" | 11–23 月 × 815 万 |
| **4** | ⭐ **`debt_service_annual` 经营期贷款利息** | ⭐⭐ 存量贷款利息 1,785 万/年。原引擎只有 `rent_annual`（租金语义），总府自有物业无租金，**必须新增独立维度**；且改造后新增融资利息更大（待定） | 1,785 万/年（改造前存量，改造后新增融资待定） |
| **5** | ⭐ **`building_value_existing` + `building_depreciation_years`** | ⭐⭐⭐ 原引擎 `building_value` 默认 = **总投 × 60%**、折旧 = **building_value / 10**。对**存量物业改造**这是错的：总府存量房产评估值（21,949 万）与改造投资（1.5–4.4 亿）**是两个完全不同的量**，且折旧年限（30 年经济寿命 vs 10 年会计口径）也不同。**房产税与折旧都必须按存量房产原值计** | 21,949 万（⚠️ 参照值）/ 折旧 10 年 |
| **6** | ⭐ **`ramp_type='renovation'` + `'flat'`** | ⭐⭐ 原引擎 5 条爬坡曲线全是**新店爬坡**。改造项目的爬坡期**已在停业期消耗**（停业 11–23 月），开业即近成熟；基线（在营酒店）更不应有新店爬坡 | renovation: Y1 0.95/0.90 → Y2 成熟；flat: 全 1.0（基线用） |

### 2.1 ⭐⭐⭐ 第 7 处优化（最重要）：**增量口径（基线对比）**

**这不是"加一个参数"，而是换一种决策口径。**

| | 全口径（错误） | ⭐ 增量口径（正确） |
|---|---|---|
| 分子 | 改造后现金流 | **改造后现金流 − 改造前现金流** |
| 分母 | 改造投资 | 改造投资（不变） |
| 含义 | "这笔投资本身赚不赚钱" | "**这笔改造比不改强多少**" |
| 总府的坑 | ⭐⭐ **改造前经营现金流本身为负（年均 −1,424 万）**，全口径会把存量资产的亏损算进分子 → 分母不变、分子被存量亏损压低 → **得出"回收期 20–86 年、IRR 不成立"的错误结论** | 分离存量与增量，答案完全不同 |

**实现**：引擎新增 `baseline` 参数 → 先算改造前基线（同一资产口径：同样的存量折旧/房产税/利息），再逐项相减。

### 3.3 ⚠️⭐⭐⭐ 但"改造前亏 1,424 万"这个数字**不能当核心论据**（关键敏感性）

**存量房产评估值 × 存量贷款利息** 双变量敏感性（方向二中性）：

| 存量房产评估值 ＼ 存量贷款利息 | 1,000 万/年 | 1,785 万/年（实测） | 2,600 万/年 |
|---|---|---|---|
| **15,000 万** | −579 / **+2,081** / +2,659 / −28,591 | −1,364 / **+1,296** / +2,659 / −28,591 | −2,179 / **+481** / +2,659 / −28,591 |
| **21,949 万**（参照值） | −640 / **+2,020** / +2,659 / −28,591 | −1,424 / **+1,235** / +2,659 / −28,591 | −2,240 / **+420** / +2,659 / −28,591 |
| **30,000 万** | −710 / **+1,949** / +2,659 / −28,591 | −1,495 / **+1,164** / +2,659 / −28,591 | −2,310 / **+349** / +2,659 / −28,591 |

> 单元格式：**改造前年均CF / 改造后年均CF / 年均增量 / 增量NPV@8% / 增量回收期**

> ⭐⭐⭐ **三条必须写进方案的纪律**：
> 1. **"改造前亏多少"高度依赖两个尚未确定的变量**（评估值 1.5–3.0 亿 → 亏 579–2,310 万）。**在正式评估报告出具前，不能把它当核心论据。**
> 2. ⭐ **但"改造后能不能转正"是稳健的**：9 格全部为正（+349 ~ +2,081 万）。→ **"改造后现金流由负转正"可以作为论据，"改造前亏了多少"不能。**
> 3. ⭐⭐ **增量 NPV 恒为 −28,591 万，对这两个变量完全不敏感**（因为评估值与利息在改造前后同步变动、互相抵消）→ ⭐ **增量决策只取决于 ADR / OCC / GOP 率 / 投资额 / 停业月数这五个可控量**，其中**停业月数是唯一能单方面压缩的**（每省 1 月 = 815 万）。

## 6. 与国资口径的衔接（⭐ 这才是最终上会口径）

| 测算结果 | 国资口径下的读法 |
|---|---|
| 增量 NPV 全负 | → 走**口径切换**：不用 IRR/NPV，用**评估增值率**（华安锦江 21 个酒店资产均值 68.26%，可为负仍有先例） |
| 改造后现金流由负转正 | → 支撑**"不改造的代价"**（第 2 段论证），但**幅度不能引用**，因为它依赖待评估变量 |
| 停业月数是唯一单方面可压缩量 | → 每省 1 月 = 815 万，**且直接进增量 NPV**（方向二 18→16 月 = +1,630 万 NPV） |
| 方向二抽佣 12.3% vs 方向一 17% | → 十年抽佣差直接进现金流，是方向二的第二大价值来源（第一是 ADR） |

⭐⭐ **最终上会的一句话**：
> **纯财务口径（IRR/NPV）三个方向都不成立；但改造能把经营现金流从负转正、并保住经营权与资产证券化资格。决策依据是「评估增值率 + 资产证券化通道 + 不改造的代价 + 两期立项」，不是 IRR。**
