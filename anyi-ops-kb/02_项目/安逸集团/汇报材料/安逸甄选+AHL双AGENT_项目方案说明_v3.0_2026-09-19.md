# 第一章 这是什么——AHL 不是 SaaS，是范式革命者

## 1.1 一句话定位

**AHL 是四川省国资文旅行业首个 AI 垂系 Agent 平台。**

它做的事情只有一件：**让客人用 AI 直接找到对的商家，让商家用 AI 直接找到对的客人**——中间不抽水，不抽佣，不囤数据。

## 1.2 它解决什么问题

客人今天找酒店、找景区、找特产、找餐厅的路径：

```
现状：
  客人 → 打开 OTA 平台 → 搜索 → 比价 → 看评价 → 选 → 下单 → 钱到平台 → 平台抽 10-15% → 剩 85-90% 到商家

AHL 模式：
  客人 → 对 AI 说出需求 → AI 直接匹配 → 客人下单 → 钱 100% 到商家 → 平台收 TOKEN 计量费（≈电费）
```

**0% 佣金**。客人付的钱 100% 到商家。平台只收一笔按"握手次数"算的"电表费"。

## 1.3 为什么是"现在"

```
1990s    Web 1.0  信息找人    存活 15 年
2000s    Web 2.0  人找信息    存活 10 年
2010s    移动互联网  中心化入口  存活 5 年
2020s+   AI 时代    Agent 协议  正在压缩
```

**核心判断**：2024 年 LLM 元年之后，住宿业 + 文旅业的"AI 范式革命"窗口期约 **5-7 年（2025-2031）**。错过这一窗口，2028 年后被市场淘汰的概率大幅提升。

**这不是"做不做"的问题，而是"早做还是晚做"的问题。**

**Guest Agent 对客，Host Agent 对店。**两侧共用一个大模型，沉淀数据与价值循环。

## 2.2 C 矩阵与 B 矩阵——全业态接入

**C 矩阵（客人端）**：5 类客群 × N 个体

```
① 商务客     出差型     效率优先     协议价敏感
② 背包客     性价比     攻略驱动     社媒分享
③ 亲子客     需求多元   安全与体验并重
④ 入境客     语言/支付  跨文化适配
⑤ 宠物客     特殊需求   传统货架最难服务的人群
```

**B 矩阵（商家端）**：8 类商家 + N 持续接入

```
一张协议 · 全业态接入
├─ 酒店 · 民宿
├─ 餐饮 · 门店
├─ 零售 · 特产          ← 安逸甄选在这里
├─ 景区 · 营地
├─ 娱乐 · 演艺
├─ 交通 · 自驾
├─ 旅行社
├─ 本地生活
└─ + N（持续接入）
    ├─ 物流 · 教育
    ├─ 政务 · 商业地产
    └─ 任何 Agent 握手场景都适用
```

**关键洞察**：B 矩阵**不只服务于酒店**——而是面向**整个吃住行游购娱**的所有实体。这是 AHL 不同于其他酒店 AI 工具的核心。

## 2.3 TOKEN 经济——类比电表电网

```
TOKEN 就是 Agent 经济的「电费」
AHL 是那块标准化电表

类比电费：
  电网不靠卖电赚差价，只按度计量
  TOKEN 不靠抽佣赚差价，只按握手次数计量

每次握手（C Agent 与 B Agent 对话）消耗 TOKEN
所有 TOKEN 经 AHL 协议层标准化记账流转
```

**四类 TOKEN**：
- **基础 TOKEN**（年订阅）= 稳定底盘
- **调用 TOKEN**（按次按效果）= 杠杆层
- **增值 TOKEN**（数据/算法订阅）= 高毛利层
- **流通 TOKEN**（跨主体结算）= 网络效应放大器

## 5.2 五大应用场景

客人离店后，Host Agent 自动推送专属优惠、新品上市、活动邀请——**复购率从 15-20% 提升到 40%+**。

## 6.3 0% 佣金——为什么这是真正的护城河

```
OTA 平台：
  客人付 1000 元 → 平台抽 100-150 元 → 商家拿到 850-900 元
  客户归属平台，数据归属平台，定价权归平台

AHL 平台：
  客人付 1000 元 → 商家拿 1000 元 → 平台收 TOKEN 计量费（远小于 100 元）
  客户归属商家，数据归属商家，定价权归商家
```

**对商家**：每笔交易多收 100-150 元，一年下来差距巨大。
**对客人**：没有平台抽水压低服务质量。
**对 AHL**：靠规模效应和增值服务赚钱，不靠抽水赚钱。

| 🟡 不主动提"安逸集团"营销 | 公开宣传弱化安逸身份 | 试点用"垂系 Agent 行业研究"等中性词 |
| 🟢 数据与关联交易合规 | 严格按《数据安全法》《个人信息保护法》| 集团法务部介入 |

## 7.2 试点选址原则

**硬门槛**：
- 在营且未纳入改造
- 集团直营 / 控股
- 数字化基础成熟

**规避风险**：
- 不选安逸连锁已闭店（6 家门店 6/30 闭店）
- 不纳入古尔沟项目（资不抵债 181.74%）
- 立项同步做合规自查

## 7.3 三重一大合规路径

```
第一步（重大投资决策）：安逸集团董事会 → 安逸酒店集团发文
第二步（跨集团）：旅投集团董事会 → 四川省旅游投资集团发文
```

每一步独立立项、独立汇报、独立决策——避免「越级汇报」或「上级越权」风险。

# 第十章 它与传统方案比怎么样——五维对比

| 维度 | 传统 SaaS（如携程通、订单来）| AHL |

| **数据归属** | 平台沉淀 | 数据归属酒店 + AHL 双回流 |
| **跨店协同** | 无 | 客源互导 + 数据共池 + 价格杠杆 |

**核心区别**：AHL 不是"又一家 OTA"，而是把"客户 · 数据 · 收益"全部交还给酒店的 AI 运营底座。
