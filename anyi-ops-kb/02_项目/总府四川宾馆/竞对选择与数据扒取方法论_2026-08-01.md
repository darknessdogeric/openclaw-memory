## 一、顶层逻辑 — 定位 → 竞对 → 数据 三步走

```
[Step 1: 项目定位]  → 决定"我和谁比"
```

## 三、数据扒取方法论 — 5 类来源 + 工具矩阵

### 3.1 5 类核心数据

| # | 数据类型 | 用途 | 主要来源 |
|---|---------|------|---------|
| 1 | **价格数据** (ADR / RevPAR) | 定价对标 | OTA（携程/Booking/Agoda）+ 官网 |
| 2 | **入住率** (Occ) | 需求对标 | STR（付费）+ OTA 实时查询 + 财报 |
| 3 | **客户评价** (评分 + 评论) | 服务/产品对标 | 携程/美团/飞猪/TripAdvisor 评论爬取 + NLP |
| 4 | **配套 + 房型** | 产品对标 | 官网 + 实地 + 携程详情页 |
| 5 | **经营数据** (GOP/EBITDA/收入) | 财务对标 | 上市公司财报 + 行业报告 + 第三方研究 |

### 3.2 工具矩阵（B166ER 现成能力）

| 数据类型 | 推荐工具 | 备用工具 | 注意事项 |
|---------|---------|---------|---------|
| **静态页面** | scrapling (scrap_tools.py) | Tavily | 政府/百科/新闻/财报披露 |
| **OTA 实时价格** | Obscura + Playwright | scrapling | 注意反爬、IP 代理 |
| **跨境 OTA (Booking/Agoda)** | InvisiblePlaywright | Skyvern Vision LLM | Firefox 引擎差异化 |
| **酒店官网房型/套餐** | Playwright | Obscura | 会员体系需要登录态 |
| **评论 NLP 分析** | 本地 LLM + 评论批量爬取 | — | 携程评论 10-30k/家 |
| **上市公司财报** | Tavily 搜索 + web_fetch | scrapling | 同花雪球/巨潮 |
| **STR 数据** | (付费 API) | 替代：用 OTA 实时 + 历史 | STR 一年约 ¥10-20 万 |
| **POI + 评分** | 高德地图 API | 百度地图 API | 替代：scrapling 抓大众点评 |
| **视觉理解 (房型/大堂)** | Skyvern Vision LLM | image 工具 | 适合截图解析 |

### 3.3 扒取执行顺序（4 周时间表）

#### Week 1: 基础数据盘点
- Day 1-2: **静态数据** — 14 家候选酒店的工商信息、开业时间、房间数、星级、品牌
  - 工具：scrapling + Tavily
  - 输出：`competitors_basic.json` (14 × 10 字段)
- Day 3-4: **地理位置** — POI 坐标、距总府川宾直线/驾车距离
  - 工具：高德地图 API
  - 输出：`competitors_geo.json` (14 × 5 字段)
- Day 5: **客源类型识别** — 各酒店主打客群（商务/会议/政务/亲子）
  - 工具：官网 + 携程酒店详情 + 评论 NLP
  - 输出：`competitors_segment.json` (14 × 8 字段)

#### Week 2: 价格 + 入住率深度扒取
- Day 6-8: **OTA 价格扒取** — 14 家 × 3 OTA × 30 天 = 1,260 个价格点
  - 工具：Obscura (国内) + InvisiblePlaywright (Booking)
  - 输出：`competitors_pricing.csv` (14 × 90 字段)
- Day 9-10: **入住率估算** — 通过 OTA "房间紧张度" + 评论密度 + 财报披露
  - 工具：Playwright + 评论爬取
  - 输出：`competitors_occupancy.json` (14 × 4 字段)

#### Week 3: 客户评价 + 产品对标
- Day 11-13: **评论爬取 + NLP 分析** — 14 家 × 5,000 条 = 70,000 条评论
  - 工具：scrapling + 本地 LLM
  - 输出：`competitors_reviews.csv` + `competitors_nlp.json` (评论分类 + 情感 + 痛点)
- Day 14-15: **配套 + 房型** — 14 家房型详情、餐饮、会议、SPA、健身房
  - 工具：Playwright + 截图
  - 输出：`competitors_product.json` (14 × 20 字段)

#### Week 4: 经营数据 + 综合分析
- Day 16-17: **财报 + 行业报告** — 上市公司对标项目数据 + 行业基准
  - 工具：Tavily + web_fetch
  - 输出：`industry_benchmarks.json` (10 个关键指标)
- Day 18-19: **综合对标** — 14 家 × 5 维评分 = 70 个评分点
  - 输出：`competitive_positioning_matrix.png` (定位矩阵)
- Day 20: **报告输出** — 竞品画像表 + 价格指数曲线 + 客源雷达图

### 3.4 关键 KPI 计算公式

**RevPAR = ADR × Occ**（最核心指标）

**RGI (Revenue Generation Index)** = 本酒店 RevPAR / 竞争集平均 RevPAR × 100
- RGI = 100：与竞争集持平
- RGI > 100：优于市场
- RGI < 100：低于市场

**MPI (Market Penetration Index)** = 本酒店 Occ / 竞争集平均 Occ × 100
- 类似 RGI 但只衡量入住率

**ARI (Average Rate Index)** = 本酒店 ADR / 竞争集平均 ADR × 100
- 类似 RGI 但只衡量房价

**CR (Contribution Ratio)** = 本酒店某渠道订单占比
- 用于分析 OTA 依赖度

## 七、风险与合规

### 7.1 数据扒取的合规边界

| 风险点 | 应对 |
|--------|------|
| **OTA 反爬** | 控制频率（≤1 次/小时/酒店）；用 Obscura 浏览器隔离；遵守 robots.txt |
| **IP 被封** | 准备 3-5 个 IP 代理；用 scrapling 内置 retry |
| **数据准确性** | 三源交叉验证（OTA + 官网 + 实地）；标注数据时点 |
| **个人信息** | 评论 NLP 不存储 PII；只分析聚合特征 |
| **商业敏感** | 财报数据按上市公司披露范围；非公开数据不引用 |

### 7.2 红绿灯清单

- 🟢 可扒取：公开 OTA 价格、公开评论、公开财报、公开行业报告
- 🟡 谨慎：评论 PII（脱敏后用）、竞品内部运营数据（不引用）
- 🔴 禁止：付费 STR 数据（除非有合法授权）、付费行业报告（除非已购）
