关于在安逸集团试点应用 AHL 垂系 Agent 平台的工作计划

报送：安逸酒店集团 总经理办公会 报送单位：安逸酒店集团 产业发展部 拟稿人：张实（产业发展部部长） 拟稿时间：2026 年 8 月 1 日 密级：内部

一、计划背景与战略意义

（一）集团当前面临的核心挑战

集团"十五五"高质量发展规划已对集团面临的突出短板作出明确诊断，集中体现为"三个不匹配"：

一是资产与战略需求不匹配。 集团资产总额 35.51 亿元，但 2025 年净亏 6,843 万元，闲置面积近 50%；167 家酒店分散在多个城市，单店平均客房数不足 100 间，规模偏小且资产利用效率不高；6 大酒店改造周期长（每个 2-3 年），改造期间收入中断。

二是产品与资产价值不匹配。 集团旗下酒店 RevPAR（每间可售房收入）比同地段竞品低 30% 以上；硬件设施老化、文化主题缺失；客户体验与服务标准化不到位，携程评分多在 4.5-4.6，落后于头部品牌 4.8 以上水平。

三是机制与市场竞争不匹配。 集团运营机制相对传统，效率与市场化程度低于头部民营酒店集团；决策链条长，激励不活；数字化运营能力薄弱，集团总部对单店"看得见但管不着"；"安逸汇"会员体系起步晚，私域流量薄弱。

（二）集团"十五五"1234 战略与本计划的对接

集团"十五五"规划明确"1234"发展战略，本计划直接服务于第四步"全方位市场化"——而"全方位市场化"必须以体系化数字化能力为底座。

（三）本计划的核心使命

本计划旨在通过集团内部发起的方式，从零启动 AHL 垂系 Agent 平台在安逸集团内的试点应用，不依赖任何外部已有落地案例（前期接触均未实质性推进），完全依托集团自有资源与技术合作，探索一条符合安逸集团实际的数字化转型路径。

二、AHL 整体构想与架构

（一）AHL 是什么

AHL（AI Hospitality Layer）是专为酒店行业打造的人工智能智能底座 + 数字员工矩阵，依托大模型与垂系 Agent 编排技术，为酒店提供 7×24 小时不知疲倦的 AI 运营团队。

AHL 的核心定位：酒店 AI 技术底座服务商（不是再造 OTA，不是做酒店管理公司，而是为酒店提供"AI 运营底座"）。

AHL 与传统解决方案的本质区别：

比较维度 OTA 平台（携程/美团/飞猪） 酒店管理公司（华住/亚朵） 自建 APP/小程序 AHL
客户关系归属 归属平台 相对独立但深度有限 归属酒店但活跃度低 归属酒店
核心能力 流量分发 标准化管理输出 预订入口 AI 运营底座
费用模式 佣金 10-15% 加盟费 + 管理分成 开发成本数千万 按效果付费
数据流向 单向流向平台 数据回流有限 数据孤岛 双向数据喂养
跨店协同 平台内强，跨平台弱 同集团内协同 无 跨店、跨业态

（二）AHL 的核心护城河：数据喂养网络效应

AHL 真正的护城河不是技术、不是大模型，而是"数据喂养的网络效应"——这是一个经济学概念：

正反馈循环：
1. 一家酒店使用 AHL Agent
2. Agent 触达客户 → 客户行为数据反馈
3. Agent 基于数据优化 → 触达更精准
4. 触达成本下降 → 客户体验提升
5. 更多酒店加入 AHL
6. 更多数据喂养 → Agent 进一步优化
→ 回到第 2 步（良性循环）

关键含义：谁能先形成这个正反馈循环，谁就赢。集团 167 家酒店的规模优势是构建这个网络效应的天然基础。

（三）AHL 的演进路径（4 阶段）

阶段一 [0-12 个月]   AI 底座建设 → 大模型微调 + Agent 矩阵搭建 + 单店验证
阶段二 [12-24 个月]  行业数据飞轮 → 数据壁垒形成 → 1000 万+ 住客画像
阶段三 [24-36 个月]  具身智能集成 → 前台 + 客房 + 餐饮机器人 → 50%+ 场景覆盖
阶段四 [36 个月+]   生态平台扩展 → 开放 API 生态 → 行业标准制定

（四）AHL 的技术架构

AHL 技术架构分为五层，自下而上构建完整能力体系：

第一层：大模型基座。 基于 DeepSeek 等开源大模型作为基座，通过行业数据集进行深度微调，确保模型理解酒店行业专业术语与实操规范。模型精度目标 >85%，推理延迟 <500ms。

第二层：行业数据集。 覆盖万豪、希尔顿、华住、亚朵等 8 大酒店品牌 PP（行业惯例做法）与 SOP（标准操作流程）体系，沉淀 100 万+ 知识实体条目、500 万+ 关系边。这是 AHL 区别于通用大模型的核心壁垒。

第三层：Agent 编排层。 构建 9 大 Agent 集群（覆盖收益管理、OTA 维护、私域运营、C 端客服、B 端助手等场景），挂载 51 个 SKILL（业务技能单元），实现智能化任务的自动调度与协同。

第四层：数据集成层。 通过 API 接口与酒店 PMS（酒店管理系统）、CRS（中央预订系统）、OTA 平台、IoT（物联网）设备等数据源实现实时数据对接，统一数据中台，数据延迟 <1 分钟。

第五层：业务应用层。 在上述四层基础上构建面向不同用户角色的应用界面——C 端住客通过微信等触点与 AI 智能体交互；B 端酒店管理者通过工作台获取经营洞察与决策建议；集团总部通过数据看板实现全局管控。

（五）AHL 的产品架构（5 大 AI 能力模块）

模块一：收益管理与自动调价。 实时监控携程、美团、飞猪等 OTA 平台竞品价格、挂牌等级、评价变化，根据市场需求、天气、节假日前后，自动给出定价建议。酒店收益人员只需一键确认执行，无需手工收集数据。

模块二：OTA 智能维护。 携程评分实时监控、差评 30 分钟内预警、AI 自动分析差评原因（服务/设施/卫生/噪音）并生成个性化回复建议，紧急差评立即电话通知店长。

模块三：私域运营自动化。 客人离店后自动引导加入酒店微信社群，定时推送天气、活动、优惠信息；离店 7 天后推送复购优惠唤醒沉睡客人；按 RFM 模型（最近消费、消费频次、消费金额）对会员进行分层精细化运营。

模块四：C 端智能客服。 客人通过微信问"周六带孩子住江景 600 左右"，AI 30 秒内推荐最合适房型并协助完成预订（跳转小程序支付），全程在微信内完成，无需电话、无需等待前台。

模块五：B 端智能运营助手。 酒店管理者问"本周入住率多少""周边竞品价格有什么变化"，AI 直接给出答案和解读；每月自动生成核心指标报告（入住率/RevPAR/好评率/差评原因分布/竞品对比）。

三、AHL 与安逸集团及旅投集团的有机结合

（一）AHL 在集团内的定位

AHL 在安逸集团内的定位是集团数字化基础设施，而非单一产品试点。这一定位决定了 AHL 与集团的关系不是"试点项目到期评估是否继续"，而是"集团数字化能力的长期建设"。

具体定位层级：

  • 集团总部层面：AHL 是集团"十五五"1234 战略第四步"全方位市场化"的数字化底座，由集团产业发展部牵头统筹，集团信息中心协同。

  • 酒店层面：AHL 是集团下属酒店接入 AI 能力的统一入口，单店无需自建技术团队、无需更换现有 PMS 系统、无需购买专用硬件设备。

  • 数据层面：AHL 沉淀的数据资产归属集团统一管理，是集团核心数字资产的重要组成部分。

（二）与安逸集团现有业务的结合

一是与集团 PMS / CRS 系统集成。 AHL 通过 API 接口与集团现有 PMS、CRS 系统对接，不替代现有系统，而是叠加在现有系统之上，为集团 167 家酒店统一接入 AI 能力。

二是与"安逸汇"会员体系融合。 AHL 的私域运营模块可与集团现有"安逸汇"会员体系对接，实现会员数据双向流通；AHL 触达的客户数据可沉淀为"安逸汇"会员资产，"安逸汇"会员亦可通过 AHL 获得更精准的服务。

三是与 167 家酒店的接入路径。 按照"试点先行—逐步推广—全面覆盖"三步走：试点期 2 家，扩展期 30-50 家，成熟期 100+ 家。接入方式采用 SaaS 化部署（开箱即用、按需付费），降低单店接入成本与技术门槛。

（三）与旅投集团旗下多业态的协同

旅投集团旗下业态分散，包括酒店、景区、餐饮、交通（锦绣天府号等）等。AHL 可作为多业态横向联动的统一数字触点：

酒店 + 景区协同： 入住酒店的客人由 AI 主动推荐景区门票；景区游客由 AI 推荐集团旗下酒店住宿。

酒店 + 餐饮协同： 入住酒店的客人由 AI 推荐集团旗下餐饮门店；餐饮会员由 AI 推荐酒店住宿。

酒店 + 交通（锦绣天府号）协同： 入住酒店的客人由 AI 推荐天府号列车行程；天府号旅客由 AI 推荐沿途酒店。

（四）数据资产归属与共享机制

数据归属原则：客户数据归属集团统一管理，AHL 仅作为数据处理工具，不持有数据所有权。

数据共享机制：集团内不同业态、不同酒店之间的客户数据，在客户授权前提下，可通过 AHL 数据中台实现合规共享，为跨业态联动提供数据基础。

数据安全合规：严格遵循《中华人民共和国数据安全法》《中华人民共和国个人信息保护法》要求，落实数据脱敏、客户授权、最小必要等原则。

（五）组织关系与决策机制

集团总部层面：AHL 试点项目由集团产业发展部牵头统筹，集团信息中心提供数据基础设施协同，集团法务部提供合规审查支持，集团财务部提供预算管理支持。

试点酒店层面：试点酒店作为 AHL 应用主体，派员参与项目工作组，配合完成数据对接、系统部署、人员培训、效果评估等工作。

旅投集团层面：本试点项目作为安逸集团内部试点，待取得成效后再行研究向旅投集团其他业态（景区、餐饮、交通）推广的可行性。

四、通过 AHL 解决集团 9 大核心问题

（一）问题 1：集团对下属单店赋能及管控不足

现状痛点： 167 家酒店分散在多个城市，集团总部"看得见但管不着"；单店经营数据依赖人工报表，滞后且不准确；集团能力（收益管理、客户分析、采购、培训）难下沉到单店。

AHL 解决方案： 通过数据集成层实时采集试点酒店经营数据，构建集团统一数据中台；通过 5 大 AI 能力模块将集团专业能力自动下沉到单店（自动定价建议、自动差评回复、自动会员运营等）；通过 B 端智能运营助手让集团总部随时掌握单店经营状态。

预期成效： 试点期 2 家酒店数据可见度从"周报滞后"提升到"实时可见"；试点期收益管理建议接受率 ≥60%。

（二）问题 2：安逸品牌力不足，业主单位不接受

现状痛点： "安逸"品牌在中高端酒店市场认知度低；业主单位（持有物业方）不愿接受"安逸"品牌加盟；即使签约，业主也常要求"换牌"；品牌拉力不足导致集团轻资产输出受阻。

AHL 解决方案： AHL 的差异化策略——不推"安逸"品牌，推"垂系 Agent 服务"。通过 AHL 的 AI 能力（精准触达、收益优化、客户复购）让业主看到实际增值收益，业主接受的不是"安逸"品牌，而是"安逸的 AI 能力"。

预期成效： 业主接受度从 ~20% 提升到 ~50%；协议合作酒店从 0 家增长到 30-50 家。

（三）问题 3：旅投旗下及安逸旗下多业态横向联动

现状痛点： 旅投集团旗下业态分散（酒店、景区、餐饮、交通）；各业态会员体系孤立，客户无法跨业态享受服务；集团内协同弱，每个业态"各自为政"。

AHL 解决方案： 通过 AHL 数据中台打通酒店、景区、餐饮、交通等业态的客户数据；通过 C 端智能客服实现客户在不同业态的无缝切换体验；通过 5 大 AI 能力模块为各业态提供统一的智能化运营支持。

预期成效： 跨业态客户转化率 ≥15%；集团内协同收入贡献 ≥3,000 万元/年。

（四）问题 4：迅速扩充受众群体（会员联动）

现状痛点： "安逸汇"会员体系起步晚；OTA 替代率低（中央预订占比 <10%）；私域流量薄弱；客户获取成本高，OTA 佣金 15-25% 持续侵蚀利润。

AHL 解决方案： AHL 私域运营模块作为统一会员接口，让客户在不同业态无缝切换；AHL 触达数据沉淀为"安逸汇"会员资产；通过 OTA 智能维护模块提升集团在 OTA 平台的评分与排名。

预期成效： "安逸汇"会员从 0 增长到 1,200 万（含酒店、景区、餐饮、交通多业态客户）；中央预订占比从 <10% 提升到 25%。

（五）问题 5：安逸集团自身在此项目上创新创收

现状痛点： 集团收入单一（管理费 + 营收分成 + 部分租金收入）；缺乏创新收入来源；2025 年净亏 6,843 万元。

AHL 解决方案： 集团可向行业输出"垂系 Agent 服务"（SaaS 模式），按调用量或效果分成收费；不直接做酒店管理，而是把 AHL 的 AI 能力作为"技术服务"对外销售。

预期成效： 集团创新收入贡献 ≥5,000 万元/年；集团收入结构多元化（创新收入占比从 0 提升到 8%+）。

（六）问题 6：轻重资产分离助力

现状痛点： 集团重资产改造周期长（6 大酒店改造）；轻资产输出能力弱；重资产项目投入大、回报慢。

AHL 解决方案： AHL 让"轻资产输出"具备差异化卖点——不是传统酒店管理公司，而是"AI 赋能酒店运营"；AHL Agent 可以让轻资产管理的酒店达到"垂系 Agent 网络"的客户触达效果。

预期成效： 轻重资产分离完成（2027 年底）；轻资产管理酒店从 0 增长到 100+ 家；AHL 成为轻资产管理的"标准组件"。

（七）问题 7：行业影响力

现状痛点： 安逸集团在酒店行业默默无闻；缺乏行业话语权，难以参与行业标准制定。

AHL 解决方案： 试点成功 → 行业首发案例（成都酒店行业论坛）→ 申请四川省酒店业 AI 应用试点 → 申请行业标准制定。

预期成效： 行业媒体曝光 ≥10 篇/年；行业论坛主旨演讲 ≥3 次/年；申请行业标准 1-2 项。

（八）问题 8：重资产方向存量改造

现状痛点： 6 大酒店改造 + 总府四川宾馆/皇冠假日等存量改造，周期长；改造期间收入中断；改造后需要"快速恢复 + 提升"。

AHL 解决方案： 改造后立即接入 AHL，用 AI 能力提升入住率/复购率；改造期可作为"重资产改造+轻资产运营"样板；AHL Agent 帮助新开业酒店"3 年爬坡到稳态"（缩短爬坡期）。

预期成效： 改造酒店 RevPAR 提升 20-30%；"改造 + AHL" 成为集团样板方法论。

（九）问题 9：整个集团体系化数字化运作

现状痛点： 集团没有统一数字化平台，各业态数据孤岛；缺乏统一的"客户 ID""门店 ID""产品 ID"；数字化决策能力弱；集团总部"看不见一线"。

AHL 解决方案： AHL 作为集团数字化"底座"——Agent 既是客户触达工具，也是数据采集入口；通过 Agent 自然形成"统一客户 ID + 统一门店 ID + 统一产品 ID"；数据沉淀到集团数据中台，支撑集团决策。

预期成效： 集团数字化覆盖从 <30% 提升到 90%+；决策周期从"周级"缩短到"日级"。

五、试点计划与实施路径

（一）试点原则

一是在营酒店原则。 试点酒店必须为 2024 年以来持续正常运营的在营酒店，不在集团 2026-2028 年存量改造计划范围内，避免改造期入住率波动、IT 系统切换等变量干扰。

二是集团直营或控股管理原则。 试点酒店必须为集团直营或控股管理酒店，确保管理权可控、数据可对接、运营调整可落地。

三是数字化基础较好原则。 试点酒店具备较好的数字化基础设施条件（PMS、CRS、CRM 较成熟），具备 OTA 在售房间（携程、美团、飞猪等平台正常运营）。

四是业态代表性原则。 试点酒店涵盖不同业态代表性，便于验证 AHL 平台普适性，为后续规模化推广积累经验。

（三）试点期 12 个月时间表

试点期拟定为 12 个月（2026 年 9 月至 2027 年 8 月），分两个阶段推进：

阶段一：内部 MVP 验证期（第 1-6 个月）。 完成两家试点酒店 AHL Agent 系统部署、数据接口对接与内部测试，形成 MVP 验证报告，初步评估平台核心功能的应用成效。

阶段二：扩大试点期（第 7-12 个月）。 在阶段一验证基础上扩大应用范围，推进试点酒店全面接入，完成跨酒店客户转化测试，形成可复制、可推广的方法论与试点报告。

八、合规性与风险防控

（一）合规性论证

一是数据安全与个人信息保护合规。 AHL 平台运营过程中涉及客户预订信息、消费记录、行为偏好等数据采集与处理，将严格按照《中华人民共和国数据安全法》《中华人民共和国个人信息保护法》要求，落实数据脱敏、客户授权、最小必要等原则，确保数据处理活动合法合规。

二是关联交易合规。 本试点项目涉及集团与第三方 AI 技术服务商的合作，将严格遵循《企业国有资产法》《公司法》及集团关联交易管理制度，履行内部审议程序，确保交易定价公允、程序合规。

三是国企数字化转型政策合规。 本试点项目积极响应国务院国资委《关于加快推进国有企业数字化转型工作的通知》要求，符合四川省《"十四五"国有资本布局优化和结构调整规划》关于支持数字经济业务发展的政策导向。

四是三重一大决策程序合规。 本试点项目投资金额 380-560 万元，触发集团"重大投资决策"事项标准，将严格按照"三重一大"决策程序要求，履行党委前置研究、董事会决议等程序。

（二）风险识别与防控措施

序号 风险类别 风险描述 防控措施
1 技术风险 AHL 系统实际应用效果不达预期 阶段一充分验证，阶段二动态调整；预留阶段终止机制
2 经营风险 试点酒店配合度不足 集团分管副总牵头协调；试点前充分沟通；激励机制配套
3 合规风险 数据安全、关联交易合规风险 严格落实法律法规要求；法务全程介入；定期合规审查
4 市场风险 第三方 AI 技术服务商交付能力不足 选择有酒店行业成功案例的服务商；合同明确违约责任；保留备选方案
5 行业风险 行业竞品快速跟进 发挥集团 167 家酒店规模优势；加快数据喂养网络效应积累

（三）阶段终止机制

为有效控制试点风险，建立试点阶段动态调整与终止机制：

一是阶段一（第 6 个月末）评估后，若实际效果未达预期目标 60% 以上的，将削减阶段二预算 50%，并视情况调整试点酒店范围；

二是阶段二（第 12 个月末）评估后，若累计实际效果仍未达预期目标 70% 以上的，将暂缓扩大试点范围，待平台技术进一步成熟后再行评估；

三是试点全过程设置"暂停按钮"，每个里程碑节点前均设置集团分管副总书面复评环节，必要时可暂停试点。
