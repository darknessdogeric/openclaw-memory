## 摘要

**一、为什么现在要做这件事**

集团"十五五"高质量发展规划明确指出集团面临"三个不匹配"——资产与战略需求不匹配（资产 35.51 亿但 2025 净亏 6,843 万）、产品与资产价值不匹配（RevPAR 比同地段竞品低 30%+）、机制与市场竞争不匹配。同时集团 (52 家轻资产酒店 + 78,752 间管理房间, 十五五规划口径)分散在多个城市，集团总部"看得见但管不着"，缺乏数字化抓手。

**二、AHL 是什么**

AHL（垂系 Agent 平台）是我作为产业发展部部长牵头规划、本人主导设计的一个集团级数字化基础设施项目。它不是再造一个 OTA（携程/美团/飞猪），而是再造一个"触达层"——让酒店拥有自己的客户关系链资产。AHL 的核心创新在于"数据喂养的网络效应"：一个酒店 Agent 触达客户 → 数据反馈 → Agent 更精准 → 触达成本下降 → 更多酒店加入 → 更多数据喂养 → 良性循环。这是传统酒店管理公司和 OTA 都做不到的事情。

**三、试点怎么做**

我建议在集团内选择 **2 家在营酒店**（**不在 2026-2028 改造计划内**）作为首批试点，**12 个月**内完成 MVP 验证和模式复制。试点预算 300-500 万元（占集团年度营收 0.2%），由产业发展部牵头、集团信息中心协同。

**四、为什么董事长应该支持**

本计划响应集团"十五五"1234 战略第四步"全方位市场化"的数字化能力建设诉求。如果不在 2026 年内启动，集团将错过"AI + 服务业"的窗口期，2028 年后被市场淘汰的概率大幅提升。

## 第一章 项目背景与战略意义

### 1.1 集团当前面临的核心挑战

集团"十五五"高质量发展规划自我诊断中明确指出，集团当前面临"三个不匹配"的核心短板：

**短板一：资产与战略需求不匹配**

集团资产总额 35.51 亿元，但 2025 年净亏 6,843 万元，闲置面积近 50%。资产规模与同业头部企业（华住、亚朵、锦江、首旅）相比差距明显，且现有资产利用效率低下。具体表现：

- 78,752 间管理房间 + 52 家轻资产酒店分散在多个省市，单店平均客房数不足 100 间，规模偏小
- 资产质量参差，6 大酒店改造周期长（2-3 年/家），改造期间收入中断
- 重资产持有模式造成集团资金占用大、回报周期长（典型回收期 8-11 年）

**短板二：产品与资产价值不匹配**

集团旗下酒店 RevPAR（每间可用房收入）比同地段竞品低 **30%+**，核心原因：

- 硬件设施老化（部分酒店 5-10 年未系统改造）
- 文化主题缺失（除少数旗舰项目外，集团酒店缺乏差异化定位）
- 客户体验与服务标准化不到位（携程评分多在 4.5-4.6，落后于头部品牌 4.8+）

**短板三：机制与市场竞争不匹配**

集团运营机制相对传统，效率与市场化程度低于头部民营酒店集团：

- 决策链条长，重大事项需多级审批
- 激励机制不活，员工积极性受限
- 数字化运营能力薄弱，集团总部"看得见但管不着"
- 会员体系（"安逸汇"）起步晚，私域流量薄弱

### 1.2 集团"1234"战略与本计划的对接

集团"十五五"规划明确"1234"发展战略：

- "**1**" 一条主线：高质量发展
- "**2**" 两大品牌：宸屿生活美学 + 安逸生活方式
- "**3**" 三大赛道：城市商务 / 文化主题 / 文旅度假
- "**4**" 四步实施路径：轻重分离 → 打造标杆 → 品牌经营 → 全方位市场化

本计划直接服务于**"4"第四步"全方位市场化"**——而"全方位市场化"必须以**体系化数字化能力**为底座，否则"市场化"只是空话。

### 1.3 项目提出的战略必要性

从产业发展部角度，我认为集团当前最紧迫的不是再造一家酒店、不是再多开一个项目，而是**建立集团数字化基础设施**。原因有三：

**理由一：窗口期紧迫。** 国务院国资委已发布《关于加快推进国有企业数字化转型工作的通知》，明确国企数字化转型是"十四五""十五五"重点任务。同时"AI + 服务业"正处于爆发前夜，2025-2027 年是行业格局形成的关键窗口。集团如果不在 2026 年内启动，2028 年后被市场淘汰的概率大幅提升。

**理由二：解决"三个不匹配"的根本抓手。** 三个不匹配中，前两个（资产、产品）可以通过轻重分离、存量改造解决；第三个（机制）必须通过数字化转型实现。集团传统的人工报表、季度会议、邮件审批模式，已经无法适应 78,752 间管理房间 + 52 家轻资产酒店分散运营的管理需求。

**理由三：行业标杆的引领机会。** 集团作为四川省国资旗下酒店集团，有机会成为"AI + 酒店业"行业标准的制定者之一。这不仅是经济价值，更是**行业话语权**的战略价值。

## 第二章 AHL 是什么 —— 给董事长的详细说明

### 2.1 行业现状与机会

当前中国酒店行业的客户触达渠道高度集中在 OTA（携程/美团/飞猪）：

- OTA 渠道占比通常达到 60-80%
- OTA 佣金率 15-25%，持续侵蚀酒店利润
- 中央预订（酒店直订）占比通常不足 10%
- 私域流量（公众号、小程序、APP）活跃度低

这种格局导致酒店面临两大困境：

**困境一：客户关系不属于酒店**。OTA 掌握客户数据和复购决策权，酒店沦为"OTA 的线下供应商"。

**困境二：获客成本不断上升**。OTA 通过算法提高佣金率，酒店利润率持续被压缩。

### 2.2 AHL 的核心定义

**AHL 是"垂系 Agent 平台"**——基于人工智能的、专门服务酒店行业的智能体网络。"垂系"是相对于"通用"而言的，意为"垂直深耕酒店行业"，不是 ChatGPT 那种通用聊天机器人。

**AHL 与传统方案的本质区别**：

| 维度 | 传统方案（OTA / 酒店管理公司 / 自建 APP）| AHL |
|------|--------------------------------------|-----|
| 客户关系归属 | 归属 OTA / 集团总部 | **归属酒店本身** |
| 触达方式 | 客户主动搜索 | **Agent 主动推荐**（基于客户画像）|
| 客户理解深度 | 标准化标签（年龄段、消费档次）| **深度语义理解**（客户具体需求）|
| 数据喂养 | 数据单向流向 OTA | **数据喂养 Agent 越来越精准** |
| 跨店协同 | 难（各酒店独立运营）| **Agent 网络互通** |
| 投资门槛 | 数千万级（APP/小程序）| **百万级（Agent 即插即用）**|

### 2.3 AHL 的三大核心组件

**组件一：数据层**——客户需求数据
- 客户主动表达的需求（搜索、咨询、预订）
- Agent 主动理解的需求（语义分析、行为预测）
- 历史交互数据（评价、复购、推荐）

**组件二：触达层**——垂系 Agent 网络
- 每个酒店配备专属 Agent（"酒店 AI 管家"）
- Agent 主动向客户推送个性化服务（不是被搜索，而是被推荐）
- Agent 之间可以互相协作（跨店推荐、套餐组合）

**组件三：关系层**——关系链资产
- 客户在不同酒店、不同业态（酒店、景区、餐饮、列车）的全旅程轨迹
- 数据沉淀到集团，形成"集团关系链资产"
- 这是集团的核心竞争壁垒（OTA 拿不到这部分数据）

### 2.4 AHL 的护城河：数据喂养的网络效应

AHL 的真正护城河不是技术、不是 AI，而是**"数据喂养的网络效应"**——这是一个经济学概念：

```
正反馈循环：

第 1 步：1 家酒店使用 AHL Agent
    ↓
第 2 步：Agent 触达客户 → 客户行为数据反馈
    ↓
第 3 步：Agent 基于数据优化 → 触达更精准
    ↓
第 4 步：触达成本下降 → 客户体验提升
    ↓
第 5 步：更多酒店加入 AHL
    ↓
第 6 步：更多数据喂养 → Agent 进一步优化
    ↓
回到第 2 步（良性循环）
```

**关键含义**：谁能先形成这个正反馈循环，谁就赢。集团作为四川省最大的国资酒店集团之一，有 78,752 间管理房间 + 52 家轻资产酒店作为"天然试验田"，这是民营酒店集团无法比拟的规模优势。

### 2.5 AHL 与现有解决方案的对比

**对比 1：OTA（携程/美团/飞猪）**
- OTA 是"商场"，酒店是"店铺"，客户属于商场
- AHL 让客户属于酒店，集团掌控自己的客户资产
- 集团不应再做 OTA 的"打工仔"，应该有自己的客户关系

**对比 2：传统酒店管理公司（如华住、亚朵输出管理）**
- 酒店管理公司输出"人 + 系统"，但缺乏 AI 能力
- AHL 输出的是"AI 智能体"，是更高维度的能力输出
- AHL 可以成为集团轻资产管理的"差异化卖点"——这是其他酒店管理公司做不到的

**对比 3：自建 APP / 小程序**
- 自建 APP 开发成本数千万，且需要持续运营投入
- 客户使用 APP 的频率低（一年可能只用 1-2 次），活跃度问题难以解决
- AHL Agent 是"按需触达"，客户不需要下载任何东西，体验更轻

### 2.6 AHL 对集团的核心价值（一句话）

> **AHL 不是产品，是集团数字化基础设施。** 它让集团 (52 家轻资产酒店 + 78,752 间管理房间, 十五五规划口径) + 旅投旗下多业态拥有自己的客户关系链，让集团从"OTA 的线下供应商"升级为"客户资产的持有者"。

## 第三章 试点目标与范围

### 3.1 试点总目标

12 个月内完成 **2 家在营酒店**的 AHL Agent 部署，验证核心假设，形成可复制的方法论。

### 3.2 为什么不在改造范围内的酒店做试点

我特别说明：**本试点不选择 2026-2028 改造计划内的酒店**（如总府四川宾馆、总府皇冠假日等），原因有三：

**原因一：变量干扰。** 改造期间酒店处于"半营业状态"，入住率波动大、客户结构不稳定，无法准确评估 AHL Agent 的真实效果。

**原因二：数据基础不完整。** 改造期间酒店 IT 系统（PMS、CRM、OTA 接口）处于切换或重建状态，Agent 数据采集和触达都不稳定。

**原因三：决策权不在产业发展部。** 改造项目由集团其他部门主导，产业发展部介入会增加协调成本。试点应选择产业发展部能"说了算"的酒店。

### 3.3 试点酒店选择标准

**必须满足的条件**：
- 在营状态（2024-2026 持续运营）
- 不在 2026-2028 改造计划内
- 集团直营或托管（管理可控）
- 数据基础设施较好（PMS、CRM 较成熟）
- 客户结构有差异化（不是纯商务或纯度假单一类型）

**理想条件**：
- 集团核心商圈酒店（验证 AHL 在核心商圈的效果）
- 不同业态组合（验证 AHL 的普适性）
- 数字化基础好（业主配合度高）

### 3.4 试点酒店候选（2 家）

基于上述标准，我建议选择 **2 家具有不同业态代表性的在营酒店**作为试点（具体酒店名单待集团批准后另行报告）：

**候选酒店 A：城市商务旗舰酒店**

- 位置：成都核心商圈
- 档次：4 星级
- 房间数：150-200 间
- 客户结构：商务 50% + 散客 30% + 协议 20%
- 集团参与方式：直营
- 现有数字化基础：OTA + 集团 PMS + 基础 CRM
- **试点价值**：验证 AHL Agent 在城市商务酒店的精准触达效果、协议客户数字化运营、OTA 替代效果

**候选酒店 B：度假或托管运营酒店**

- 位置：成都周边景区或地州市
- 档次：4-5 星级
- 房间数：80-120 间
- 客户结构：度假 60% + 会议 20% + 散客 20%
- 集团参与方式：托管运营
- 现有数字化基础：基础 OTA + 简单 CRM
- **试点价值**：验证 AHL Agent 在度假场景的客源激活、托管模式下的数据回流、与集团总部的实时联动

**两家酒店组合的协同价值**：城市商务 + 度假两类客户的"全旅程"联动——商务客入住城市酒店后，Agent 主动推荐度假套餐；度假客回到城市后，Agent 推荐城市酒店复购。这正是 AHL "数据喂养网络效应"的初次验证。

### 3.5 试点排除条件（红线）

以下情况**不纳入试点**：

- 在改造计划内的酒店（避免变量干扰）
- 业主单位不配合的酒店（避免无效投入）
- 集团不控股的酒店（避免管理权风险）
- 数字化基础设施为零的酒店（避免"无米之炊"）

## 第四章 解决方案与实施路径

### 4.1 AHL 解决的九大集团痛点

基于试点酒店的实际情况，AHL 试点将同时验证 AHL 对集团九个核心痛点的解决能力：

| # | 集团痛点 | AHL 解决方案 | 试点验证指标 |
|---|---------|-------------|-------------|
| 1 | **集团对下属单店赋能不足** | Agent 数据回流 + 能力下沉到单店 | 集团对试点酒店数据可见度从"周报滞后"提升到"实时可见" |
| 2 | **安逸品牌力不足，业主单位不接受** | 不推"安逸"品牌，推"垂系 Agent 服务"差异化 | 业主接受度、协议合作意向 |
| 3 | **多业态横向联动弱** | 统一客户 ID + 跨业态 Agent 触达 | 跨酒店客户转化率 ≥10% |
| 4 | **会员体系薄弱** | Agent 作为统一会员接口 | 试点期会员增长 ≥5 万 |
| 5 | **集团缺乏创新创收** | 集团输出"垂系 Agent 服务"SaaS 模式 | 试点期服务收入 ≥100 万 |
| 6 | **轻重资产分离需要差异化卖点** | AHL 作为轻资产管理差异化能力 | 试点输出方法论支持集团轻资产管理 |
| 7 | **行业影响力不足** | 试点成功形成"成都模式" | 行业媒体曝光 ≥3 篇 |
| 8 | **存量改造需要"激活"能力** | 改造后酒店可接入 AHL（虽不在本试点）| 试点沉淀方法论可推广到改造项目 |
| 9 | **集团体系化数字化缺失** | AHL 作为集团数字化底座 | 试点形成数据中台基础 |

### 4.2 试点路径设计（3 阶段 12 个月）

**阶段 0：内部 MVP（第 1-6 个月，2026/9-2027/3）**

- 选定 2 家试点酒店
- 完成 Agent 系统部署（与第三方 AI 公司合作）
- 数据接口对接（PMS / CRM / OTA）
- 内部测试与小流量验证
- **阶段产出**：MVP 验证报告、效果数据

**阶段 1：扩大试点（第 7-12 个月，2027/4-2027/12）**

- Agent 系统优化（基于阶段 0 数据）
- 试点酒店全面铺开
- "安逸汇"会员体系打通
- 跨酒店客户转化测试
- **阶段产出**：扩大试点报告、可复制方法论

### 4.3 关键里程碑

| 时点 | 关键动作 | 决策门槛 |
|------|---------|---------|
| **2026/9** | 集团董事会决议，启动试点 | 董事长批准 |
| **2026/12** | Agent 系统部署完成（阶段 0 中期）| 阶段评估 |
| **2027/3** | 阶段 0 完成评估 | 决定是否进入阶段 1 |
| **2027/6** | 阶段 1 中期评估 | 试点效果评估 |
| **2027/12** | 试点完成 | 形成可复制方法论 |

### 4.4 风险控制节点

每个阶段都有明确的"暂停/终止"机制：

- 阶段 0 投入 300 万，若 6 个月内效果不达预期，**削减阶段 1 预算 50%**
- 阶段 1 投入 200 万，若 12 个月累计效果不达预期，**暂缓扩展，等待技术成熟**
- 全程设置"暂停按钮"：每个里程碑前都有董事长复评机会
