## 工具 6:增量索引器 详解

### 背景问题

全量索引 14,740 块耗时 **7-8 分钟**。每次 KB 变化都要重建,Eric 等不及。

### 增量索引原理

```
扫描 KB 所有 .md (536 个文件)
  ↓
SHA256 哈希(只算 16 字符短哈希)
  ↓
对比已有索引(documents.pkl 中已有 path)
  ↓
识别 3 类变化:
  - 新增文件:path 不在已有索引
  - 修改文件:文件 mtime > 索引文件 mtime
  - 删除文件:path 在已有索引,但文件不存在
  ↓
只对新文件/修改文件生成 embeddings
  ↓
合并到 embeddings.npz
```

### 实测性能(增量索引首次跑)

| 步骤 | 数量 | 耗时 |
|------|------|------|
| 扫描 KB | 536 个文件 | <1 秒 |
| 模型加载 | - | **23.6 秒** |
| 删除旧索引 | 441 块 | <1 秒 |
| 处理新/修改 | 60 个文件 → 2,741 块 | **87.7 秒** |
| 合并 + 保存 | 21 MB 压缩 | <5 秒 |
| **总耗时** | - | **~2 分钟** |

vs 全量索引 7-8 分钟 → **加速 ~4 倍**。

### 实测效果

- 增量前:**14,740 块**
- 增量后:**15,299 块**(净增 559 块)
- 检索测试("安逸集团1244战略"):正常工作,Top-1 命中 AHL 内部预审稿(0.624)

## KB 工作流标准动作(v3.2)

```
Eric 提问
  ↓
1. 立即 kb_semantic_search.py search "..."
   → 取 top-5 相关片段
2. 基于知识基础回答
  ↓
Eric push 新文件 或 我产出新报告归档
  ↓
3. 归档到 anyi-ops-kb / universal-kb
  ↓
4. 跑 kb_scanner.py 检查一致性
   - 发现冲突 → kb_auto_r66.py apply
   - 发现旧版本 → kb_auto_archive.py apply
5. 跑 kb_index_incremental.py apply(2 分钟)
  ↓
下次检索立即可用新知识
```

**关键变化**:从全量 7-8 分钟,缩短到 **增量 2 分钟**,且**完全自动**(无需手动 index)。
