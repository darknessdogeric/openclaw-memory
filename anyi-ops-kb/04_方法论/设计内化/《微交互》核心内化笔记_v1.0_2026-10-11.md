## 一、核心命题（4 要素模型）

Dan Saffer 在书中第一次描述：**微交互 = 产品里"只处理一个小任务"的互动单元**。

**4 大要素**：

| 要素 | 含义 | 例子 |
|------|------|------|
| **触发**（Trigger）| 启动微交互 | 按按钮 / 系统通知 / 时间到 |
| **规则**（Rules）| 交互逻辑 | 按按钮 → 灯开关 → 状态变化 |
| **反馈**（Feedback）| 用户知道发生了什么 | 边框变绿（验证通过）/ 震动（静音切换）|
| **循环与模式**（Loops & Modes）| 随时间/上下文变化 | "立即购买" → "再次购买"|

## 二、4 大核心方法（来自 web_search）

### M1 · 微交互不是装饰动画

```
"做按钮的 hover 状态最少要包含：
- 默认状态
- 滑过状态
- 键盘焦点
- 按下
- 不可用
- 处理中
- 完成"
```

**Eric 海报对应**：v10 海报的"蓝色圆形 B 标"hover 应该有变化（不是死的）——**目前是静态的，需要加 hover 反馈**

### M2 · 微交互 8 条设计准则

1. **不要让用户无聊**（让用户知道发生了什么）
2. **保持简单**（动画清晰流畅）
3. **关注用户情绪**（情绪影响交互）
4. **可预测**（不要改变长期建立的模式，如"绿色=去"）
5. **让交互可见**（按钮状态要清晰）
6. **明确反馈**（成功/失败要视觉化）
7. **避免反复确认**（不要弹窗烦用户）
8. **微交互是"为用户确认"的工具，不是炫技**

### M3 · 微交互决策清单

| # | 检查问题 | 答案 |
|---|---------|------|
| 1 | 操作需要确认？| 添加反馈动画 |
| 2 | 正在加载/处理？| 进度/骨架屏 |
| 3 | 状态变化？| 过渡动画 |
| 4 | 用户可能错过重要内容？| 吸引注意力动效 |
| 5 | 频繁重复操作？| 保持简洁 |
| 6 | 纯装饰？| 跳过（除非品牌需要）|
| 7 | 无动画时功能正常？| ✅ 动画仅为增强体验 |
| 8 | 重复 100 次后用户烦躁？| 减弱或移除 |

### M4 · 微交互的功能 4 类

1. **传达反馈**（操作结果）
2. **完成单一任务**（打开/关闭/保存）
3. **增强操控感**（用户主导感）
4. **防止误操作**（视觉化提示）

## 三、对 v10 设计 DNA 的具体深化

| v10 元素 | 微交互启示 |
|---------|---------|
| 顶部 kicker + 标题 | ✅ 静态即可（不是按钮） |
| 段标题 🔭💡🎯 | ✅ emoji 是"触发"——读者眼睛被吸住 |
| 整宽横线 | ⚠️ 可加 hover 时变色（当前静态） |
| 底部 banner | ✅ 蓝色边框 + 渐变背景 = 视觉"反馈" |
| B 标 | ⚠️ 可加 hover 时旋转 + 金边高亮 |
| 引文左蓝边 | ✅ 视觉化的"强调反馈" |
| 数字"13天超长" | ✅ 大字号 = 视觉焦点 = "触发注意"|

**重点改进方向**（Eric 海报数字化时）：
1. B 标 hover 时金边变粗 + 微旋转
2. 整宽横线 hover 时变金
3. 段标题 emoji 可加微动效
