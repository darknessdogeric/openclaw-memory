## 一、核心命题（5 大可立刻应用）

| # | 命题 | 一句话 |
|---|------|-------|
| 1 | **结果 > 产出** | 我们想改变用户什么行为？（不是"做了什么功能"）|
| 2 | **假设先行** | "我们相信 [做这个] 对 [这个用户] 会产生 [这个结果]，当 [这个信号] 变化时验证" |
| 3 | **最小可行实验** | 用最小代价验证最大风险假设 |
| 4 | **跨职能协作** | 设计 + 工程 + PM 在同一假设框架下工作 |
| **5** | **从产出 → 结果** | "功能上线" ≠ "问题解决"，看用户行为变化 |

## 二、Lean UX 假设陈述格式（核心句式）

```
"我们相信 [做 X]
 对 [用户 Y]
 会产生 [结果 Z]。
 当 [可测信号 W] 变化时，
 我们知道这是真的。"
```

## 三、4 大核心方法（来自 web_search）

### M1 · 假设优先级矩阵（Assumption Mapping）

```
X 轴：不确定性（我们有多少证据）
Y 轴：风险（错了影响多大）
        ↑
  高风险 │
        │   🟥 高风险+高不确定（最先测）
        │
  ──────┼──────────→ 不确定性
        │
        │
  低风险 │
```

**Eric 海报对应**：海报上线后，**最高风险+最高不确定**的假设 = "目标受众会扫码" → 先测这个

### M2 · MVP 4 等级

| 等级 | 名称 | 工具 |
|------|------|------|
| L1 | 纸上原型 | A4 纸 + 笔 |
| L2 | 草图 | Figma/Sketch |
| L3 | 高保真原型 | Figma + 交互 |
| L4 | 真功能（限时） | Landing page + 5 天关 |

**原则**：**从 L1 开始，没过 L1 不进 L2**

### M3 · 双轨敏捷（UX in Sprint）

```
Sprint 1：UX 设计 + 实验（不写代码）
Sprint 2：UX 设计 + 实验 + 上一轮结果验证
Sprint 3：开发（基于已验证的 UX）
Sprint 4：开发 + 上线 + 度量
```

**关键**：**设计与开发错峰 1 个 Sprint**，避免"设计未验证就开发"

### M4 · 4 个核心原则（来自 O'Reilly 概述）

1. **跨职能协作**（设计师 + PM + 开发）
2. **假设明示 + 快速验证**（不是"权威"假设）
4. **可用性测试每轮都有**（不是里程碑才有）
5. **从产出 → 结果**（UX 的 OKR，不是"完成功能"）

## 五、立即可用执行清单（Eric 海报设计用）

```
□ Eric 海报上线前，问 1 句：
  "我想改变目标受众什么行为？"
  → 想清楚再设计，否则在猜

□ Eric 海报上线后，验证 1 个假设：
  "我们相信 [这张海报]
   × [投放朋友圈]
   会产生 [扫码+分享]。
   当 [24h 扫码率 > 5%] 时，
   我们知道这是对的。"

□ 把"完成海报"≠"成功"
  → 成功 = 读者行为变化（转发/扫码/收藏）
```
