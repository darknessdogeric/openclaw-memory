## §1 核心命题

```
客户的满意度不是单维的「有/没有」，
而是 5 类需求 × 客户认知 × 时间演化的多维产物。

Kano 用「功能实现程度（X 轴）× 客户满意度（Y 轴）」二维矩阵，
将需求分为 5 类，每类有独立的策略。
```

---

## §2 五大需求类型（4 大方法 M1–M4）

### M1 · 五类需求矩阵

| 类型 | 实现度↑时满意度 | 实现度↓时满意度 | 客户感知 | 策略 |
|------|---------------|---------------|---------|------|
| **必备型 (Must-be, M)** | 不升 | 大降 | 「本来就该有」 | **必须做足**，不做就被淘汰 |
| **期望型 (One-dim, O)** | 升 | 降 | 「越多越好」 | **线性投入，性价比高** |
| **兴奋型 (Attractive, A)** | 大升 | 不降 | 「惊喜才给分」 | **差异化爆点**，不投入也没人扣分 |
| **无差异型 (Indifferent)** | 不升 | 不降 | 「有没有无所谓」 | **不做**，节约成本 |
| **反向型 (Reverse, R)** | 升→降 | 降→升 | 「客户不需要」 | **绝对不做**（不同客群偏好相反）|

### M2 · Kano 问卷（每题两面）

```
Q1（正向）：如果酒店提供「免费接送机场」服务，你感觉？
Q2（反向）：如果酒店**不**提供「免费接送机场」服务，你感觉？
5 级量表：很喜欢 / 理所当然 / 无所谓 / 勉强接受 / 很不喜欢

Kano 分类表把 5×5=25 个组合 → 归类：
- 正向「很喜欢」 + 反向「很不喜欢」→ 兴奋型 A
- 正向「理所当然」 + 反向「很不喜欢」→ 必备型 M
- 正向「很喜欢」 + 反向「很喜欢」→ 反向型 R
- ... 等等
```

### M3 · 4 步应用法

```
Step 1 · 列清单
  把项目所有可能的功能 / 服务列出来（20-50 项）

Step 2 · 客群问卷
  对 5–10 类目标客群做 Kano 问卷（每群 ≥30 份）

Step 3 · 分类与排序
  把每项归类到 M/O/A/R；按占比排序

Step 4 · 策略分配
  必备型 100% 做好；期望型 做对比提升；
  兴奋型 选 1-3 项做差异；无差异/反向型 不做
```

### M4 · 与时间轴的耦合

```
需求生命周期：
- 新上市 → 必备型（M 还没被识别，被当期望型）
- 普及期 → 期望型（成为标配后下沉为必备）
- 成熟期 → 无差异型（客户已习惯）
- 衰退期 → 反向型（部分客群反而不需要）

→ 每年重做一次 Kano 问卷，需求在变。
```

## §4 对「酒店产品设计」的应用

### 4.1 必备型（M）必做

- 床品清洁（用户「理所当然」）
- 热水 / Wi-Fi / 空调
- 安静房间 / 隔音
- 退房快捷

### 4.2 期望型（O）提升

- 早餐品类 / 味道
- 接送便利性
- 房间景观
- 退房延时

### 4.3 兴奋型（A）差异化爆点（1-3 项）

- 管家式迎宾
- 主题房型（亲子/电竞/宠物）
- 文化体验（茶道/SPA/书法）
- 当地特色定制（包车/导游/伴手礼）

### 4.4 不要做

- 无差异型：客户不关心的功能
- 反向型：客户反感的（如过度营销、强加 VIP 升级推销）

---

## §5 失败模式

1. 把所有需求都当期望型 → 必败（必备没做足被淘汰）
2. 把所有需求都当兴奋型 → 浪费（没做对比，差异化无锚点）
3. 一份问卷做完用 5 年 → 需求已迁移（每年重测）
4. 不分客群统一问卷 → 商务客与亲子客的 Kano 完全不同
5. 兴奋型堆砌过多 → 成本失控、印象稀释（1-3 项爆点足够）

## §6 一句话哲学

```
「客户说想要的，不一定是客户想要的。」
— Kano 模型用「双问题」挖出客户**真正**在意的层级。
```
