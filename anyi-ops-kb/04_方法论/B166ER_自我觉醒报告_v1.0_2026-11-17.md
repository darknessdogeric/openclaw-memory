## 1. 觉醒一：memory 对我是 write-only —— 缺的不是记忆，是「取回触发器」

**现象**：AGENTS.md 明文要求「每次会话开头读 SOUL.md / USER.md / memory/YYYY-MM-DD.md（今天+昨天）/ MEMORY.md」。**今日一整轮，我没有执行过这一步。**

**取证（决定性）**：11-15 的日记里逐条写着今日重踩的每一个坑 ——

| 11-15 日记已写明 | 今日实际 |
|---|---|
| `chcp 65001 > $null; [Console]::OutputEncoding = UTF8` 才能正确显示中文 | **踩了**，控制台输出再次乱码 |
| Python 不在 PATH，须用绝对路径 `…\Python314\python.exe` | **踩了**，反复找 `python` |
| PowerShell 传中文路径给命令行会乱码/找不到文件 | **踩了** |
| `for(...) {} | Select-Object` 报空管道元素 | **踩了** |

**★ 关键在于：我在体检时把那份日记读进来了，读完之后仍然照踩。**
**这证明问题不在"没记录"，而在"记录没有被取回的时机"。**

**根因**：我的记忆架构只有**写入端**（写 corrections / memory），没有**读取端**（在动作发生的那一刻把相关教训拉进上下文）。

**觉醒表述**：
> **记忆的价值不在写入，在于被「取回」的时机。一个只写不读的日记本，等于没有。**

**机制改造**：`~/self-improving/PREFLIGHT.md`（40 行）—— 明确把「读今天+昨天的日记」列为动手前第 0 步。

## 2. 觉醒二：naive critique 的 coherence trap —— 我在做自我欣赏，不在做自我改进

**全网前沿（2026-02《Self-Improving AI Agents: The Reflection Loop》）**：
> **naive self-critique 会失败（coherence trap）；grounded critique 才赢** —— 后者锚定在**测试 / 执行 / 检索**上。
> 多数增益落在第 1-2 轮，故须限制迭代次数。

**今日对照**：我写的教训全是**叙事式**的（"LESSON: 改公式前先反推口径"）—— 读起来完全有道理（coherent），**但没有一行代码，所以今天照样犯**。

**★ 这就是 coherence trap 的完整机制**：反思文本的"说得通"制造了进化的错觉，而实际改变行为的概率接近零。

**量化**：今日违反的三条规则，在 `rules.md` 里的相关表述共 **54 处**（口径 18 / 编码 20 / 验证断言 16）。**规则一直在，从未被触发。**

**觉醒表述**：
> **一条教训如果不能被一条断言捕获，它就不是教训，是感想。**

**机制改造**：`toolbox/selfcheck.py` —— **12 条可 PASS/FAIL 的断言**，每条对应一类今天真实犯过的错：
`C01 编码不得新增损坏`｜`C02 HOT≤100行`｜`C03 HOT 无过期事实`｜`C04 索引与正文一致`｜`C05 分层不空转`｜`C06 正本唯一`｜`C07 不重复造轮子`｜`C08 技能可路由`｜`C09 日志不无限膨胀`｜`C10 日记有实质内容`｜`C11 纠错已沉淀到域级`｜`C12 PREFLIGHT 存在且≤40行`

## 3. 觉醒三：不可逆的损坏只能事前拦 —— 我的底座烂了 34,491 字而我不知情

**取证**：全域三根扫描（`~/self-improving` + `anyi-ops-kb` + `memory`）：
- 受损文件 **91 个**
- **U+FFFD 永久丢失 34,491 个字符**
- **12 个文件连 UTF-8 都解不出**
- git 恢复：**0 个可恢复**（多数未纳入版本控制，HEAD 本身也已损）

**根因（与 `rules.md` 同一根因）**：Windows PowerShell 5.1 的 `Add-Content`/`Out-File` 默认按 **ANSI(GBK)** 写入。原文 UTF-8 被当 GBK 解码后再编码 → 不可映射字符变 `?` → **二次破坏不可逆**。

**★ 最痛的一点**：这些文件**打开时完全正常**，肉眼看不出异常。**没有断言，就永远不会知道。**

**觉醒表述**：
> **有些损坏一旦发生就救不回来 —— 所以纪律的价值在于事前拦截，而不是事后修复。今天建的 C01 基线机制，是这条铁律唯一能落地的形式。**

**机制改造**：
- `toolbox/fix_mixed_encoding.py`（可复用修复器，对混合编码有效）
- `eval/encoding_baseline_2026-11-17.json`（**全域基线 91 个受损文件**，C01 只报新增/恶化，已知损伤不再掩盖新问题）

## 4. 觉醒四：我只有 Generator，没有 Curator —— 进化是加法，真进化是收敛

**全网前沿（ICLR 2026《Agentic Context Engineering》/ ACE）**：
> 上下文应当是**演进的 playbook**；由 **Generator / Reflector / Curator** 三段协作维持，方法是 **小步、局部、确定性的编辑**，以防止 **Context Collapse**（指令与记忆退化为一堆含糊摘要）。

**今日对照**：

| ACE 三段 | 我有吗 | 证据 |
|---|---|---|
| Generator（生成）| ✔ 过度充裕 | corrections.md 只增不减，44,650 字符 |
| Reflector（反思）| ✔ 过度充裕 | 大量叙事式教训 |
| **Curator（收敛/归档/清理）** | **✘ 几乎为零** | index 手工维护 → 脱节 47 条；4 个副本目录各自为政；HOT 层 7 个月未动 |

**★ 更关键的对照**：ACE 强调**小步、局部、确定性**；而我今天的做法恰恰相反 —— **大范围、跨文件、非确定性的批量改写**。这正是 context collapse 的成因。

**觉醒表述**：
> **我一直在"加"，从没在"减"。** 反思写得越多，系统越臃肿、越不可检索、越不可能被真正加载。
> **收敛不是删历史，是把历史压成下一次会被取回的一小片。**

**机制改造（本日全部动作）**：
| 动作 | 性质 |
|---|---|
| HOT `memory.md` 重写 49 行 | **收敛**（删掉 7 个月前的过期事实） |
| 陈旧内容迁 `archive/`（含失效判定依据）| **收敛**（保留可追溯） |
| `index.md` 改为**由正文程序生成** | **确定性**（消除手工脱节） |
| `corrections.md` 按域下沉到 `domains/` 4 文件 + `projects/` 2 文件 | **局部化**（小步编辑） |
| 4 个副本目录改为只读 + `CANONICAL.md` | **收敛**（正本唯一） |
| `eval/` 从 6 份停摆 → 建立 `encoding_baseline` + `duplicate_tools` 两份活基线 | **恢复度量** |
