# 报告体系总图：信源矩阵 → 月报 → 季报 → 半年报 v1.0

> **本文件用途**：解决 2026-09-06 23:31 三个范式（01/02/03）都引用的核心总图缺失问题
> **设计原则**：1 个信源池 → 3 个时间维度报告 + 4 个用户角色视角 + 全自动工作流

## 三、数据处理层（核心）

### 3.1 范式驱动的数据流

```
[信源池] → [报告类型选择] → [数据采集器] → [数据处理器] → [报告生成器]
                │                │                │              │
```

## 六、自动工作流

### 6.1 月报自动流（每月 1-5 日）

```
Day 1：8+4 家上市公司 IR 月度新闻 + TrendRadar 扫描
Day 2：STR + 迈点 + 奥维 + Skift 月报
Day 3：集团内部 P&L + 6 大改造进度 + 政策追踪
Day 4：AI 行业 + VC 动态
Day 5：拼装月报（套 01_酒店月报范式 8 章）+ R66 校验 + 归档
```

### 6.2 季报自动流（季后 15 日内）

```
Day 1-3：8+4 家上市公司 Q 财报 + 集团 Q 财务 + 6 大改造 Q 进度
Day 4-7：Skift + Phocuswright + Cushman + CBRE 季报 + VC Q 动态
Day 8-12：拼装季报（套 02_酒店季报范式 10 章）+ 战略复盘会
Day 13-15：R66 校验 + 归档
```

### 6.3 半年报自动流（半年后 30 日内）

```
Day 1-5：8+4 家上市公司 H 财报 + 集团 H 财务 + 6 大改造 H 进度 + 6 个月月报
Day 6-15：EHL H 报告 + OECD/世行/IMF H 报告 + WTTC + Saudi 2030
Day 16-25：拼装半年报（套 03_酒店半年报范式 12 章）+ 战略复盘会
Day 26-30：R66 校验 + 归档
```

## 七、范式系统使用流程

### 7.1 第一次使用（一次性配置）

```
1. 读 04_报告体系总图（本文件）→ 理解整体架构
2. 读 01/02/03 三个范式 → 选择本次报告类型
3. 跑 hotel_sources.py --list → 确认信源可用
4. 配置 cron 任务 → 每月/季/半年自动触发
```

### 7.2 日常使用（每月/季/半年一次）

```
1. cron 触发 → 自动跑信源扫描
2. 收集本月数据 → 填入模板
3. 套范式生成报告 → R66 校验
4. 归档 anyi-ops-kb + 同步 Obsidian Vault
```
