# OpenViking 评估报告

> **一句话**: 字节跳动/火山引擎开源的 **AI Agent 上下文数据库**,方向上精准命中我们 KB 层的痛点;我们**已安装(0.2.9)但未跑通**,有 **5 项可修复阻塞**。

---

## 一、本体:它是什么

| 项 | 内容 |
|----|------|
| **定位** | "Self-evolving Context Database for AI Agents" — Agent 的**长期记忆/知识/技能**统一底座 |
| **出身** | 字节跳动 / 火山引擎 Viking 团队开源 |
| **仓库** | github.com/volcengine/OpenViking |
| **License** | Apache-2.0 |
| **Star** | 16.4k → 23.8k(增长极快;不同时点口径) |
| **最新版** | **0.3.22+**(GitHub)/ 0.4.15(火山文档) |
| **底层** | 自研 AGFS 文件系统 + VikingDB 向量库 |
| **云服务** | 火山引擎「OpenViking Context」全托管(Agent Plan 套餐) |

### 核心命题

> **"Agent 的记忆不该是黑箱"** —— 传统 RAG = 文本进、向量出,没人看得见存了什么。
> OpenViking 把上下文映射为 **`viking://` 虚拟文件系统**,Agent 用 `ls / tree / read / grep / find` 操作,每个目录自带摘要。

## 二、核心机制(4 大设计)

### 2.1 文件系统范式

```
viking://
├── resources/          # 资源:项目文档、代码库、网页
│   └── my_project/
│       ├── docs/
│       └── src/
├── user/{user_id}/
│   ├── memories/       # 记忆:偏好、习惯、经验
│   │   └── preferences/
│   ├── resources/
│   ├── skills/         # 技能:如何做任务
│   └── peers/          # 多 Agent 协作
└── agent/              # Agent 技能、指令、任务记忆
```

**关键**: 每个上下文单元有唯一 `viking://` URI → **可浏览、可检查、可编辑**(对比黑箱向量库)

### 2.2 三层上下文加载(L0/L1/L2)

| 层 | 内容 | Token | 用途 |
|----|------|-------|------|
| **L0** | 一句话摘要(`.abstract.md`) | ~100 | 快速相关性判断 |
| **L1** | 概览(`.overview.md`) | ~2,000 | Agent 规划阶段 |
| **L2** | 全文 | 按需 | 必要时深读 |

**价值**: Agent 先扫摘要再决定读什么 → **Token 大幅节省**

### 2.3 目录递归检索(非扁平向量池)

```
1. 意图分析 → 生成多个检索条件
2. 初始定位 → 向量检索定位高分**目录**(非文档)
3. 精细探索 → 目录内二次检索
4. 递归深入 → 子目录递归
5. 结果聚合 → 返回最相关上下文
```

**对比**: 传统 = 全库扁平搜索;OpenViking = **限定子树搜索**(如"只在某项目/某记忆子树内搜")

### 2.4 会话 → 记忆自动沉淀

- 提交会话 → 归档对话 + **抽取记忆为 Markdown**(可检查、可编辑、可合并)
- `ov compile` → 把素材组织成 wiki / 知识图谱 / 报告
- **自迭代循环**: 会话结束后异步分析任务结果与反馈 → 自动更新记忆目录

## 五、5 项阻塞与修复清单

| # | 阻塞 | 影响 | 修复动作 | 难度 |
|---|------|------|---------|------|

| 5 | **启动命令错** | 服务起不来 | 用 `openviking-server`(非 `python -m openviking`) | 🟢 低 |

## 六、VLM 可行路径(关键决策)

OpenViking 0.2.9 支持的 VLM provider: **volcengine / openai / litellm**

**litellm = 万能网关** → 可接 Kimi / GLM / Ollama 等

| 路径 | 模型 | 成本 | 中文 | 备注 |
|------|------|------|------|------|
| **A. Kimi(推荐)** | **kimi-k3**(多模态) | 💰 按量 | ✅ 强 | **我们已配置 moonshot** — 零新增账号成本 |
| B. 火山豆包 | doubao-seed-2.x-pro | 💰 按量 | ✅ 强 | 需火山引擎账号 |
| C. OpenAI | gpt-4o 等 | 💰 按量 | 🟡 | 我们曾遇 429 |
| D. 本地 Ollama | qwen2.5-vl / llava | 🆓 免费 | ✅ 好 | 需本地算力(本机 GPU?) |
| E. GLM | glm-4v | 💰 | ✅ | 需智谱账号 |

**Embedding 路径**:

| 路径 | 模型 | 成本 | 中文 |
|------|------|------|------|

## 七、对我们的价值判断

### 7.1 我们 KB 层现状 vs OpenViking 能力

| 维度 | 我们现状 | OpenViking |
|------|---------|-----------|
| 语义索引 | ✅ 15,299 块(sentence-transformers,本地免费) | 更强(混合检索+目录限定) |
| 分层加载 | ❌ 无(全文检索) | ✅ L0/L1/L2 |
| 目录限定检索 | 🟡 部分(kb_semantic_search) | ✅ 递归目录检索 |
| 可观测 | ❌ 黑箱 | ✅ **可视化检索轨迹** |
| 会话→记忆 | ❌ 手动(memory/*.md 手写) | ✅ **自动沉淀 + 自迭代** |
| 工具链 | ✅ 6 工具(kb_scanner/maintenance/auto_r66/auto_archive/semantic_search/incremental) | 统一平台 |
| Token 成本 | 未优化 | **-34%~-91%** |

### 7.2 最大价值点(按其对我们重要性排序)

| # | 价值 | 说明 |
|---|------|------|
| 1 | **会话→记忆自动沉淀** | 我们现在的 `memory/YYYY-MM-DD.md` 是**手写**的;OpenViking 可**自动抽取** — 这是最痛的痛点 |
| 2 | **L0/L1/L2 分层** | 我们 15,299 块全文检索 → 可先扫摘要,Token 大降 |
| 3 | **可观测性** | 我的检索现在是黑箱;OpenViking 可看轨迹 → **符合 R66 可追溯要求** |
| 4 | **目录限定检索** | 现在全库搜;可按 KB 子树精确搜 |
| 5 | **官方 OpenClaw 集成** | Context engine 原生支持,非第三方适配 |

### 7.3 成本与风险

| 项 | 评估 |
|----|------|
| **软件成本** | 🆓 免费(Apache-2.0) |
| **运行成本** | Embedding(按量)+ VLM(按量)— 可用 Kimi/Jina 复用已有账号 |
| **迁移成本** | 🟡 中(需导入 15,299 块 + 重建索引) |
| **学习成本** | 🟢 低(文件系统范式,零学习) |
| **风险1** | 版本迭代快(0.2.9 → 0.4.x,半年跨 2 个大版本) |
| **风险2** | 中文检索依赖模型选择(已踩过 potion 坑) |
| **风险3** | L0/L1 摘要质量依赖 VLM(当前阻塞) |

## 八、我的判断(V2.9 先诊断可达性)

### 8.1 诚实结论

> **方向对,值得做;但当前是"半成品安装",需先修 5 项阻塞才能验证真实价值。**

### 8.2 建议路径(分 3 步)

| 步骤 | 动作 | 时间 | 产出 |
|------|------|------|------|
| **Step 1** | 升级 0.2.9 → 最新 + 修 VLM(Kimi K3)+ 修维度 + 修启动命令 | 1 小时 | 服务能跑 |
| **Step 2** | 小规模 POC:导入 1 个子目录(如 `anyi-ops-kb/07_战略与改革/`) | 2 小时 | 验证检索质量 vs 现有 kb_semantic_search |
| **Step 3** | 若 POC 通过 → 全量导入 + 配置 OpenClaw Context engine 集成 | 1 天 | 替换/增强 KB 层 |

### 8.3 不建议做什么

- ❌ **不建议**直接全量迁移(15,299 块)未经验证
- ❌ **不建议**买火山云服务(先用本地 + 现有 API)
- ❌ **不建议**在假期前动 KB(国庆后更稳)
