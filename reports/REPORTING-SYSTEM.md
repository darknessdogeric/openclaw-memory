## 一、报表体系全景

### 1.1 分层发布策略（核心机制）

**问题**：不同机构数据发布时间差异大（OTA T+1、交通部 T+2、酒店之家 T+7、券商 T+7-10），单一时点出报告必不完整。

**方案**：每个假期复盘拆为两段，每个周期报告按数据就位时间调度。

```
假期复盘：快报(Flash) → 完整报告(Final)
  T+2         →  T+7~8
  OTA+交通部    →  酒店之家+券商+集团

预测报告：预订趋势初稿 → 正式预测
  T-10~T-7        →  T-3~T-1
  OTA预订数据      →  交通部+券商+酒店之家

周期报告：按数据就位时间调度
  月度 → 次月12日（统计局+券商月报就位）
  季度 → 次季首月25日（大部分数据就位）
```

详细数据发布日历见：`DATA-CALENDAR.md`

### 1.2 三层报表矩阵

```
周期层（时间驱动）
├─ 月度市场分析    → 次月12日（统计局+券商月报就位）
├─ 季度分析报告    → 次季首月25日
├─ 半年分析报告    → 7/15, 1/15
└─ 年度分析报告    → 次年1/15

长假层（事件驱动，预测→快报→完整复盘 三节点）
├─ 春节  → 预测（除夕-7天）→ 快报（初七+2天）→ 完整（初七+7天）
├─ 五一  → 预测（T-7）→ 快报（T+2）→ 完整（T+7）
└─ 十一  → 预测（T-7）→ 快报（T+2）→ 完整（T+7）

小长假层（同上，时间线更紧凑）
├─ 元旦/清明/端午/中秋 → 预测（T-5）→ 快报（T+1~2）→ 完整（T+5~7）

专项层（季节性）
└─ 暑期 → 预测（6/25）→ 快报（8/15 中期）→ 完整（9/10）
```

### 1.2 报表配对逻辑（核心机制）

每份节前预测必须与节后复盘严格配对：
- 节后复盘 = 逐项对照节前预测 → 计算偏差率 → 归因分析 → 迭代预测模型
- 偏差率纳入"预测精准度追踪表"，滚动12个月可见趋势

### 3.2 动态发现规则 ⚡

```
IF 发现新的行业数据源 AND 来源可信 THEN
  1. 即时纳入 DATA-CALENDAR.md，标注发现日期
  2. 评估优先级（⭐⭐ ~ ⭐⭐⭐⭐）
  3. 若为高频/高价值源 → 调整后续cron任务指令
  4. 在下次月度报告中测试使用
END IF

已有数据源失效（停更/付费墙/质量下降）→ 标记⚠️降级，保留记录但不强制采集
```

## 六、迭代进化机制

1. **每次复盘后**：偏差归因 → 调整预测模型参数 → 记录到方法论改进日志
2. **每季度**：评估数据源质量 → 淘汰低质源 → 纳入新数据源
3. **每半年**：评估报表体系有效性 → 调整模板结构 → 删减低价值维度
4. **每年**：完整方法论升级 → V2.0 → V3.0...
