# prediction-discipline

> **来源书**：《信号与噪声：大数据时代预测的科学与艺术》纳特·西尔弗（Nate Silver）著｜原书 *The Signal and the Noise: Why Most Predictions Fail but Some Don't*（Penguin, 2012）
> **中文版**：中信出版社，译 胡晓姣／张新／朱辰辰；2013-08 首版；**2026-06 新版 ISBN 9787521784220，562 页**；繁体版《精準預測》（三采文化，2013-09）
> **作者**：538.com 创始人；2008 年美国大选预测中 49 州命中，2012 年全 50 州命中
> **内化日期**：2026-11-26
> **技能定位**：把「我以为」变成「可证伪、可结算」——**这不是知识，是一套对自己施加约束的工作流**

---

## 一、为什么必须建这个

西尔弗全书讲的是一件事：**信息量不等于预测力。** 2008 年有史以来最多的数据、最复杂的模型、最多的人，金融危机照样没被预测到。他给的诊断不是「数据不够」，而是四条结构性错误：

1. **用同一批数据既找规律又验证**（非样本预测）→ 必然过拟合
2. **忽略基准率**（基础率）→ 把噪声读成信号
3. **人类天生过度自信** → 概率说 70%，实际兑现 50%
4. **模型越复杂越糟** → 简单模型 + 少量变量常常更好

**这四条对酒店经营同样成立，而且更狠。** 酒店数据量小、季节性强、样本更少、归因更容易自欺。

## 二、三条原则（西尔弗原文，中国版第 2 章）

| # | 原则 | 落到我的执行 |
|---|---|---|
| **一** | **用概率的方法思考问题** | 不说「会涨/会跌/一定」，说「以 P 概率、在某区间内」；每条结论都带概率与基率 |
| **二** | **今天的预测是你以后人生的第一个预测** | **每条预测进台账**（ledger.py add）—— 写下概率、基率、**结算日**；到期必须回来打分（settle） |
| **三** | **寻求共识** | 群体预测优于个体（538 的全部价值来源）；我把「多源交叉」当共识机制，不靠单一来源下判断 |

**原则二是这套技能的引擎**：没有台账，原则一就只是口头禅。

## 三、五个可执行工具（零依赖，标准库）

### 3.1 ledger.py — 预测台账（原则二的执行器）

`
python scripts/ledger.py add --q "问题" --p 0.55 --base-rate 0.40 --resolve 2027-01-15 --domain market --note "依据"
python scripts/ledger.py settle --id <id> --outcome 1 --note "实际：..."
python scripts/ledger.py pending     # 到期未结算的（到期必须回来）
python scripts/ledger.py list
python scripts/ledger.py score      # Brier + 可靠性图 + Murphy 分解
`

**强制约束（脚本会拒）**：概率必须在 (0,1) 开区间；必须给结算日；未填基率会警告。
**为什么强制**：没有结算日的问题 = 不可证伪的断言 = 不算预测；「一定会」不是概率。

### 3.2 base_rate.py — 基率陷阱与贝叶斯（书的核心直觉）

`
python scripts/base_rate.py screen --prevalence 0.01 --sens 0.99 --spec 0.99
python scripts/base_rate.py bayes --prior 0.2 --lr 3.0
python scripts/base_rate.py odds --prior 0.2 --sens 0.9 --spec 0.8
python scripts/base_rate.py discovery --prevalence 0.001 --sens 0.9 --spec 0.9
python scripts/base_rate.py dilute --coverage 0.08 --effect 0.25 --baseline 0.46
`

- **screen**：稀有事件 + 高灵敏度 → **阳性里只有一半是真的**（1% 基率、99%/99% 检测 → PPV 仅 50%）。酒店场景：某渠道「高意向线索」多，不代表转化高
- **bayes / odds**：**似然比才是可迁移的量** —— 换基率重算后验即可，结论不必重推
- **discovery**：找全 vs 误报的代价权衡（书里「预测是为了让损失最小化」）
- **dilute**（酒店专用）：**定向动作的整体贡献有上限** = 覆盖率 × 组内效应。覆盖 8% 的会员活动、组内 +25% → 整体最多 +2%。**观察到远超 2% 的整体提升，就不可能只由这次活动解释**

### 3.3 regression_to_mean.py — 回归均值（书里棒球章的暗礁）

`
python scripts/regression_to_mean.py --r 0.6 --z1 -2
python scripts/regression_to_mean.py --series 0.5,1.2,1.8,2.4
`

**E[z2|z1] = r · z1**：挑出「最差的一批」做干预，下次他们自然变好 —— **不需要任何干预也会发生**。

**酒店场景警告（最容易自欺的一处）**：
- 挑出入住率最低的 10 家酒店做专项帮扶，下季度平均回升了 → **先问 r 是多少**
- 挑出 RevPAR 最差的月份做促销，次月回来了 → 回归均值
- **证伪四法**：设同样差的对照组 / 基线作为协变量回归 / 多测几次基线 / 看「最好的一批」是否等量下滑

### 3.4 signal_audit.py — 「这是信号还是噪声」判决器

`
python scripts/signal_audit.py --tests 40 --effect 0.3 --sd 1.0 --n 30 --prevalence 0.01 --in-sample --narrative "结论原话"
`

依次审：**多重比较**（试了 N 个假设 → 阈值收紧到 α/N，至少 N×α 个假阳性）→ **效应量与检验力**（n=30、效应 0.3 SD → 检验力严重不足，**阴性结果不可解读**）→ **基率** → **是否样本内验证** → 给出**诚实口径改写模板**。

**注意工具给的检验力是粗略近似（正态近似、忽略小样本与真实分布）**；它的价值在于**逼我写清 n、效应量、试了几次**，而不是给出精确功效。

### 3.5 brier.py — 校准诊断（读台账）

`
python scripts/brier.py --ledger ../../data/prediction_ledger.jsonl --show-all
python scripts/brier.py --demo
`

- **Brier** = (1/N)Σ(p−o)²，越低越好；恒猜 0.5 且 50/50 事件为 0.25
- **Murphy 分解**：可靠性（越低越好）− 分辨力（越高越好）＋ 不确定性
- **可靠性图**：说 70% 的那批，兑现是不是 70%？点落在对角线上 = 校准良好
- **n 极小时只用于自查，不可对外宣称校准水平**

## 四、我的自审清单（每次给结论前过一遍）

1. **这是预测吗？** 有没有可证伪的表述与结算日？没有 → 先写进台账再出口
2. **基率是多少？** 这件事通常多久发生一次？比我的结论更常见的是什么？
3. **我是不是挑了极端样本？** 是否「挑最差的一批做改善，然后说改善了」？→ 查回归均值
4. **我试了几次？** 如果我在 40 个切法里挑了最好看的那个，阈值必须收紧
5. **是相关还是因果？** 有没有第三个变量同时驱动两者？
6. **样本量够吗？** 效应量多大？检验力够不够？（阴性结果可能只是没测出来）
7. **我的概率诚实吗？** 标 90% 的时候，我愿意按 10% 的代价下注吗？
8. **群体怎么说？** 多个独立来源指向同一结论吗？
9. **和基线比了吗？** 什么都不做会怎样？基线是什么？
10. **这是要用来决策的，还是用来显得确定？** 决策只看期望损失，不是准确率

## 六、诚实边界

1. **书里的案例主要是美国政治、体育、经济、气象** —— 酒店业的基率、检验力、效应分布**没有现成的**，必须自建。这也是我把这本内化落成「工具＋台账」而不是「结论清单」的原因。
2. **signal_audit.py 的检验力是粗略近似**（正态近似）；其价值在于**逼我写清 n、效应量、试了几次**，不是给出精确功效。
3. **regression_to_mean.py 的 r 需实测**，不能拍脑袋给 0.6。
4. **Brier 需要足够样本才有意义**；n<30 的台账只算「留痕」，不算「校准」。
5. **我自己的预测也会错** —— 台账的意义就是把错也记录下来，而不是只留说对的。
6. **书本身不是万能**：西尔弗强调「预测是为了让损失最小化」，不是「追求准确」—— 这条已写进 base_rate.py discovery 的输出。

## 七、维护触发器

- 给出任何**未来判断**（价格、走势、事件、结果、增速）→ 先进台账，再出口
- 拿到一组「改善了」的数据 → 先跑 regression_to_mean.py
- 要用某个检测/评分/信号做决策 → 先跑 base_rate.py screen
- 要宣布「某因素起作用」→ 先跑 signal_audit.py
- 每月结算到期预测 → ledger.py pending → settle → score，看可靠性图是否在漂移
