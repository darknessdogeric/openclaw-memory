# Multi-OTA Price Intelligence Tool (MOTI)

## 定位

**AHL酒店初始定位专用工具**。在零竞品数据前提下，通过多OTA平台抓取 + AI视觉解析 + 入住率加权，还原酒店真实市场价格锚点。

---

## 核心方法论

### 三层数据采集

| 层级 | 平台 | 方法 | 权重建议 |
|------|------|------|----------|
| 主平台 | 携程(Ctrip) | chrome-devtools + AI视觉 | 40% |
| 次平台 | 美团(Meituan) | chrome-devtools + AI视觉 | 30% |
| 补全 | 去哪儿(Qunar) | chrome-devtools + AI视觉 | 20% |
| 验证 | 飞猪(Fliggy) | chrome-devtools + AI视觉 | 10% |

> 如果某平台无该酒店数据，降低其权重重新分配

### OCC加权算法

```
OCC_typical = f(城市等级, 酒店档次, 淡旺季)

真实均价 = Σ(平台均价_i × 平台权重_i × OCC_typical_i) / Σ(平台权重_i × OCC_typical_i)

简化版(无OCC数据时):
真实均价 = Σ(平台均价_i × 平台权重_i)
```

### 标准房判定规则

**优先级**：
1. **关键词法** → 高级间/豪华间/单间/标间 → 纳入
2. **库存数量法** → 原始库存最大2种基础房型 → 纳入
3. **主观判断法** → 命名不规范但能判断主力房型 → 纳入

**排除**：
- ❌ 套房/商务套间
- ❌ 家庭房/亲子房
- ❌ 行政房/复式Loft
- ❌ 泳池别墅/私人泳池

### 价格还原公式

```
挂牌价选项价格 → 应用折扣 → 还原真实裸房收益

参考公式: 真实裸收益 = (挂牌价 - 优惠金额) × 0.85
```

## 标准工作流

### Step 0: 准备阶段
```
输入: 酒店名称 / 携程ID(如有)
```

### Step 1: 多OTA搜索
```
1. 携程: 搜索酒店 → 进入详情页 → 截图
2. 美团: 搜索同一酒店 → 进入详情页 → 截图
3. 去哪儿: 搜索同一酒店 → 进入详情页 → 截图
```

### Step 2: AI价格提取
```
对每个平台截图用 image 工具分析:
- 提取所有房型名称+价格
- 判断是否为标准房(关键词/库存/主观)
- 标注来源平台
```

### Step 3: 数据清洗
```
1. 过滤非标准房
2. 还原真实裸收益
3. 按平台汇总
```

### Step 4: OCC加权计算
```
1. 获取城市等级(一线/二线/三线)
2. 判断酒店档次(钻级/星级)
3. 估算典型OCC:
   - 一线城市高端: OCC≈70-80%
   - 二线城市中端: OCC≈60-70%
   - 三线城市经济: OCC≈50-60%
4. 计算加权均价
```

### Step 5: 输出报告
```json
{
  "hotel_name": "xxx",
  "sources": ["ctrip", "meituan", "qunar"],
  "weighted_adr": 298.5,
  "currency": "CNY",
  "confidence": "high/medium/low",
  "breakdown": {
    "ctrip": { "adr": 305, "weight": 0.4, "rooms": 3 },
    "meituan": { "adr": 285, "weight": 0.3, "rooms": 2 },
    "qunar": { "adr": 292, "weight": 0.2, "rooms": 2 }
  },
  "occ_weighted": true,
  "estimated_occ": 0.68,
  "revpar_estimate": 203
}
```

- [ ] 计算加权均价
- [ ] 输出结构化报告

## 局限性说明

1. **平台覆盖率**：部分小酒店可能仅在1-2个平台有数据
2. **时间截面偏差**：单日价格≠长期均价
3. **OCC估算误差**：典型OCC与实际可能有±15%偏差
4. **房型匹配误差**：各平台房型命名不统一，主观判断有偏差
5. **无真实成交数据**：这是公开数据方法的根本局限

> ⚠️ 此工具输出为"市场定位参考"，非"精确收益数据"。AHL平台运营3-6个月后，用真实成交数据替代估算值。
