## 二、按规模分级的选型决策树

### 2.1 微小型（< 5 家酒店）

**核心特征**：
- 预算 < 5 万/年
- 1-2 个 IT 人员
- 业务优先、数字化辅助

**推荐组合**：

```
钉钉/企微（基础平台）
├── 简道云 / 钉钉宜搭（采购申请 + 审批）
├── 京东企业购（标准物资）
├── 同驿商城（酒店专用物资）
├── 钉钉表格（台账、报表）
└── 钉钉群（沟通协同）
```

**预算**：5-20 万/年
**实施周期**：1-2 周

**选型决策**：
- 不需要专业 SRM
- 不需要专业 WMS
- 不需要 BI（Excel 足够）
- 重点是"先用起来"

### 2.2 小型（5-20 家酒店）

**核心特征**：
- 预算 5-30 万/年
- 1-3 个 IT 人员
- 标准化 + 灵活性平衡

**推荐组合 A**（云原生优先）：

```
钉钉/企微
├── 简道云（流程引擎）
├── 甄云 SRM SaaS（供应商管理）
├── 京东企业购（标准物资）
├── 同驿商城（酒店专用）
├── 简道云（轻量 WMS）
└── 钉钉 + FineBI Lite
```

**推荐组合 B**（行业 SaaS 优先）：

```
钉钉/企微
├── 携程商旅"招采通"（企业协议采购）
├── 同驿商城（酒店专用）
├── 神州一诺（一物一码 + 智能补货）
├── 钉钉钉钉表格（台账）
└── 钉钉机器人（告警）
```

**预算**：30-80 万/年
**实施周期**：1-2 个月

### 2.3 中型（20-50 家酒店）

**核心特征**：
- 预算 30-150 万/年
- 3-5 个 IT 人员
- 体系化建设期

**推荐组合 A**（国内大厂套件）：

```
用友/金蝶 Cloud
├── 用友/金蝶 SRM（供应商管理）
├── 用友/金蝶 WMS（仓储管理）
├── 用友/金蝶 BI（数据分析）
├── 同驿商城（酒店专用物资）
├── 京东企业购（标准物资）
├── 钉钉/企微（协同）
└── API 网关（系统集成）
```

**推荐组合 B**（行业最佳组合）：

```
钉钉/企微
├── 甄云 SRM（行业最佳 SRM）
├── C-WMS（轻量 WMS）
├── FineBI（数据分析）
├── 同驿商城（酒店专用）
├── 京东企业购（标准物资）
├── iPaaS（系统集成）
└── AI 引擎（比价/预测）
```

**预算**：80-200 万/年
**实施周期**：3-6 个月

### 2.4 大型（50-100 家酒店）

**核心特征**：
- 预算 200-500 万/年
- 5-15 个 IT 人员
- 数字化转型期

**推荐组合**：

```
用友 NC Cloud / 金蝶云苍穹（ERP）
├── 用友/金蝶 SRM（供应商全生命周期）
├── 用友/金蝶 WMS（仓储管理）
├── 帆软 FineBI（数据分析）
├── 同驿商城（酒店专用）
├── 京东企业购（标准物资）
├── 钉钉/企微 + RPA（流程自动化）
├── AI 平台（智能比价/预测/补货）
├── 阿里云 iPaaS（系统集成）
└── 区块链平台（溯源）
```

**预算**：300-800 万/年
**实施周期**：6-12 个月

### 2.5 集团型（> 100 家酒店）

**核心特征**：
- 预算 500 万-2000 万/年
- 15+ 个 IT 人员
- 全面数字化

**推荐组合**：

```

├── SAP Ariba / Oracle Procurement Cloud（采购云）
├── SAP EWM（仓储管理）
├── SAP IBP（供应链计划）
├── 自研 BI + AI 平台
├── 行业 SaaS 集成（京东/同驿/神州一诺）
├── 区块链溯源平台
├── 数字孪生平台
├── 自研数据中台
└── 智能决策系统
```

**预算**：800-3000 万/年
**实施周期**：12-24 个月

核心工具：SRM + AI 比价

```
核心工具：WMS + AI 需求预测
辅助工具：SRM、智能补货系统
预算分配：50% WMS + 30% AI + 20% SRM
```

### 痛点 3：供应商质量差

```
核心工具：SRM + 质量追溯系统
辅助工具：一物一码、IoT
预算分配：50% SRM + 30% 追溯 + 20% IoT
```

### 痛点 4：响应速度慢

```
核心工具：移动化 + RPA + 应急系统
辅助工具：钉钉/企微、智能告警
预算分配：40% 移动化 + 30% RPA + 30% 应急
```

### 痛点 5：决策不科学

```
核心工具：BI + 数据中台 + AI
辅助工具：KPI 仪表盘、预测算法
预算分配：50% BI + 30% AI + 20% 数据中台
```

## 四、按部署方式选型

### 4.1 SaaS 模式

**优势**：
- 快速上线（周级）
- 免运维
- 持续更新
- 成本可控（订阅制）

**劣势**：
- 数据安全顾虑
- 定制能力弱
- 长期成本高

**适用**：< 50 家酒店、标准化需求

### 4.2 私有化部署

**优势**：
- 数据安全
- 强定制
- 长期成本低

**劣势**：
- 实施周期长（季度级）
- 需要专业 IT
- 升级困难

**适用**：> 50 家酒店、强定制需求

### 4.3 混合云

**优势**：
- 灵活
- 平衡

**劣势**：
- 复杂度高

**适用**：50-200 家酒店

## 六、3 大选型陷阱

### 6.1 陷阱 1：自研陷阱

**现象**："我们要自研一套 SRM"
**真相**：
- 自研成本 = SaaS 的 10-50 倍
- 自研周期 = 1-3 年
- 自研风险 = 100%（失败率）

**结论**：< 200 家酒店不自研，用成熟 SaaS

### 6.2 陷阱 2：过度定制

**现象**："我们要 100% 符合我们业务"
**真相**：
- 80% 的需求是行业共性
- 20% 的特殊需求应该靠流程优化而非定制

**结论**：少定制，多优化流程

### 6.3 陷阱 3：低价中标

**现象**："这个厂商报价最低，选它"
**真相**：
- 总拥有成本（TCO）才是关键
- 实施成本 = 软件成本的 1-3 倍
- 维护成本 = 年订阅的 20-30%

**结论**：看 TCO，不看采购价
