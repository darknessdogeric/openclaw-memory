# 数据与经营同步方法 v1.0

> **配套主报告**：`01-主报告-酒店供应链工程全维度体系.md` §5 + §6
> **核心命题**：数据 ≠ 经营。**同步** 才是命门。
> **目的**：建立"数据驱动经营、经营反哺数据"的闭环方法

---

## 一、3 大核心命题

| 命题 | 误区 | 真相 |
|------|------|------|
| ① 数据有 ≠ 数据用 | "我们数据库里有所有数据" | 90% 的酒店数据躺在表里没人看 |
| ② 经营有 ≠ 经营准 | "总经理拍脑袋决策" | 经验 + 数据 = 真正的准 |
| ③ 同步难 | "ERP、PMS、CRM 数据不通" | 不是技术问题，是制度问题 |

**核心结论**：同步 = 数据采集 + 加工 + 推送 + 决策 + 反馈 = 5 步闭环

---

## 二、5 步同步闭环（核心模型）

```
经营场景
   ↓
数据采集（自动）
   ↓
数据加工（清洗 + 关联 + 计算）
   ↓
数据推送（仪表盘 + 告警 + 建议）
   ↓
经营决策（人 + AI）
   ↓
效果反馈（反哺数据）
   ↓
（回到经营场景）
```

### 2.1 第 1 步：数据采集（自动 + 实时）

| 维度 | 数据源 | 采集方式 | 频次 |
|------|--------|---------|------|
| 入住 | PMS | API 实时 | 实时 |
| 营收 | PMS / POS | API 实时 | 实时 |
| 库存 | WMS | API 实时 | 实时 |
| 订单 | SRM | API 实时 | 实时 |
| 财务 | ERP | API 定时 | 日 |
| 客户 | CRM | API 实时 | 实时 |
| 设备 | IoT | MQTT | 实时 |
| 外部 | OTA | API 定时 | 时 |
| 市场 | 行业 | 爬虫 | 日 |
| 舆情 | 媒体 | 爬虫 | 日 |

**关键**：所有数据**必须自动采集**，不能人工 Excel 录入。

### 2.2 第 2 步：数据加工

| 加工类型 | 内容 | 工具 |
|---------|------|------|
| 清洗 | 去重、纠错、补全 | SQL / Python |
| 关联 | 订单 ↔ 库存 ↔ 入住 | 关联表 |
| 计算 | KPI、趋势、预测 | 算法 / BI |
| 标签化 | 客户标签、品类标签 | 标签系统 |
| 维度化 | 时间/空间/品类 | OLAP |

**数据加工的关键**：业务可理解 = 加工必须基于业务场景，不是技术炫技

### 2.3 第 3 步：数据推送（不是仪表盘，是建议）

**反模式**：
```
"我们有 BI 仪表盘，30 个图表" → 总经理还是拍脑袋
```

**正模式**：
```
"系统告诉我们：明早 6 点应该补 200 件浴巾，原因是明天入住率 95% 且库存只剩 30%"
```

**4 层推送机制**：

| 层级 | 频次 | 受众 | 内容 |
|------|------|------|------|
| 实时告警 | 实时 | 店长 | 异常告警（库存 < 安全线）|
| 日报推送 | 早 8 点 | 店长/采购 | 当日行动建议 |
| 周报推送 | 周一 | 总监 | 周度复盘 + 建议 |
| 月报推送 | 月初 | 总经理 | 月度经营 + 战略建议 |

**推送工具**：
- 钉钉/企微机器人
- 邮件
- BI 仪表盘
- 短信（紧急）

### 2.4 第 4 步：经营决策（人 + AI）

| 决策类型 | 谁决策 | 数据依赖度 |
|---------|--------|----------|
| 战略决策 | CEO | 80% 数据 + 20% 经验 |
| 战术决策 | 总监 | 60% 数据 + 40% 经验 |
| 日常决策 | 经理 | 50% 数据 + 50% 经验 |
| 操作决策 | 员工 | 30% 数据 + 70% SOP |
| 自动决策 | AI | 95% 数据 |

**AI 自动决策场景（2026 已成熟）**：
- 库存自动补货（阈值触发）
- 价格自动调整（基于竞品/需求）
- 订单自动审核（小额、固定供应商）
- 风险自动告警（供应商异常）

### 2.5 第 5 步：效果反馈（反哺）

**关键**：决策效果必须**反哺**到数据，形成闭环

| 决策 | 效果数据 | 反哺方式 |
|------|---------|---------|
| 补货决策 | 入住率、缺货率 | 校准预测模型 |
| 定价决策 | 出租率、ADR | 校准价格模型 |
| 采购决策 | 库存周转、成本 | 校准品类模型 |
| 供应商决策 | 绩效、服务 | 校准供应商模型 |

**没有反馈 = 没有学习 = 数据浪费**

## 三、3 大同步场景（详细设计）

### 3.1 场景 1：入住率 ↔ 物资消耗（核心同步）

**业务逻辑**：
```
入住率 ↑ → 物资消耗 ↑ → 库存 ↓ → 补货 ↑
```

**数据流**：
```
PMS（入住率）
   ↓
   ↓ API
   ↓
数据中台（清洗 + 关联）
   ↓
   ↓ 计算：物资消耗预测
   ↓
WMS（实时库存）
   ↓
   ↓ 比对：是否需要补货
   ↓
SRM（自动生成采购单）
   ↓
   ↓ 推送给采购员
   ↓
钉钉告警 + 行动建议
```

**算法**：
```
预测消耗 = 入住率 × 系数 × 入住人数 × 入住天数
         + 季节系数
         + 事件系数（会议/节假日）
```

**同步规则**：
- 入住率 < 50%：低频补货（7 天一次）
- 入住率 50-80%：常规补货（3 天一次）
- 入住率 > 80%：高频补货（每天）
- 入住率 > 95%：紧急补货（实时告警）

### 3.2 场景 2：成本 ↔ 营收（经营同步）

**业务逻辑**：
```
营收 ↑ → 物资消耗 ↑ → 成本 ↑
但：物资成本率应保持稳定
```

**同步指标**：
| 指标 | 公式 | 告警线 |
|------|------|--------|
| 物资成本率 | 物资成本/营收 | 超过档次基准 3% |
| 单房成本 | 物资成本/房晚 | 同比超 5% |
| 集采节省率 | 集采节省/应集采 | < 5% |
| 应付账期 | 应付/日均采购 | > 60 天 |

**数据流**：
```
PMS（营收、房晚）
ERP（成本、应付）
   ↓
   ↓ 数据中台
   ↓
KPI 计算
   ↓
   ↓ 告警规则
   ↓
仪表盘 + 钉钉推送
```

### 3.3 场景 3：客户体验 ↔ 物资质量

**业务逻辑**：
```
物资质量 ↓ → 客户体验 ↓ → 复购 ↓
```

**同步指标**：
- 物资相关客诉率
- 物资合格率
- 物资使用反馈

**数据流**：
```
客服系统（投诉）
WMS（物资批次）
   ↓
   ↓ 关联：投诉物资 ↔ 批次 ↔ 供应商
   ↓
供应商绩效更新
   ↓
   ↓ 触发：投诉 > 阈值 → 启动供应商评估
```

## 四、4 大同步机制

### 4.1 主数据同步（Master Data）

**原则**：全集团"一套主数据"
- 供应商主数据：统一编码、统一分类
- 物料主数据：统一 SKU、统一规格
- 客户主数据：统一客户 ID

**实现**：
- 主数据管理平台（MDM）
- 主数据 → 各系统分发
- 各系统不能私自创建

### 4.2 交易数据同步（Transactional）

**原则**：实时同步，不允许数据滞后
- 订单：实时推送 SRM
- 收货：实时推送 WMS
- 付款：实时推送财务
- 入住：实时推送 PMS

**实现**：
- API 实时推送
- 消息队列（Kafka / RocketMQ）
- 事件驱动架构（EDA）

### 4.3 分析数据同步（Analytical）

**原则**：T+1 同步到数据仓库
- 每日数据 ETL
- 月度数据归档
- 实时数据流（BI 看）

**实现**：
- 数据仓库（数仓）
- ETL 工具（Kettle / Airflow / DataX）
- 实时计算（Flink / Spark Streaming）

### 4.4 主-从同步原则

| 数据类型 | 同步方向 | 同步频次 |
|---------|---------|---------|
| 主数据 | MDM → 各系统 | 实时 |
| 交易数据 | 业务系统 → 数据中台 | 实时 |
| 分析数据 | 各系统 → 数仓 | T+1 |
| 报表数据 | 数仓 → BI | 实时 |

## 五、3 大同步技术架构

### 5.1 架构 A：点对点同步（小酒店）

```
PMS ←→ ERP
PMS ←→ CRM
ERP ←→ SRM
```

**适用**：< 10 家酒店
**优势**：简单、快
**劣势**：N² 复杂度

### 5.2 架构 B：ESB 总线同步（中型酒管）

```
PMS ─┐
ERP ─┤
CRM ─┼─→ ESB ─→ SRM/WMS/BI
SRM ─┤
WMS ─┘
```

**适用**：10-50 家酒店
**优势**：标准化、可扩展
**劣势**：ESB 中心化

### 5.3 架构 C：数据中台（大型酒管）

```
PMS ─┐
ERP ─┤
CRM ─┼─→ 数据中台 ─→ 业务系统
SRM ─┤            ↓
WMS ─┘         数据服务
                 ↓
              BI/AI/自动化
```

**适用**：> 50 家酒店
**优势**：数据资产化、智能化
**劣势**：投入大

## 六、3 大同步治理机制

### 6.1 数据质量管理（DQ）

| 维度 | 标准 |
|------|------|
| 完整性 | 必填字段 100% 填写 |
| 准确性 | 抽样准确率 > 99% |
| 一致性 | 跨系统一致率 > 95% |
| 时效性 | T+1 同步 100% |
| 唯一性 | 主数据重复率 < 1% |

### 6.2 数据权限管理

| 层级 | 权限 |
|------|------|
| 总经理 | 全部数据 |
| 总监 | 本部门 + 全 KPI |
| 经理 | 本业务 + 详细数据 |
| 员工 | 自己相关数据 |
| 供应商 | 仅自己数据 |

### 6.3 数据文化建设

- 数据月会：每月分享数据洞察
- 数据培训：每季度一次
- 数据问责：问题数据追责到人
- 数据激励：数据贡献者奖励

## 七、5 大同步红线

| 红线 | 后果 |
|------|------|
| ❌ 禁止 Excel 录入核心数据 | 永远落不了数据中台 |
| ❌ 禁止系统各自为政 | 数据孤岛 |
| ❌ 禁止无主数据 | 重复、口径不统一 |
| ❌ 禁止无反馈 | 数据浪费 |
| ❌ 禁止无治理 | 数据脏乱差 |
