## 二、三层架构详解

### 第一层：一脑 (AHL-LLM 垂类大模型)

```
AHL-LLM 垂类大模型
├── 核心能力
│   ├── 非标语义理解
│   │   ├── 理解"采光好的房间" → 下午2点光照强度>500lux
│   │   ├── 理解"安静" → 夜间噪音<30dB
│   │   ├── 理解"有设计感" → 检索装修风格标签
│   │   └── 理解"适合带娃" → 匹配亲子设施+安全属性
│   │
│   ├── 住宿业知识图谱
│   │   ├── 房源实体：房间、设施、服务、政策
│   │   ├── 商户实体：品牌、位置、特色、口碑
│   │   ├── 用户实体：偏好、历史、画像、场景
│   │   └── 关系网络：相似度、互补性、替代性
│   │
│   ├── 推理与决策
│   │   ├── 需求解析 → 匹配条件 → 候选排序 → 推荐理由
│   │   ├── 动态定价 → 需求预测 → 库存优化 → 收益最大化
│   │   └── 风险识别 → 异常检测 → 预警触发 → 干预建议
│   │
│   └── 多轮对话管理
│       ├── 意图识别与澄清
│       ├── 上下文记忆与关联
│       ├── 主动追问与引导
│       └── 结果确认与转化
│
├── 模型架构
│   ├── 基座模型：DeepSeek / Qwen 微调
│   ├── RAG增强：向量知识库实时检索
│   ├── 工具调用：Function Calling调用PMS接口
│   └── 安全对齐：住宿业合规与价值观
│
└── 训练数据
    ├── 公开数据：OTA评价、攻略内容、酒店标准
    ├── 私有数据：商户深度采集、交易记录、用户行为
    └── 合成数据：对话模拟、场景生成、边界测试
```

### 第二层：一网 (AHL Protocol 协议层)

```
AHL Protocol 协议层
├── 语义接口层 (Semantic Layer)
│   ├── 需求解析API
│   │   └── 输入：自然语言 → 输出：结构化需求
│   │
│   ├── 房源匹配API
│   │   └── 输入：需求向量 → 输出：候选房源列表
│   │
│   ├── 智能问答API
│   │   └── 输入：用户问题 → 输出：自然语言回答
│   │
│   └── 推荐理由API
│       └── 输入：房源ID → 输出：个性化推荐理由
│
├── 数据路由层 (Data Routing Layer)
│   ├── 库存查询路由
│   │   └── 统一查询 → 分发至各PMS → 聚合结果
│   │
│   ├── 价格查询路由
│   │   └── 实时价格获取 → 缓存策略 → 动态更新
│   │
│   ├── 预订创建路由
│   │   └── 订单创建 → PMS推送 → 确认回调
│   │
│   └── 状态同步路由
│       └── 订单状态监听 → 变更通知 → 多端同步
│
└── 交易结算层 (Settlement Layer)
    ├── 支付网关
    │   └── 微信支付、支付宝、信用卡
    │
    ├── 分账系统
    │   └── 直连分账：用户→商户(97%) + 平台(3%)
    │
    ├── 结算对账
    │   └── 日终对账、差异处理、资金清算
    │
    └── 发票服务
        └── 电子发票、自动开票、抬头管理
```
