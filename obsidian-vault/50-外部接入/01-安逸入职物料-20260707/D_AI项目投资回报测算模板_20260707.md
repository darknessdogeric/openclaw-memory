# D. AI 项目投资回报（ROI）测算模板

> **用途**：集团所有 AI 项目的"算账"统一模板
> **核心原则**：不为 AI 而 AI · 不烧钱 · 不脱实向虚
> **生成时间**：2026-07-07
> **版本**：v1.0 草案

---

## 一、使用说明

### 1.1 适用场景

- 任何 AI 项目立项前必须填本模板
- 任何 AI 项目阶段性评估必须更新本模板
- 任何 AI 项目结项必须用本模板复盘

### 1.2 必填项

- 项目基本信息
- 投入明细（一次性 / 持续性 / 显性 / 隐性）
- 收益明细（直接 / 间接 / 短期 / 长期）
- 风险评估
- 决策建议

### 1.3 责任人

- 填表人：项目负责人
- 审核人：产业发展部 + 财务部
- 决策人：班子

### 2.4 投资回报计算

| 指标 | 计算公式 | 数值 | 说明 |
|------|---------|------|------|
| 净收益（Year 1）| = 总收益 - 总投入 | | |
| 投资回报率（ROI）| = 净收益 / 总投入 × 100% | | |
| 投资回本期 | = 总投入 / 年化净收益 | | 月数 |
| 5 年总收益 | = 累计 5 年收益 | | 假设前 1 年爬坡 + 2-3 年稳定 |
| 5 年总投入 | = 累计 5 年投入 | | 假设持续性投入 |
| 5 年净收益 | = 5 年总收益 - 5 年总投入 | | |
| 5 年 ROI | = 5 年净收益 / 5 年总投入 × 100% | | |

### 2.5 敏感性分析（5 档）

| 情景 | 收益调整 | 投入调整 | 净收益 | ROI | 决策 |
|------|----------|---------|--------|------|------|
| 极保守 | 50% | 100% | | | 不投 / 慎投 |
| 保守 | 75% | 100% | | | 试点 |
| 中性 | 100% | 100% | | | 立项（基准）|
| 乐观 | 125% | 110% | | | 加快 |
| 极乐观 | 150% | 120% | | | 加码 |

> 注：核心是"如果项目只实现 50% 效果，ROI 是否仍为正" — 是则可投

## 三、风险评估

### 3.1 风险矩阵（4 维）

| 风险类别 | 风险描述 | 严重度（1-5）| 概率（1-5）| 风险值 | 应对措施 |
|---------|---------|------------|---------|--------|---------|
| **技术风险** | 算法效果不达预期 | | | | 算法选型 + 试点验证 |
| | 系统集成困难 | | | | API 设计 + 兼容性测试 |
| | 数据质量差 | | | | 数据治理前置 |
| **业务风险** | 业务部门不配合 | | | | 高层挂帅 + 业务主导 |
| | 业务人员抵触 | | | | 培训 + 激励机制 |
| | 客户不接受 | | | | 小范围试点 |
| **财务风险** | 投入超预算 | | | | 阶段评估 + 止损机制 |
| | 收益不达预期 | | | | 保守测算 + 备份方案 |
| | 算力成本失控 | | | | 算力合同控制 |
| **组织风险** | 关键人才流失 | | | | 团队备份 + 知识沉淀 |
| | 项目责任不清 | | | | 明确 RACI |
| | 跨部门协调难 | | | | 项目经理制 |
| **合规风险** | 数据安全 | | | | 国密算法 + 权限管理 |
| | 隐私保护 | | | | 数据脱敏 + 合规审查 |
| | 知识产权 | | | | 法务审核 + 专利布局 |

> 风险值 = 严重度 × 概率（> 15 红色 / 10-15 黄色 / < 10 绿色）

### 3.2 退出机制

- **止损线**：项目 ROI 持续 6 个月 < 50% 预期 → 启动退出评估
- **退出方式**：暂停 / 缩范围 / 转型 / 完全终止
- **退出成本**：已投入沉没成本 + 退出额外成本
- **退出责任人**：立项时明确

## 六、AI 项目组合管理

### 6.1 组合策略

| 项目类型 | 占比 | 说明 |
|---------|------|------|
| 必投（高 ROI）| 50% | 动态定价 / 智能排班 / 评论分析 |
| 可投（中 ROI）| 30% | 智能客服 / 智能营销 / 客诉预判 |
| 慎投（需试点）| 15% | 能耗优化 / 数据中台 / 数据资产 |
| 不投 | 5% | 通用大模型应用 / 元宇宙 / 数字人 |

### 6.2 组合管理

- 季度组合评审
- 单项目独立 ROI 评估
- 组合协同效应评估
- 资源动态调配

### 6.3 风险分散

- 不把所有 AI 预算压在 1-2 个项目
- 至少 3-5 个项目并行
- 项目之间不能强依赖

## 七、跟踪与复盘

### 7.1 跟踪机制

- **周报**：项目进度 + 关键指标
- **月报**：投入 vs 预算 + 收益 vs 预期
- **季报**：项目组合评审 + 调整建议
- **年报**：年度复盘 + 下一年规划

### 7.2 复盘机制

- 立项后 3 个月：**早期复盘**（是否继续）
- 立项后 6 个月：**中期复盘**（是否扩大）
- 立项后 12 个月：**年度复盘**（是否升级或终止）
- 立项后 24 个月：**长期复盘**（是否成为标准）

## 九、关键原则

### 9.1 算账原则

1. **算账优先** — 每个项目必须有 ROI 测算
2. **保守测算** — 宁可低估收益，不要高估
3. **全成本** — 显性 + 隐性 + 机会成本都要算
4. **退出机制** — 任何项目都要预设退出条件
5. **持续跟踪** — 投入 / 收益 持续跟踪，及时调整

### 9.2 红线

- ❌ 不为 AI 而 AI（业务价值驱动）
- ❌ 不烧钱（任何项目必须有 ROI）
- ❌ 不脱实向虚（必须落地到具体业务）
- ❌ 不照搬互联网模式（考虑集团实际）
- ❌ 不孤立看待单个项目（看组合）
- ❌ 不承诺必成功（任何项目都有失败可能）
