## 二、协议定位（一句话）

> **"安逸酒店 Agent 协议"（简称 AHAP - An Yi Hotel Agent Protocol）是面向中国酒店行业的开放 Agent 协议标准，由安逸酒店集团发起并主导，定义酒店业上下游 Agent 互联互通、数据交换、能力调用的技术规范。**

### 2.1 协议三大类比

| 类比对象 | 类比逻辑 |
|---------|---------|
| 阿里千问协议 | 通用 Agent 协议（跨行业）|
| 苹果 HomeKit | 智能家居互联协议 |
| 谷歌 Android | 移动操作系统协议 |

### 2.2 协议核心定位

- **不是产品**（不直接卖给酒店）
- **不是平台**（不自建应用）
- **是协议**（让别人按这个标准做应用）
- **类似 MCP / A2A**（技术规范）
- **是连接器**（让酒店 + 上下游 + AI 应用无缝对接）

## 三、协议架构（4 层）

### 3.1 整体架构

```
┌─────────────────────────────────────────────────┐
│  Layer 4：Agent 应用层（第三方开发）              │
│  客房 Agent · 餐饮 Agent · 营销 Agent · 等等      │
├─────────────────────────────────────────────────┤
│  Layer 3：Agent 能力层（集团提供）                │
│  智能客服 · 动态定价 · 评论分析 · 智能排班 · 等等  │
├─────────────────────────────────────────────────┤
│  Layer 2：协议层（AHAP 核心）                      │
│  数据交换协议 · Agent 调度协议 · 能力调用协议      │
├─────────────────────────────────────────────────┤
│  Layer 1：基础设施层（外部依赖）                  │
│  大模型 · 算力 · 酒店 PMS/CRM/CDP 系统            │
└─────────────────────────────────────────────────┘
```

### 3.2 4 层详解

#### Layer 1：基础设施层（外部依赖）
- 大模型：千问 / 豆包 / 文心 / DeepSeek / 自研（视情况）
- 算力：阿里云 / 腾讯云 / 自建机房
- 酒店 IT 系统：PMS / CRM / CDP / RMS / POS / IoT

#### Layer 2：协议层（核心 · 集团自主）
- **数据交换协议（AHAP-DEP）**
  - 客户数据格式、会员数据格式、订单数据格式
  - 数据脱敏规则、数据权限规则
  - 数据交换频率、传输协议
- **Agent 调度协议（AHAP-ASP）**
  - Agent 注册规范、Agent 发现机制
  - 多 Agent 协同协议、Agent 调用链规则
  - Agent 状态管理、错误处理
- **能力调用协议（AHAP-CCP）**
  - 酒店能力封装（订房 / 改单 / 入住 / 退房 / 评价）
  - 上下游能力封装（餐饮 / 洗衣 / 接送 / 维修）
  - 第三方能力对接（OTA / 支付 / 地图 / 天气）

#### Layer 3：Agent 能力层（集团提供基础能力）
- 智能客服 Agent
- 动态定价 Agent
- 评论分析 Agent
- 智能排班 Agent
- 能耗优化 Agent
- 客诉预判 Agent
- 数据报表 Agent
- 智能营销 Agent
- 内容生成 Agent
- 智能巡检 Agent

#### Layer 4：Agent 应用层（生态开发）
- 第三方开发者基于 AHAP 开发酒店行业应用
- 集团内部子公司基于 AHAP 开发业务应用
- 集团加盟商基于 AHAP 开发单店应用

## 四、协议核心 API 规范（示例）

### 4.1 数据交换 API

```yaml
# 客户档案数据格式
customer_profile:
  customer_id: string # 客户唯一标识
  name: string # 姓名（脱敏）
  phone: string # 手机号（脱敏）
  vip_level: enum # VIP 等级（普通/银卡/金卡/白金/钻石）
  preferences: object # 偏好（房型/早餐/楼层/特殊要求）
  stay_history: array # 入住历史
  total_stays: integer # 累计入住次数
  total_spend: decimal # 累计消费
  last_stay_date: date # 最后入住日期
  tags: array # 客户标签（商务/亲子/银发/会议/入境）
```

### 4.2 Agent 调度 API

```yaml
# Agent 调用请求
agent_request:
  agent_id: string # Agent 标识（如 "pricing-agent"）
  request_id: string # 请求 ID
  context: object # 上下文（酒店 ID/时段/触发条件）
  parameters: object # 参数
  timeout: integer # 超时（秒）
  callback_url: string # 回调 URL

# Agent 调用响应
agent_response:
  request_id: string
  status: enum # success/failed/timeout
  result: object # 结果
  error: object # 错误信息
  execution_time: integer # 执行时长（毫秒）
```

### 4.3 能力调用 API

```yaml
# 订房能力调用
capability_request:
  capability: "create_booking" # 能力名称
  hotel_id: string # 酒店 ID
  room_type: string # 房型
  check_in: date # 入住日期
  check_out: date # 退房日期
  guest_count: integer # 客人数
  customer_id: string # 客户 ID
  source: string # 渠道（OTA/官网/小程序/Agent）
  price: decimal # 价格
```

## 五、生态合作策略

### 5.1 协议开放层级

| 层级 | 开放范围 | 合作模式 |
|------|---------|---------|
| **公开** | 数据格式、API 规范 | 开源协议，任何人都能看 |
| **受限** | Agent 能力调用 | 注册申请 + 资质审核 + 计费 |
| **专有** | 集团内部 Agent | 不开放 |
| **战略** | 头部合作伙伴 | 深度共研 + 数据共享 + 收益分成 |

### 5.2 合作伙伴分类

#### 战略级（5-10 家）
- 头部 OTA（携程、美团、飞猪、同程）
- 头部 PMS 厂商（石基、别样红、软云天下）
- 头部 CDP/RMS 厂商
- 头部云厂商（阿里云、腾讯云、华为云）
- 头部咨询公司（麦肯锡、BCG、贝恩、罗兰贝格）

#### 核心级（20-30 家）
- 中型 PMS / CRM / RMS 厂商
- 酒店用品供应链（布草、食材、设备）
- 酒店培训认证机构
- 行业媒体与协会

#### 生态级（50+ 家）
- 中小型开发者
- 行业 SaaS 提供商
- 高校与研究机构

### 5.3 收益模式

| 模式 | 收入来源 | 适用对象 |
|------|---------|---------|
| API 调用费 | 按调用次数收费 | 第三方开发者 |
| 数据服务费 | 数据脱敏后服务 | 行业研究机构 |
| 战略合作分成 | Agent 商业化分成 | 战略合作伙伴 |
| 认证服务费 | 协议合规认证 | 厂商 |
| 培训认证费 | 协议实施培训 | 行业从业者 |
