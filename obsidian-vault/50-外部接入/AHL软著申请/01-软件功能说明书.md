## 一、软件概述

### 1.1 软件用途

宿语AI住宿服务系统（简称"宿语系统"）是一款面向住宿业（民宿、酒店、客栈）的智能对话预订系统。系统以自然语言对话为核心交互方式，通过多Agent协同架构，实现客户咨询、房源推荐、在线预订、支付对接的全链路智能化。

与传统的OTA平台不同，本系统不是"搜索-比价-下单"的货架模式，而是"理解-推荐-服务"的对话模式。客户通过自然语言描述需求，系统理解其情绪和意图后，直接完成预订，无需切换页面。

### 1.2 目标用户

- **C端（客户）**：计划出行、寻找住宿的消费者，以大理等旅游目的地为主要场景
- **B端（房东/商家）**：民宿业主、酒店管理者，通过AI辅助完成客户咨询和房源管理
- **C端（房东版）**：商家以AI管家身份与客户对话，处理预订和管理

### 1.3 运行环境和依赖

```
后端依赖：
- Python 3.x
- Flask（Web框架）
- Flask-SQLAlchemy（ORM）
- requests（HTTP调用）
- python-dotenv（环境变量）
- DeepSeek API（LLM调用）

前端依赖：
- Vue 3
- Vite（构建工具）
- axios（HTTP客户端）

基础设施：
- SQLite（数据库，默认）
- DeepSeek API Key（需用户配置）
```

### 2.2 技术特点

本系统采用前后端分离架构，后端基于Flask提供REST API，前端基于Vue3构建单页应用。核心AI能力由DeepSeek大语言模型驱动，通过多Agent协同架构实现复杂业务逻辑的解耦和扩展。

### 3.1 Master Agent（主协调Agent）

**文件**：`backend/app/agents/master_agent.py`

**功能描述**：主协调Agent是整个系统的路由中枢，负责接收来自前端的请求，根据请求类型（客户对话/房东管理/支付/预订）将请求分发到对应的子Agent，并汇总子Agent的响应返回给前端。

**核心功能**：

- 子Agent生命周期管理（延迟初始化、实例缓存）
- 统一响应格式封装

**关键接口**：
```
route_request(request_type: str, data: Dict) → Dict
get_homestay_agent(homestay_id: str) → HomestayAgent
```

### 3.2 Customer Agent（客户Agent）

**文件**：`backend/app/agents/agents.py`

**功能描述**：客户Agent是C端的核心业务处理器，负责处理客户的所有对话请求，包括：意图识别、对话式预订流程管理、多轮上下文记忆、房源推荐、响应生成。

**核心功能**：

#### 3.2.1 意图识别与路由
系统根据客户消息内容，自动识别其意图类型（预订/价格咨询/房源详情/景点推荐/闲聊等），并调用对应的处理逻辑。

#### 3.2.2 会话式预订状态机
预订流程以状态机形式管理，支持分步信息收集（选房型→选日期→收集联系方式→自动下单），支持暂停/继续/取消等对话管理语义。

```python
booking_flow = {
    'active': bool,        # 是否在预订流程中
    'room_id': str,       # 已选房型
    'check_in': date,     # 入住日期
    'check_out': date,    # 退房日期
    'customer_name': str, # 入住人姓名
    'customer_phone': str,# 手机号
    'guests_count': int   # 入住人数
}
```

#### 3.2.3 情绪意图覆盖
系统会根据对话历史动态调整意图判断，确保多轮对话的连贯性。当用户在预订流程中发送闲聊消息时，系统能够智能判断是否暂停预订流程。

#### 3.2.4 预订流程处理
- 自动校验手机号格式（11位中国手机号）
- 自动校验入住/退房日期逻辑（退房必须晚于入住）
- 房间可用性实时检查
- 订单自动创建和状态管理
- 超额入住人数预警和换房引导

### 3.3 MultiLevelVectorKB（多级向量知识库）

**文件**：`backend/app/services/multilevel_vector_kb.py`

**功能描述**：本系统的核心创新模块，实现了基于语义层次的知识库检索系统。区别于传统的关键词匹配或扁平向量检索，本系统将知识库划分为三个语义层次，针对不同意图自动选择对应层次进行检索和生成约束。

**三层语义架构**：

| 层次 | 语义类型 | 关键词示例 | Guardrail规则 |
|------|---------|-----------|-------------|
| 情绪层（EMOTION） | 放松、治愈、安静、浪漫、陪伴 | 放松/解压/心情/焦虑 | 不得提及房源/价格/预订 |
| 感官层（SENSORY） | 风景、海风、阳光、日出日落 | 风景/气味/声音/温度 | 不得提及房源/价格/预订 |
| 房源层（ROOM） | 房型、价格、位置、设施 | 预订/价格/房型/退房 | 正常业务，可推荐和引导 |

**向量检索实现**：
- 基于MD5哈希的Token化（无需外部Embedding模型）
- TF-IDF加权
- 256维向量空间
- 点积相似度计算

**关键方法**：
```python
select_layer(intent, message) → str  # 根据意图选择语义层
search(layer, query, rooms, top_k) → List  # 检索指定层
render_context(layer, results) → str  # 渲染检索结果为文本
get_guardrail(layer) → str  # 获取当前层的Guardrail约束
violates_guardrail(text, layer) → bool  # 检测是否违反Guardrail
safe_fallback(layer) → str  # Guardrail触发时的兜底话术
```

### 3.4 RecommendationEngine（智能推荐引擎）

**文件**：`backend/app/services/recommendation_engine.py`

**功能描述**：负责根据用户需求（自然语言描述）对房源进行多维度评分和排序，生成个性化的推荐理由。

**用户需求分析维度**：
- 预算区间（便宜/中等/高端）
- 入住人数（单人/情侣/家庭/团队）
- 位置偏好（古城/山间/洱海）
- 风格偏好（文艺/豪华/度假）
- 关键词匹配（安静/景观/私密等）

**评分体系（满分100分）**：
- 预算匹配度：30分
- 容纳人数匹配度：25分
- 位置偏好匹配度：25分
- 风格偏好匹配度：20分
- 关键词命中：额外加分（上限15分）

## 四、输入输出说明

### 4.1 典型对话流程示例

**输入（用户）**：我想去大理住几天，想放松一下，有洱海景观最好

**系统处理流程**：
1. 意图识别 → `general`（泛化需求）
2. 语义层选择 → EMOTION（情绪层：放松）
3. 知识库检索 → 在情绪库中检索相关内容
4. 房源推荐 → 调用RecommendationEngine，按洱海偏好筛选和评分
5. LLM生成 → DeepSeek生成自然语言推荐

**输出（系统）**：
> "大理真是个适合放松的地方……说到洱海，我想起一个词——'湖光山色'。清晨的洱海，太阳从苍山背后慢慢升起来，湖面像镜子一样平静。
> 
> 如果想要躺在床上就能看到洱海日出，我推荐【房型A】（洱海全景大床房），躺在床上就能看到湖面。而且房间里有一股淡淡的木质香气，让人特别安心。"

### 4.2 预订流程示例

**输入**：我想订第二套，3月15日入住，18日退房，张三，13812345678

**系统处理**：
1. 识别为booking意图
2. 解析房型（第二套）→ 匹配到具体room_id
3. 解析日期 → check_in=2026-03-15，check_out=2026-03-18
4. 解析联系方式 → customer_name=张三，customer_phone=13812345678
5. 校验手机号格式 → 通过
6. 检查房间可用性 → 可用
7. 创建订单 → 返回订单详情

**输出**：
> "已为您下单【房型名】，3月15日入住，18日退差（共3晚），总价¥XXX。
> 
> 订单号：XXXXXX  
> 状态：待确认  
> 房东将在XX小时内联系您确认。"
