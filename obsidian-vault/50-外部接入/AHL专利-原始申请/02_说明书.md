# 说明书

## 技术领域

本发明涉及人工智能与住宿业融合的技术领域，具体涉及一种基于双向AI智能匹配的去中心化住宿交易方法及系统，尤其涉及通过自然语言交互与向量匹配引擎实现用户需求与商户服务精准对接的技术方案。

## 背景技术

### 1. 现有住宿交易模式的问题

当前住宿行业主流交易模式以OTA（在线旅游代理商）平台为核心，用户通过关键词搜索、比价、筛选完成预订。这一模式存在以下结构性缺陷：

| 问题维度 | 具体表现 |
|---------|---------|
| 信息过载 | 用户需在海量房源中逐一浏览，平均决策时间超过30分钟 |
| 单向推送 | 平台基于销量和佣金高低排序，用户被动接受"货架逻辑" |
| 数据垄断 | 用户行为数据、偏好数据被平台独占，商户无法获取 |
| 高佣金抽成 | OTA平台抽取15%-25%的交易佣金，压缩商户利润空间 |
| 需求失配 | 用户实际需求（如"有故事的老房子"）无法通过关键词检索表达 |

### 2. 现有AI客服的局限

现有酒店AI客服多基于规则匹配或简单的FAQ检索，存在以下问题：
- 无法理解用户的非结构化自然语言需求
- 无法捕捉"氛围感""故事性"等主观软性偏好
- 缺乏跨平台商户资源的整合能力
- 无法实现动态定价与精准营销的联动

### 3. 深水数据缺失

传统OTA平台仅采集结构化数据（价格、位置、评分），而以下对决策至关重要的非标准数据长期缺失：

- 光照指数（房间朝向与采光质量）
- 噪音分贝（夜间环境噪声水平）
- 房源氛围语义标签（"复古""温馨""工业风"等）
- 主理人背景与故事（民宿的人格化特征）
- 周边在地文化故事（非标准化旅游资源）

这些数据被称为"深水数据"，是实现真正精准匹配的关键资产。

## 发明内容

### 1. 本发明要解决的技术问题

本发明旨在解决现有住宿交易模式中需求匹配精度低、数据孤岛严重、佣金成本过高、用户决策负担重等技术问题。

### 2. 技术方案概述

本发明提出一种基于双向AI智能匹配的去中心化住宿交易方法，核心思路是：

用户侧：自然语言需求 → AI理解 → 精准匹配 → 最合适的3-5家推荐
商户侧：服务能力封装 → 精准推送 → 目标客群主动获取

通过向量检索技术，将用户需求与商户服务同时映射到高维语义空间，实现超越关键词匹配的语义级精准对接。

### 3. 核心创新点

创新点一：非标准数据的向量化封装
传统住宿数据仅包含结构化字段，本发明首次将非标准数据（氛围、主理人故事、光照指数、噪音分贝等"深水数据"）纳入向量化体系，显著提升匹配精度。

创新点二：双向AI智能体协同架构
本发明设计了C端AI管家与B端AI运营官的双Agent协同机制：C端Agent负责理解用户、匹配合适商户；B端Agent负责封装商户能力、主动运营客户；两者通过共享向量数据库实现数据互通与反馈闭环。

创新点三：多轮对话式需求澄清
当单一轮次匹配的置信度不足时，系统主动触发多轮对话，通过递进式提问逐步收窄需求范围，确保匹配结果的可信度。

创新点四：去中心化数据归属
用户数据与商户数据存储于分布式节点，数据归属权归用户与商户本身，平台仅提供技术匹配服务，不对数据进行垄断。

## 具体实施方式

### 实施例一：C端用户匹配场景

**场景描述**：用户说"我想住大理古城带院子的民宿，喜欢有故事的老房子，预算500元左右"

**处理步骤**：

1. **语义理解**：识别关键词——"大理古城"（地理位置）、"带院子"（房型特征）、"有故事的老房子"（软性偏好）、"500元"（价格约束）

2. **向量生成**：
   - 硬性约束：地理位置=大理古城，价格区间=400-600元
   - 软性偏好：氛围语义="历史感""故事性""老房子"，映射至氛围向量维度

3. **Top-K检索**：在商户向量数据库中检索，返回Top-5候选商户

4. **结果呈现**：
   - 商户A（评分4.8，院子里有百年古树，主人是白族手工匠人）
   - 商户B（评分4.7，改建于清代老宅，主理人是本地作家）
   - （以此类推）

5. **推荐理由**：每家商户附带AI生成的推荐理由，解释为何该商户符合用户需求

### 实施例二：B端商户运营场景

**场景描述**：某大理古城民宿完成房源信息录入，包括标准数据与非标准深水数据

**处理步骤**：

1. **数据向量化**：
   - 标准属性：位置=大理古城东门，房型=独立小院，价位=480元/晚，评分=4.8
   - 非标准属性：氛围="百年白族老宅，院子里有石榴树和古井"，主理人故事="主人是老裁缝，收藏了一批老物件"，光照指数=优（东朝向），噪音分贝=低（位于巷尾）

2. **动态定价**：AI运营官结合实时市场需求、竞品价格、库存状态，自动生成建议定价区间

3. **精准推送**：当C端用户需求向量与该商户向量相似度超过阈值时，自动将房源推荐至该用户

4. **反馈优化**：记录用户的点击、咨询、预订、点评数据，回传至B端运营模块，持续优化商户向量表征

### 实施例三：多轮对话澄清场景

**场景描述**：用户需求模糊——"我想找个特别的地方"

**处理步骤**：

1. **初次匹配置信度低**：需求向量与现有商户向量的最大相似度低于0.6阈值

2. **触发多轮对话**：
   - 第一轮："您希望的住宿环境是安静还是热闹？"
   - 第二轮："您偏好历史感还是现代设计？"
   - 第三轮："您希望周边有什么特色体验？"

3. **逐轮收窄**：每轮回答更新需求向量，逐步提升置信度

4. **最终输出**：置信度达到0.8以上时，返回Top-3推荐及理由
