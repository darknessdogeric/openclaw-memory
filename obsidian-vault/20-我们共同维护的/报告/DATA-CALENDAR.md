## 三、分层报告体系

### 两档报告机制（精简版）

```
┌──────────────────────────────────────────────────┐
│              节假日报告分层体系                     │
├─────────────┬────────────────┬───────────────────┤
│  档次        │  预测          │  复盘              │
├─────────────┼────────────────┼───────────────────┤
│ Preliminary │ T-7 预订趋势    │ T+1~T+2 快报（不采）│
│ Final       │ T-2 综合预测    │ T+7 完整复盘 ✅     │
│ Supplement  │ —              │ T+14 补充更新（可选）│
└─────────────┴────────────────┴───────────────────┘
```

### 报告输出格式规范

每份报告必须包含：
1. **数据来源标注**：每个数据点标注来源 + 发布时间 + 置信度
2. **预测偏差分析**：预判值 vs 实际值，计算偏差率
3. **置信度标注**：
   - 🟢 官方/高频精确
   - 🟡 平台抽样/模型推算
   - 🔴 假设/预估值

## 八、预测-复盘对比迭代框架（新增）

### 核心原则
- **先预测，后复盘**：每次节假日必须先有预测报告，才能出复盘报告
- **复盘必须对比预测**：复盘不是独立行为，必须逐项与预测对照找偏差
- **逐次迭代优化**：每次偏差写入 `memory/reports/预测精度迭代记录.md`

### 进化三阶段
| 阶段 | 覆盖范围 | 精度目标 |
|------|---------|---------|
| Phase 1: 公版（当前） | 全国/城市分级/档次 | ±5% |
| Phase 2: 区域版 | 具体省份/城市群 | ±3% |
| Phase 3: 集团/公司版 | 具体集团/单体酒店 | ±1% |

### 对比分析维度
每次复盘必须覆盖：全国总量/城市分级/档次分级/区域/高峰日/渠道结构/客源结构

### 迭代信号触发
| 信号 | 条件 | 动作 |
|------|------|------|
| 🟢 | 偏差<3%维度≥8/10 | 记录最佳实践 |
| 🔴 | 偏差>5%维度≥3/10 | 触发模型复查 |
| 🔴 | 方向预测错误 | 触发深度归因 |
