### 1.2 关键问题清单

> 见面时必须问清楚的关键问题，按优先级排序

**P0（必须问）**

```
问题1：您们现在用的是什么PMS系统？
目的：确定后续技术对接方案
答案将决定是走蓝凤凰API路径还是Opera路径
现场行动：如果对方不确定，直接问"前台电脑上的系统叫什么名字"

问题2：携程后台的EBK数据开通了吗？
目的：确认能否快速获取OTA数据
答案：开通了→可以5分钟导出数据；没开通→需要指导开通
现场行动：如果没开通，现场指导开通

问题3：历史数据可以导出来吗？
目的：确认能否获取历史订单用于基准分析
答案：可以→问能导多久的数据；不可以→问原因
现场行动：如果可以，现场导出第一批数据

问题4：谁负责和OTA对接？
目的：找到正确的对接人
答案：前台经理/销售经理/店长
现场行动：确认后互加微信
```

**P1（应该问）**

```
问题5：总共有多少间客房？
目的：用于ADR/OCC计算基准
问题6：携程和美团各占多少产量比例？
目的：了解OTA渠道重要性
问题7：酒店的定位是什么档次？
目的：竞品选择依据
问题8：什么时候做夜审？
目的：确定数据更新频率
```

**P2（了解即可）**

```
问题9：最近有没有收到差评？
问题10：竞品酒店有哪些？
问题11：有没有和旅行社/团队合作？
问题12：节假日/旺季的价格策略是什么？
```


## 三、数据获取SOP

### 3.1 历史订单数据获取

**目标**：获取最近30天订单数据

**步骤**：

```
Step 1：找对人
→ 前厅经理或财务经理
→ 问："我想导一份最近1个月的订单数据，不知道找谁？"

Step 2：说明用途
→ "我们是AHL团队，帮酒店做收益管理的。
   想分析一下咱们的数据，不会对外传播。"

Step 3：提供模板
→ 给出标准Excel模板（字段说明）
→ 或让酒店按PMS默认格式导出

Step 4：确认格式
→ 收到数据后，当场检查字段是否完整
→ 确认日期格式、金额格式
→ 问清楚字段含义

Step 5：签字留存
→ 如果涉及数据安全，签署承诺书
→ 留下联系方式
```

**标准导出字段要求**：

| 必填字段 | 说明 |
|---------|------|
| 订单号 | 唯一标识 |
| 入住日期 | 格式YYYY-MM-DD |
| 离店日期 | 格式YYYY-MM-DD |
| 房型 | 中文名称 |
| 房费 | 数字 |
| 客人姓名 | 用于去重 |
| 订单来源 | 携程/美团/前台/会员等 |

## 五、风险应对预案

### 5.1 场景：PMS是没见过的小众系统

**概率**：30%
**应对**：降级到全手工Excel

```
处理步骤：

1. 不慌张，微笑："这个系统我没见过，但没关系。"

2. 问关键问题：
   - "这个系统能导出Excel吗？"
   - "历史数据能查到吗？"
   - "有没有数据报表功能？"

3. 如果能导出Excel：
   - 现场下载导出模板
   - 让酒店人员操作导出
   - 记录导出格式

4. 如果不能导出：
   - 降级方案：只使用携程EBK数据
   - EBK数据可以计算ADR/OCC/RevPAR
   - 暂时不接入PMS

5. 后续：
   - 记录这个PMS系统信息
   - 回公司后研究该系统的数据导出方式
   - 2周内给出适配方案
```

### 5.2 场景：酒店不愿意给数据

**概率**：40%
**应对**：强调数据安全，以demo换信任

```
处理步骤：

1. 表示理解：
   "完全理解您的顾虑，数据安全确实很重要。"

2. 强调安全措施：
   - "我们的数据处理是在酒店内网进行的，不会上传到外部服务器。"
   - "我们可以签数据安全协议，约束数据使用范围。"
   - "数据只用于酒店自己的收益分析，不会对外传播。"

3. 先给demo：
   "这样，我先不拿数据走。
   您导出一份给我看看，我在现场给您分析一个demo。
   如果觉得有用，我们再考虑后续合作。"

4. 如果还是不行：
   - 放弃PMS数据
   - 只用携程EBK数据（酒店自己的数据，对方通常更愿意给）
   - 展示EBK数据能做出的分析效果

5. 后续：
   - 保持联系
   - 定期发送行业报告
   - 等信任建立后再尝试
```

### 5.3 场景：携程EBK账号没开通

**概率**：50%
**应对**：现场指导开通

```
处理步骤：

1. 问："携程后台能登录吗？"
   → 能登录 → 直接导出
   → 不能登录 → 继续下一步

2. 找携程对接业务员：
   "这个需要联系携程的业务员帮忙开通，您有对接人吗？"

3. 如果找不到对接人：
   → 打携程客服：1010-6666
   → 说明要开通EBK数据导出权限

4. 如果暂时无法开通：
   → 降级方案：让酒店销售手动截图携程后台数据
   → 或者：3天内等账号开通后再导数据

5. 记录：
   - 携程对接业务员姓名+电话
   - 开通预计时间
```

### 5.4 场景：竞品爬虫被封

**概率**：20%
**应对**：降级到手动录入

```
处理步骤：

1. 发现爬虫失败（系统告警或手动检查）
   → 不慌张，这很正常

2. 检查失败原因：
   - 是IP被封？
   - 是页面改版？
   - 是目标酒店下架？

3. 降级方案：
   - 如果是IP被封：降低爬虫频率（每日1次→每周3次）
   - 如果是页面改版：更新解析逻辑
   - 如果持续失败：降级到手动录入竞品价格

4. 手动录入方案：
   → 每周让酒店销售手动记录竞品价格
   → 填写到指定Excel模板
   → AHL系统自动导入处理

5. 后续：
   → 使用代理池（如果频繁被封）
   → 考虑斥候数据服务（付费方案）
```

### 5.5 场景：数据和酒店报表对不上

**概率**：40%
**应对**：以酒店为准，找原因

```
处理步骤：

1. 不争论，先认错：
   "可能我们的计算方式和酒店不一样，我们来核对一下。"

2. 找出差异点：
   - 邀请酒店前厅经理或财务经理一起核对
   - 逐项对比：入住率、ADR、RevPAR
   - 找出差异最大的指标

3. 常见差异原因：
   - 房量定义不同：是否含不可售房？
   - 收入定义不同：是否含早/餐/服务费？
   - 时间定义不同：夜审前后数据不同
   - 数据源不同：PMS数据 vs 财务数据

4. 调整计算逻辑：
   - 按照酒店的计算口径调整AHL系统
   - 调整后重新验证

5. 如果找不出原因：
   - 暂时以酒店数据为准
   - AHL数据仅供参考
   - 记录差异原因
   - 后续继续优化

6. 记录：
   - 差异原因分析
   - 调整后的计算逻辑
   - 确认签字
```

| 确认携程EBK | 前厅经理/销售经理 | "携程后台的数据能帮我看一下吗？" |
| 竞品信息 | 销售经理 | "我想了解一下，咱们这边主要的竞争对手有哪些？" |
| 签合同 | 总经理 | "这个合作方案需要您这边确认签署，您看方便吗？" |

### 6.3 不同角色的沟通策略

**总经理（决策人）**
```
关注点：投入产出比、品牌形象、系统风险
沟通策略：
- 强调收益提升效果（有数据支撑）
- 强调系统简单易用
- 强调数据安全承诺
- 不要讲太多技术细节
话术："这套系统一个月能帮酒店多赚X万块，投入几乎为零。
       数据安全我们有承诺书，您放心。"
```

**前厅经理（执行人）**
```
关注点：工作负担、系统易用性、对接难度
沟通策略：
- 强调不影响现有工作
- 强调数据导出很简单（5分钟搞定）
- 强调有问题随时联系
话术："这个对您这边的工作几乎没影响，每天花5分钟导个数据就行。
       有任何问题随时找我，我来处理。"
```

**销售经理（数据人）**
```
关注点：数据准确性、竞品分析效果
沟通策略：
- 展示竞品分析demo
- 强调数据更新频率
- 询问竞品信息
话术："您最了解市场情况，您看看这个竞品分析准不准？
       有什么需要调整的您告诉我。"
```
