## 一、项目背景

### 1.1 试点意义

四川乐山锦江嘉州宾馆是**AHL数字员工项目的首个实地落地试点酒店**，承担着从概念验证到产品打磨的双重使命。

**为什么选择乐山锦江嘉州宾馆作为首发试点？**

| 维度 | 逻辑 | 对AHL的意义 |
|------|------|------------|
| **市场典型性** | 旅游城市+淡旺季脉冲+OTA主导，与AHL目标市场高度吻合 | 方案可复制性强 |
| **品牌背书** | 四川安逸集团·锦江品牌授权，文旅融合定位，有差异化竞争意识 | 业主有升级数字化动力 |
| **规模确认** | 150间中高端体量，不大不小，落地可控，代表性强 | 验证规模化可行性 |
| **已开业验证** | 2021年开业，已运营近5年，数据有积累，无新开业磨合期 | 快速看到效果 |
| **数字化信号积极** | 已部署机器人服务+电子身份证入住+智能门锁，说明管理层对新技术持开放态度 | 降低推进阻力 |
| **OTA表现健康** | 4.7分/2414条真实点评，说明基础运营质量好 | 数字员工聚焦收益管理而非救火 |
| **地理位置** | 成都2小时交通圈，团队可实地支持 | 方便现场部署和迭代 |
| **业主结构清晰** | 四川旅投集团（省属国企）+乐山电力，实控人明确 | 决策链路短，谈判对象清晰（省旅投集团文旅事业部） |

**试点成功标准**：若本方案在乐山锦江嘉州宾馆跑通，AHL数字员工将具备向同类型旅游城市酒店（峨眉山、丽江大理、厦门等）快速复制的模板能力。

### 2.3 季节性规律

**乐山酒店经营季节性特征**

| 时段 | 需求特征 | 价格策略重点 |
|------|---------|------------|
| **旺季峰值**（国庆、春节、五一） | 需求超供给20-30%，满房是常态 | 抬价+限最低连住，收益最大化 |
| **旺季常态**（周末、暑期） | OCC 85-95%，价格敏感 | 动态定价，紧跟竞品 |
| **平季**（工作日+淡季平日） | OCC 55-70%，价格驱动 | 促销引流，提升OCC |
| **淡季**（12月-1月非节假日） | OCC 40-55%，客源不足 | 团队协议价，特色打包 |

**乐山特有的"周末经济"特征**：

```
一周需求分布（典型旺季周）

         OCC%
100%|█████████████  周五 95%
 90%|██████████████████  周六 98%
 80%|██████░░░░░░░░░░  周四 72%
 70%|████░░░░░░░░░░░░  周三 62%

周一到周四：淡季定价思维，促销为主
周五下午开始：需求启动，需提前涨价

```

**这一特征对AHL数字员工的核心启示**：
- 需要**周内动态定价**能力（周一至周四促销、周五涨价）
- 需要**节假日提前30天预警+定价调整**能力
- 需要**竞品实时监控**（竞品在周末前的价格动作至关重要）

### 2.4 OTA渠道特点

**乐山市场OTA格局**

| 平台 | 份额估算 | 特点 | 策略重点 |
|------|---------|------|---------|
| **携程** | 45-50% | 客源质量高，商旅+旅游均强，评分权重大 | 评分维护、重点运营 |

| **官网/直销** | 5-10% | 锦江会员自有渠道 | 会员沉淀，降低佣金 |

**OTA核心痛点（乐山市场）**

| 痛点 | 具体表现 | 影响 |
|------|---------|------|
| 差评传播快 | 旅游客群爱写点评，差评直接影响排名 | 排名↓→流量↓→收益↓ |
| 价格战频繁 | 单体酒店灵活调价，连锁被迫跟进 | 利润受损 |
| 平台佣金高 | 佣金率3-15%，旺季高佣金侵蚀利润 | 实际RevPAR打折 |

| 排名算法复杂 | 携程排名=评分×转化率×产量，缺一不可 | 运营成本高 |

**AHL数字员工介入价值**：
- 实时竞品价格监控，快速响应调价
- 差评预警+AI自动回复，降低声誉风险
- OTA排名诊断，给出具体优化动作
- 通过私域沉淀降低OTA依赖（长期目标）

### 3.2 核心痛点

**痛点优先级矩阵**

```
                  收益影响
          高                    低
        ┌──────────────┬──────────────┐
      高 │  ★旺季定价缺失  │  ★差评处理慢  │
   紧急度  │  ★竞品响应慢  │  ★信息优化难  │
        │  ★OCC波动大  │  ★转化率低   │
        ├──────────────┼──────────────┤
      低 │  ★会员活跃度低 │  ★数据孤岛   │
        │  ★私域沉睡   │  ★复购率低   │
        └──────────────┴──────────────┘
```

**Top 5 核心痛点详解**

#### 痛点1：旺季定价靠经验，收益流失严重（P0）

**现象**：节假日和周末涨价凭感觉——"去年国庆卖多少，今年跟着调"，缺乏数据支撑和动态响应机制。

**损失估算**：
- 国庆期间若有5天满房，假设ADR可从¥380提升至¥480（+26%），180间房×5天×¥100差值 = **¥90,000/国庆**的潜在收益流失
- 旺季若全年50天，按此估算，年损失超**¥100万**

**根因**：没有竞品价格实时监控，没有动态定价工具，纯经验驱动。

---

#### 痛点2：竞品价格响应滞后，总是"慢半拍"（P0）

**现象**：竞品降价了不知道，等知道了已经晚了；竞品售罄了没发现，错过溢出需求。

**具体表现**：
- 竞品调价后，人工查看携程/美团，工作时间外无法覆盖
- 发现竞品价格变化时，通常已过去12-24小时
- 无法预判竞品周末前的价格动作

**影响**：STR指数MPI/ARI/RGI持续低于竞品，市场份额被蚕食。

---

#### 痛点3：OTA差评处理被动，排名持续下滑（P1）

**现象**：
- 差评出现后平均处理时间>24小时
- 回复话术单一，缺乏个性化
- 差评预警机制缺失，好评不维护

**OTA排名影响链**：
```
差评积累 → 评分下降 → 携程排名↓ → 自然流量↓ → 不得不买流量 → 佣金↑ → 利润↓
```

**乐山市场特殊性**：旅游客群点评意愿高，差评传播快（小红书/抖音），需快速响应。

---

#### 痛点4：会员体系沉睡，私域流量未激活（P1）

**现象**：
- 锦江会员数据在集团，酒店自主运营权限有限
- 离店客户无二次触达机制
- OTA客源"一次性"——入住后即流失

**潜在价值**：
- 若能将OTA客源的20%沉淀为私域会员
- 复购率提升10%，则全年可增加收益约**¥20-30万**（按年10万住客×20%复购×¥100客单价估算）

---

#### 痛点5：周一至周四OCC低迷，增量手段匮乏（P1）

**现象**：
- 周一至周四OCC常年在55%以下
- 协议价偏低，团队价单一，无弹性定价

**乐山特殊性**：没有大型会展/商务活动支撑工作日需求，几乎纯靠旅游散客。

---

### 3.3 优先级排序

**综合紧急度和收益影响的P0-P2排序**

| 优先级 | 痛点 | 解决难度 | 预期收益 | 推荐策略 |
|--------|------|---------|---------|---------|
| **P0** | 旺季/周末动态定价能力缺失 | 中 | ¥100万+/年 | 优先部署RM动态定价SKILL |
| **P0** | 竞品价格实时监控 | 低 | ¥30万+/年 | 优先部署竞品监控SKILL |
| **P1** | OTA差评预警+处理 | 低 | 品牌增值 | 快速部署差评预警 |
| **P1** | 会员私域沉淀（OTA引流SOP） | 中 | ¥20-30万/年 | 次优先部署引流SOP |
| **P2** | 周中平淡日增量 | 高 | ¥10-20万/年 | 后期迭代 |

**部署优先级结论**：先解决"看得见的数据"（竞品监控、指标看板），再解决"决策智能"（动态定价、流失预警）。

### 4.3 定制化调整

#### 调整1：乐山节假日脉冲定价SKILL定制

**通用方案问题**：标准动态定价基于"平稳需求"假设，不适用于乐山3倍脉冲特征。

**定制化方案**：

```python
# 乐山节假日脉冲定价逻辑

PULSE_PRICING_RULES = {
    # 节假日脉冲系数（基准价倍率）
    "国庆": {"start": 3.0, "peak": 3.5, "end": 2.0},  # 10月1-3日最高
    "春节": {"start": 2.5, "peak": 3.0, "end": 2.0},
    "五一": {"start": 2.5, "peak": 3.0, "end": 1.5},
    "清明": {"start": 2.0, "peak": 2.5, "end": 1.5},
    
    # 周末系数
    "Friday": 1.3,   # 周五下午开始涨
    "Saturday": 1.5, # 周六峰值
    "Sunday": 1.2,   # 周日白天，傍晚回落
    
    # 周内淡季系数
    "Monday": 0.85,  # 周一最低
    "Tuesday": 0.85,
    "Wednesday": 0.90,
    "Thursday": 0.95,
}

# 组合计算示例：国庆周六
# ADR = 基准价 ¥280 × 3.5(国庆峰值) × 1.5(周六) = ¥1,470（上限）
# 实际执行：取 min(¥1,470, 竞品最高价 × 1.1)
```

**SKILL定制输出**：节假日定价日历+自动调价建议

| **R6：节假日脉冲超出模型预测范围** | 🟡中 | 国庆/春节3倍需求可能超出训练数据分布 | 定价建议失效 |

### 7.2 应对措施

| 风险 | 应对措施 | 责任方 | 预案 |
|------|---------|--------|------|
| **R1：PMS API延迟** | 过渡方案：手工Excel导入，先跑通全流程；同步推进API对接 | 技术+酒店 | 预留2周缓冲 |
| **R2：反爬风险** | 方案1：购买第三方数据（斥候/众荟）作为备份；方案2：降低爬取频率+代理池 | 技术 | 备用数据源签约 |
| **R3：团队配合度** | 措施1：上线前充分培训；措施2：第一周产品经理驻场陪同使用；措施3：奖励使用积极员工 | 产品+酒店管理 | 驻场支持 |
| **R4：淡季数据不足** | 方案1：初期用历史数据回填训练集；方案2：引入外部数据（天气/展会/机票）补充特征 | 技术 | 外部数据接入 |
| **R5：会员数据限制** | 方案1：与安逸集团/锦江宾馆协商数据权限；方案2：以酒店自有数据为主建立画像；方案3：通过OTA订单补充手机号等字段 | 酒店+安逸集团 | 协商会员数据权限 |
| **R6：脉冲超出预测** | 节假日启用规则引擎（非ML）：基于预订进度+历史峰值硬编码定价上限 | 技术 | 节假日特殊定价模式 |
