1. 先听后说 — 摸底信息比说服重要

3. 先demo后要 — 先展示价值，再请求数据

## 🕐 到达后时间线（第一个小时）

### T+0分钟：进入大堂，第一印象

**立即执行**：
1. 环顾大堂，观察：
   - 前台PMS电脑数量和屏幕（记住拍照但不要明着拍）
   - 前台人员状态（忙碌程度、年龄、数字化熟练度）
   - 有无机器人（已确认有，用于判断酒店数字化水平）

**心理准备**：
- 不要急着表明来意，先以"普通客人"身份观察1-2分钟
- 注意酒店员工的精神面貌，这反映了管理状态

---

### T+5分钟：联系酒店（0833-2096666）

**拨打电话（若已预约）**：
> "您好，我是XXX，之前和您联系过的，今天下午到，想确认一下方便拜访的时间。"

**若直接到达**：
> "您好，我是XXX，之前和您联系过，想来拜访聊一个数字化合作项目，请问今天总经理或者运营负责人方便吗？"

**关键动作**：确认关键对接人是谁（总经理？运营经理？销售总监？）

---

### T+10分钟：前台PMS观察（关键！）

**观察要点**（进入前台区域，借故靠近）：
- PMS界面左上角的**厂商logo和名称**（最关键！）
- 是浏览器端（云PMS）还是桌面客户端（传统PMS）
- 界面的颜色和风格（大致判断系统代数）

**拍照技巧**（如果可能）：
- 假装看手机，从侧面拍摄屏幕（广角镜头效果更好）
- 优先拍到左上角的logo+系统名称

**拍照后立即记在脑子里或手机备忘录**：
```
PMS厂商：___________
界面类型：浏览器端/桌面客户端
其他特征：___________
```

---

### T+15分钟：与对接人见面，自我介绍

**话术**：
> "您好，我是XXX，做酒店收益管理和数字化运营的。我们专注帮助酒店用AI数字员工提升收益，目前正在找一些标杆项目落地。了解到咱们乐山锦江嘉州宾馆是乐山非常有代表性的酒店，携程评分4.7，口碑很好，想来拜访学习一下。
>
> 今天主要想了解三个方面：
> 1. 咱们酒店目前在收益管理上有没有什么痛点？
> 2. 看一下咱们的数据系统，了解一下目前的运营状态
> 3. 看看有没有合作空间

> **核心逻辑**：以"学习交流"开场，比直接说"我来装系统"好接受10倍。

---

### T+25分钟：参观PMS系统（核心环节）

**请求话术**：
> "方便让我看一下咱们的PMS系统吗？我想了解一下咱们现在用的是什么系统，方便后续看数据对接方案。"

**观察内容（按优先级）**：

| 优先级 | 观察项 | 记录 |
|--------|-------|------|
| 🔴 P0 | PMS厂商名称+版本 | |
| 🔴 P0 | 能否看到历史订单列表 | |
| 🔴 P0 | 是否有"导出"功能 | |
| 🟡 P1 | 历史数据最早从什么时候开始 | |
| 🟡 P1 | 是否有报表功能（ADR/OCC统计） | |
| 🟡 P1 | 数据字段有哪些（截图最好） | |
| 🟢 P2 | 网络环境（能否访问外网） | |

**如果前台/管理人员拒绝看PMS**：
> "没关系，那我们可以看一下携程后台吗？很多酒店都是通过携程后台看数据的，这个不需要PMS权限。"

---

### T+35分钟：携程EBK后台（关键备选路径）

**如果PMS拿不到数据，立即转向携程EBK**：

**请求话术**：
> "那我看看携程后台可以吗？很多酒店都开通了EBK数据导出的，您帮我打开携程商家后台看一眼就行。"

**EBK能拿到的数据**：
- 订单产量数据（ADR/OCC/RevPAR）
- 渠道产量对比
- 点评数据
- 竞品对比

**EBK操作（酒店人员做，5分钟内完成）**：
1. 打开携程酒店商家中心：https://ebooking.ctrip.com/ebooking/
2. 登录酒店账号
3. 进入"数据中心" → "产量报表"
4. 选择日期范围，导出Excel

---

### T+45分钟：需求访谈（管理层）

**和总经理/运营总监聊**：

**问题1（开场，了解痛点）**：
> "您觉得目前酒店运营中最花时间的事情是什么？"

**问题2（引导数据话题）**：
> "咱们现在做收益管理或者调价的时候，是看什么数据？有没有觉得数据不够用或者不及时的情况？"

**问题3（摸清决策人）**：
> "如果我们要合作的话，内部需要哪些审批流程？"

**问题4（试探意愿）**：
> "您对AI数字员工这块了解吗？之前有没有接触过类似的东西？"

**记录要点**：
- 主要痛点是什么
- 目前的收益管理方式（人工/系统/Excel）
- 对AI的接受度
- 决策链

---

### T+55分钟：数据请求与承诺

**请求话术**（在展示价值之后）：

> "基于您刚才说的情况，我觉得我们的数字员工可以帮助解决[复述痛点]的问题。如果可以的话，我们先拿过去3个月的数据跑一个demo，您看可以吗？
>
> 您放心，我们有完整的数据安全承诺——数据只在这个项目范围内使用，不对外传播，也不出酒店。"

**数据请求清单**：

| 数据项 | 格式 | 时间范围 | 优先级 |
|--------|------|---------|--------|
| 历史订单数据（每天入住/退房） | Excel/CSV | 过去3-6个月 | 🔴 P0 |
| 每日ADR/OCC数据 | Excel | 过去12个月 | 🔴 P0 |
| 携程后台产量数据 | Excel | 过去3-6个月 | 🔴 P0 |
| 竞品列表（周边同级别酒店） | 文字 | - | 🟡 P1 |

**如果酒店愿意给数据**：
立即用U盘拷贝，或留邮箱发送。**不要通过网络传输原始数据**。

## ⚠️ 突发情况应对

### 情况1：酒店说"不需要"

**应对话术**：
> "完全理解。我们不是来卖东西的，就是来学习交流的。我们有一个收益日报的demo，不收费，您看看有没有用，没用就算了。可以加个微信吗？后续有问题可以交流。"

**降级策略**：加微信 → 发demo → 留好印象 → 等时机

---

### 情况2：酒店说"数据不能给"

**应对话术**：
> "我理解，数据安全很重要。我们可以签一个数据安全协议，数据只在我们这边跑demo，跑完就删，不留存。您看这样可以吗？"

**降级策略**：
- 改要"公开数据"：携程评分/价格/口碑（这个酒店无法阻止）
- 改要"脱敏数据"：不包含客人隐私，只要房间级别汇总数据
- 改用"演示数据"：我们自己模拟，不依赖真实数据

---

### 情况3：前台拒绝进入后台

**应对话术**：
> "没关系的，那我自己来操作，不用您这边提供账号，我自己用自己的携程账号看。"

**实际做法**：
- 拿出手机，打开携程，搜索竞品酒店，截图
- 展示竞品的价格/评分数据
- 说明"这些都是公开数据，我们用这些数据帮您做竞品分析"

---

### 情况4：酒店很忙，没时间接待

**应对话术**：
> "非常理解，您很忙。我可以等您方便的时候，或者我们下次再约。今天能给我5分钟吗？就5分钟，简单介绍一下，不会耽误您太久。"

**降级策略**：
- 约第二天再来（更好，因为酒店会准备）
- 留资料和联系方式
- 加微信，后续跟进
